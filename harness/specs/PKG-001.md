## Motivation

The lockfile is the execution contract (CANON §12.3): `source + lockfile + meow version + capabilities ⇒ same behavior` (I-6) only holds if the lockfile pins content hashes and the cache refuses to hand back bytes that do not match their hash (I-7). This spec lands the two foundational data structures the whole dependency subsystem builds on:

1. The **`meow.lock.jsonl`** format — strictly-sorted JSON-lines, one dependency per line, alphabetically ordered so git merges rarely conflict (Q4 resolved, CANON §12.3, glossary §28).
2. The **global content-addressed cache** layout `~/.meow/cache/<algo>/<hash>/…` with an **integrity check (recompute hash) before any read** (CANON §12.1, I-7).

This is P0 foundation work (PLAN.md Build sequence P0; Wave 1 `PKG-001`). It defines the schema + canonical writer/reader and the cache store/read with integrity enforcement. Install, registry fetch, and the PnP loader are out (those are P2: `PKG-002`, `LOAD-*`). Tracing: PLAN.md `PKG` row → invariant I-7 (`lockfile-integrity`).

## Acceptance criteria

Concrete and checkable. All hashes/specifiers are **newtypes, not raw `String`** (CRAFT Part B). The runtime never panics on a malformed lockfile or tampered blob — every reachable failure is a typed, causal error (`thiserror`), never `unwrap`/`panic!` (CRAFT Part B).

### A1 — Hash + specifier newtypes (`crates/pkg/src/hash.rs`)

```rust
/// Hash algorithm. Extensible; only Sha256 exists at P0.
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum HashAlgo {
    Sha256,
}

impl HashAlgo {
    /// Lowercase identifier used in SRI prefixes and cache paths: `"sha256"`.
    pub const fn as_str(self) -> &'static str { /* "sha256" */ }
    /// Digest length in bytes (sha256 -> 32).
    pub const fn digest_len(self) -> usize { /* 32 */ }
}

/// A content hash. The on-disk textual form is SRI (`sha256-<base64>`),
/// npm-compatible and greppable; the cache-path form is hex.
/// NOT a raw String — the type is the cheapest invariant enforcer.
#[derive(Clone, PartialEq, Eq, Hash)]
pub struct ContentHash {
    algo: HashAlgo,
    digest: [u8; 32], // fixed at P0 (sha256); becomes an enum/SmallVec when a 2nd algo lands
}

impl ContentHash {
    /// Hash `bytes` with the default algorithm (sha256). Pure, total.
    pub fn of(bytes: &[u8]) -> ContentHash;
    pub fn algo(&self) -> HashAlgo;
    pub fn digest(&self) -> &[u8];

    /// Canonical lockfile representation: `"sha256-<standard-base64-with-padding>"`.
    pub fn to_sri(&self) -> String;
    /// Parse SRI; rejects unknown algos and wrong-length digests.
    pub fn from_sri(s: &str) -> Result<ContentHash, ParseHashError>;

    /// Cache sub-path relative to the cache root: `<algo>/<lowerhex-digest>`.
    pub fn cache_subpath(&self) -> PathBuf;
}

// serde: serializes AS the SRI string (serialize_str), deserializes via from_sri.
impl serde::Serialize for ContentHash { /* … to_sri */ }
impl<'de> serde::Deserialize<'de> for ContentHash { /* … from_sri */ }

/// npm package name (e.g. "lodash", "@scope/pkg"). Ord == byte order == the
/// alphabetical sort used for git-merge-resistant lockfile lines.
#[derive(Clone, PartialEq, Eq, PartialOrd, Ord, Hash, Serialize, Deserialize)]
pub struct PackageName(String);

/// Exact resolved version (semver). Wrapper, not raw String.
#[derive(Clone, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
pub struct Version(semver::Version);

/// A semver constraint (used for the meow runtime-version constraint).
#[derive(Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct VersionReq(semver::VersionReq);
```

- `ContentHash::of` MUST be total (no panic) and deterministic.
- `from_sri(to_sri(h)) == h` for all `h` (round-trip).
- `from_sri` MUST reject: unknown algo prefix, non-base64 body, digest length ≠ `algo.digest_len()` → `ParseHashError`.

### A2 — Lockfile model (`crates/pkg/src/lockfile.rs`)

```rust
/// One dependency line. Field order here IS the canonical JSON key order
/// (struct fields serialize in declaration order → deterministic).
#[derive(Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct LockEntry {
    pub name: PackageName,
    pub version: Version,
    /// Content hash of the package tarball/dir (SRI). I-7 anchor.
    pub integrity: ContentHash,
    /// Resolved transitive deps: dep-name -> exact resolved version. BTreeMap
    /// so keys serialize sorted → byte-stable.
    pub dependencies: BTreeMap<PackageName, Version>,
    /// Registry provenance (where this resolution came from).
    pub registry: RegistryProvenance,
    /// Capability-grants placeholder. Empty at P0; the capability subsystem
    /// (I-8) defines the real grant type later. Kept sorted + serialized so
    /// adding it is non-breaking.
    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    pub capabilities: Vec<CapabilityGrant>,
    /// Wasm-artifact hashes for this package (sorted). Empty for pure-JS.
    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    pub wasm: Vec<ContentHash>,
    /// The meow runtime-version constraint this resolution targets (§12.3,
    /// §26.3 engine-bump reproducibility).
    pub meow: VersionReq,
}

/// Provenance of a resolution. Minimal at P0; Sigstore/OSV land with §15.4.
#[derive(Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct RegistryProvenance {
    pub registry: String, // e.g. "https://registry.npmjs.org"
}

/// Opaque capability-grant placeholder (real shape owned by the I-8 spec).
#[derive(Clone, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
#[non_exhaustive]
pub struct CapabilityGrant(String);

/// Sort key: (name, version). Defines the canonical line order.
#[derive(Clone, PartialEq, Eq, PartialOrd, Ord)]
struct EntryKey { name: PackageName, version: Version }

/// The whole lockfile. BTreeMap keeps entries inherently sorted + dedup'd.
#[derive(Clone, Default)]
pub struct Lockfile {
    entries: BTreeMap<EntryKey, LockEntry>,
}

impl Lockfile {
    pub fn new() -> Lockfile;
    /// Insert/replace by (name, version). Returns the prior entry if any.
    pub fn upsert(&mut self, entry: LockEntry) -> Option<LockEntry>;
    pub fn get(&self, name: &PackageName, version: &Version) -> Option<&LockEntry>;
    pub fn iter(&self) -> impl Iterator<Item = &LockEntry>; // ascending key order
    pub fn len(&self) -> usize;

    /// Read + parse. STRICT: errors if lines are not strictly ascending by
    /// (name, version) or contain duplicates — a non-canonical lockfile is a
    /// defect, not silently re-sorted (I-7).
    pub fn read(path: &Path) -> Result<Lockfile, LockError>;

    /// Parse from an in-memory string (same strictness). Used by read + tests.
    pub fn parse(text: &str) -> Result<Lockfile, LockError>;

    /// Deterministic serialize: one entry per line, ascending key order, each
    /// line compact canonical JSON, '\n'-terminated, trailing newline. No
    /// duplicates (BTreeMap guarantees it). Written atomically (tmp + rename).
    pub fn write_canonical(&self, path: &Path) -> Result<(), LockError>;

    /// The exact bytes write_canonical would produce (for byte-stability tests).
    pub fn to_canonical_string(&self) -> String;
}
```

Behaviors:
- `to_canonical_string` MUST be a pure function of the entry set: same set ⇒ identical bytes, regardless of insertion order (BTreeMap iteration + fixed struct field order + compact `serde_json`).
- Each line is `serde_json::to_string(&entry)` (compact, no spaces), then `\n`. The file ends with a trailing newline; an empty lockfile is the empty string (zero bytes).
- `read`/`parse` MUST error (`LockError::NotCanonical`) if any line is JSON-invalid, if `name+version` decreases or repeats relative to the previous line, or if a line's re-serialization key order differs from canonical (defensive: a hand-edited reordering is rejected, not absorbed).
- `read` MUST NOT panic on any input bytes.

### A3 — Content-addressed cache (`crates/pkg/src/cache.rs`)

```rust
pub struct Cache {
    root: PathBuf, // default: ~/.meow/cache  (CANON §12.1)
}

impl Cache {
    /// Use the default root (~/.meow/cache). Resolves $HOME via the provided
    /// dirs helper; no ambient host reads beyond that (CRAFT: no ambient host).
    pub fn open_default() -> Result<Cache, CacheError>;
    /// Use an explicit root (tests, vendored caches).
    pub fn with_root(root: impl Into<PathBuf>) -> Cache;
    pub fn root(&self) -> &Path;

    /// Hash `bytes`, write the blob to <root>/<algo>/<hex> atomically
    /// (tmp file + rename), idempotent (content-addressed: a re-store of
    /// identical bytes is a no-op). Returns the ContentHash.
    pub fn store(&self, bytes: &[u8]) -> Result<ContentHash, CacheError>;

    /// Read the blob for `hash`, RECOMPUTE its hash, and compare BEFORE
    /// returning (I-7). On mismatch -> Err(IntegrityMismatch); never returns
    /// tampered bytes. Missing blob -> Err(NotFound).
    pub fn read(&self, hash: &ContentHash) -> Result<Vec<u8>, CacheError>;

    /// True iff a blob exists at the expected path (does NOT verify integrity;
    /// integrity is enforced by read()).
    pub fn contains(&self, hash: &ContentHash) -> bool;

    /// Absolute path a blob lives at: <root>/<algo>/<hex>.
    pub fn path_for(&self, hash: &ContentHash) -> PathBuf;
}
```

Behaviors:
- `store(b)` then `read(&h)` returns exactly `b`.
- `store` is idempotent: storing the same bytes twice yields the same `ContentHash` and the same on-disk file (second call observes the existing blob and returns).
- `read` recomputes `ContentHash::of(disk_bytes)` and compares to the requested `hash`; if they differ it returns `CacheError::IntegrityMismatch { expected, got }` and the bytes are dropped — **refuse, never serve** (I-7 / `lockfile-integrity` gate).
- Writes are atomic (temp file in the same algo dir + `rename`), so a crashed/partial store never leaves a corrupt blob that `read` would later accept.

### A4 — Errors (`crates/pkg/src/error.rs`)

```rust
#[derive(thiserror::Error, Debug)]
pub enum ParseHashError {
    #[error("unknown hash algorithm in SRI: {0:?}")]
    UnknownAlgo(String),
    #[error("malformed SRI (expected `<algo>-<base64>`): {0:?}")]
    Malformed(String),
    #[error("bad base64 in SRI digest")]
    BadBase64,
    #[error("digest length {got} != expected {expected} for {algo}")]
    BadLength { algo: &'static str, expected: usize, got: usize },
}

#[derive(thiserror::Error, Debug)]
pub enum LockError {
    #[error("reading lockfile {path}")]
    Io { path: PathBuf, #[source] source: std::io::Error },
    #[error("lockfile line {line} is invalid JSON")]
    Json { line: usize, #[source] source: serde_json::Error },
    #[error("lockfile line {line} is not canonical: {reason}")]
    NotCanonical { line: usize, reason: String },
    #[error(transparent)]
    Hash(#[from] ParseHashError),
}

#[derive(thiserror::Error, Debug)]
pub enum CacheError {
    #[error("cache I/O at {path}")]
    Io { path: PathBuf, #[source] source: std::io::Error },
    #[error("blob not found in cache: {0}")]
    NotFound(String), // SRI of the requested hash
    #[error("integrity check FAILED: expected {expected}, recomputed {got}")]
    IntegrityMismatch { expected: String, got: String },
    #[error("cannot locate cache home (~/.meow)")]
    NoHome,
}
```

## Non-goals

- **No install / registry fetch.** No network, no tarball download, no dependency resolution algorithm — that is `PKG-002` (P2) and `LOAD-*`.
- **No PnP / VFS / materialize loader.** Resolving modules out of the cache is `LOAD-*` (P2, ADR-4); this spec only stores/reads blobs by hash.
- **No real capability model.** `CapabilityGrant` is a serialized placeholder; the grant shape and enforcement are owned by the I-8 capability spec.
- **No Sigstore/OSV provenance verification** (CANON §15.4) — `RegistryProvenance` carries only the registry URL at P0.
- **No async I/O.** Sync `std::fs` is sufficient for the schema + integrity primitive; `LOAD-*` wraps the cache read on the tokio hot path.
- **No reproducible *builds* of native binaries** — only reproducible *selection* by content hash (CANON §24.7, honesty I-11).
- **No second hash algorithm.** Type leaves room (`HashAlgo` enum) but only `Sha256` ships.

## Interface

- **Crate:** `crates/pkg` (new), library only. Public surface: `Lockfile`, `LockEntry`, `RegistryProvenance`, `CapabilityGrant`, `Cache`, `ContentHash`, `HashAlgo`, `PackageName`, `Version`, `VersionReq`, and the three error enums.
- **On-disk lockfile** (`meow.lock.jsonl`), one entry per line, ascending by `(name, version)`. Example two lines (illustrative):

  ```jsonl
  {"name":"is-odd","version":"3.0.1","integrity":"sha256-K9lP…","dependencies":{"is-number":"6.0.0"},"registry":{"registry":"https://registry.npmjs.org"},"meow":"^0.1"}
  {"name":"is-number","version":"6.0.0","integrity":"sha256-7Hb…","dependencies":{},"registry":{"registry":"https://registry.npmjs.org"},"meow":"^0.1"}
  ```

- **Cache layout:** `~/.meow/cache/<algo>/<lowerhex-digest>` — one file per blob (CANON §12.1). `<algo>` = `sha256`.
- **No CLI surface** in this spec (no `meow install` yet); these are library APIs consumed by P2 commands.

## Implementation sketch

1. **New crate** `crates/pkg` added to the workspace members. The only shared-file edit is the root `Cargo.toml` workspace member list — fence it:

   ```toml
   # === PKG-001 ===
   # members += "crates/pkg"
   # === /PKG-001 ===
   ```

2. **`crates/pkg/Cargo.toml`** deps: `serde` (derive), `serde_json`, `sha2`, `data-encoding` (or `base64`) for SRI, `hex` for cache paths, `semver` (serde feature), `thiserror`, and a `$HOME` resolver (`dirs`/`etcetera`) used only in `open_default`. Keep the dep set small (footprint, I-10).
3. **`hash.rs`** — newtypes + serde. `ContentHash::of` uses `sha2::Sha256`. SRI = `format!("{}-{}", algo.as_str(), base64(digest))`; `cache_subpath` = `<algo>/<hex>`.
4. **`lockfile.rs`** — `BTreeMap<EntryKey, LockEntry>`. `to_canonical_string` joins `serde_json::to_string(entry) + "\n"` in iteration order. `parse` reads line-by-line, tracks the previous `EntryKey`, errors on `<=` (non-strict-ascending ⇒ unsorted or duplicate) and on a re-serialization key-order mismatch. `write_canonical` writes `to_canonical_string()` to `path.tmp` then renames.
5. **`cache.rs`** — `store`: `h = ContentHash::of(bytes)`; `p = path_for(&h)`; if `!p.exists()`, create parent dirs, write to a unique temp sibling, `fs::rename` into place; return `h`. `read`: read `p` (NotFound on ENOENT), `got = ContentHash::of(&disk)`, compare to `hash`, return `IntegrityMismatch` on inequality else `Ok(disk)`.
6. **`lib.rs`** — module wiring + re-exports.

CRAFT discipline: no `unwrap`/`panic!` on any input-reachable path; `unsafe` not used (no V8/FFI boundary here); borrow `&[u8]`/`&Path`, no gratuitous clones on the store/read path.

## Tests required

All under `crates/pkg/tests/` + unit tests. Invariants proved → **`lockfile-integrity` gate (I-7)**; secondary touch on `footprint` (dep set stays small).

- **Canonical writer is byte-stable** (`lockfile-integrity`): build a `Lockfile`, `to_canonical_string()` twice ⇒ byte-identical; `write_canonical → read → write_canonical` ⇒ identical bytes (round-trip fixpoint).
- **Sorted regardless of insertion order**: `upsert` entries in shuffled order ⇒ output lines strictly ascending by `(name, version)`. Property test (proptest) over random name/version sets: every adjacent pair `lines[i] < lines[i+1]`.
- **Dedup**: two `upsert`s with the same `(name, version)` ⇒ exactly one line; `read` of input containing a duplicate line ⇒ `LockError::NotCanonical`.
- **Read rejects non-canonical input**: hand-written unsorted lines, a reordered-keys JSON object, and invalid JSON each ⇒ `LockError`. Fuzz/garbage bytes ⇒ `Err`, never panic.
- **ContentHash SRI round-trip** (property): `from_sri(to_sri(h)) == h`; `from_sri` rejects bad algo/length/base64.
- **Cache round-trip + idempotence**: `store(b)` then `read(&h) == b`; storing `b` twice yields same `h` and same file.
- **Tampering is refused** (the `lockfile-integrity` red-team case, I-7): `store(b) → h`; mutate the on-disk blob bytes; `read(&h)` ⇒ `CacheError::IntegrityMismatch` and never returns the tampered bytes. Also: truncated blob ⇒ mismatch; missing blob ⇒ `NotFound`.

## Rollout

- **Additive, greenfield.** New crate; no existing behavior changes; no runtime command ships from this spec, so nothing user-visible regresses.
- **No migration.** `meow.lock.jsonl` is a brand-new format with no predecessor to convert (no pnpm/npm interop by design, §12.3). The cache is created on first `store`.
- **Reversibility:** remove `crates/pkg` from the workspace members and delete the crate; no persisted production state depends on it yet. A stored cache is a plain directory of content-addressed files — safe to `rm -rf ~/.meow/cache` (it is a rebuildable cache, not a source of truth).
- **Format evolution:** future fields are added with `#[serde(default, skip_serializing_if = …)]` so old lockfiles still parse and the canonical form stays stable; breaking format changes ride the meow version line (§26.3) recorded by the per-entry `meow` constraint.

## Operator notes

Forks resolved by this draft (CANON had no explicit call on these; defaults chosen, no `decisions.json` edit — Main consolidates):

1. **Textual hash form = SRI, not multihash.** The assignment said "SRI/multihash"; SRI (`sha256-<base64>`) is npm-compatible and human-greppable, so it is the serialized lockfile form. Multihash is deferred; the `ContentHash` newtype can grow a multihash codec without changing the lockfile schema.
2. **`meow` runtime-version constraint is per-line**, as the assignment and the §12.3 field list specify — not a separate header line. This keeps the file as pure, strictly-sorted dependency lines (no special first line to break the sort/merge story) at the cost of repeating the constraint per entry; a later PKG spec may hoist it to a sidecar if redundancy bites.
3. **No lockfile-format-version field.** Format identity rides the file name + the per-entry `meow` constraint + additive serde defaults; adding a dedicated version field is deferred to avoid a non-dependency line.
4. **Cache layout is the literal CANON form** `<algo>/<hash>` with no directory sharding. If a single algo dir grows to millions of entries, a future spec can add `<algo>/<hh>/<rest>` sharding behind `path_for`; not needed at P0.
5. **Sync I/O** — async cache reads are wired by `LOAD-*` (P2); `crates/pkg` stays runtime-agnostic.
