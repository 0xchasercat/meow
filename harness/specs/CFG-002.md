> **SUPERSEDED by CFG-003** — the generated-root-`package.json` projection is retired; `package.json` becomes the dependency authority (DR-001 cleanup; P2.5 Drop-In Core / DR-003).

## Motivation

CFG-001 stood up the shadow-config story for `tsconfig.json` (committed `extends` shim → regenerated `.meow/tsconfig.json`). CFG-002 closes the other half of ADR-8: `package.json`. Unlike `tsconfig.json`, `package.json` has **no `extends` mechanism**, so the shim trick cannot apply — `meow` instead generates the **real root `package.json`** as a derived artifact and **owns/overwrites** it (CANON ADR-8, §18.1, §24.5 residual). Publishing metadata (`name`/`version`/`exports`/…) is a **projection** of the single human-edited source `meow.config.ts`, not an authority.

This is the surface non-`meow` tools, IDEs, and CI see (ADR-8 consequence): `npm`/`pnpm` resolution, editor "Go to package", `npm publish` metadata readers all read the root `package.json`. If `meow` did not generate it, those tools would see nothing — or, worse, a stale hand-maintained duplicate that drifts from `meow.config.ts`.

Spine: this is `Build sequence · P1 Minimal Runtime` backlog item `CFG-002` (Wave 2, PLAN.md). It serves **I-1** (one config feeds everything — `package.json` becomes a *projection* of `meow.config.ts`, never a second authority the ecosystem can edit independently) and **I-9** (generated artifacts are derived from one source, byte-stable regenerable, and marked so they are never hand-maintained; hand-edits are detected, not silently merged).

## Acceptance criteria

Extends `crates/config` (CFG-001) — no new crate. Errors stay typed (`ConfigError`, `thiserror`); nothing on the projection path may `panic!`/`unwrap()` on user input (CRAFT Part B). Reuses CFG-001's `MeowConfig::load` (the JSON-only pre-runtime loader; see Operator notes / I-11). Concrete surface:

### 1 — Publishing metadata in the config shape (fenced edit to `crates/config/src/schema.rs`)

Add a `publish` section to `MeowConfig` and the `Publish` struct, behind a `// === CFG-002 ===` fence (CFG-001 owns the file):

```rust
// === CFG-002 ===
/// Publishing metadata projected into the generated root `package.json` (ADR-8).
/// `meow.config.ts` is the SOLE authority for that file; package.json is derived.
#[derive(Debug, Clone, PartialEq, Eq, Default, Serialize, Deserialize)]
#[serde(deny_unknown_fields, rename_all = "camelCase")]
pub struct Publish {
    /// → `package.json.name`. Absent ⇒ field omitted (a config may be private/unnamed).
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub name: Option<String>,
    /// → `package.json.version`. Absent ⇒ omitted.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub version: Option<String>,
    /// → `package.json.description`. Absent ⇒ omitted.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub description: Option<String>,
    /// → `package.json.license`. Absent ⇒ omitted.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub license: Option<String>,
    /// → `package.json.private` only when true (omitted when false).
    #[serde(default)]
    pub private: bool,
    /// Subpath → target, projected verbatim into `package.json.exports`.
    /// `BTreeMap` ⇒ key-sorted ⇒ byte-stable (feeds idempotent regeneration).
    #[serde(default)]
    pub exports: std::collections::BTreeMap<String, String>,
}
// === /CFG-002 ===
```

The new field added to `MeowConfig` (inside the same fence): `#[serde(default)] pub publish: Publish,`. An absent `publish` key in config ⇒ `Publish::default()` (every sub-field empty), which projects a minimal-but-valid `package.json` (marker + `type` only). `deny_unknown_fields` makes a typo under `publish` a typed parse error pointing at the field (I-9 spirit), never a silent ignore.

### 2 — Projection (`crates/config/src/package.rs`)

```rust
use crate::{ConfigError, MeowConfig};
use std::path::Path;

/// Provenance marker. package.json is strict JSON (no comments), so the marker lives in
/// the npm-blessed `"//"` comment key — the ONLY place a marker is valid in package.json.
/// Byte-stable sentinel: regeneration always emits this exact string.
pub const PACKAGE_JSON_MARKER: &str =
    "GENERATED by `meow sync` from meow.config.ts — edits are clobbered (ADR-8).";

/// Project `cfg.publish` into the EXACT bytes of the root `package.json`. Pure function,
/// no I/O. Deterministic / byte-stable: identical `cfg` ⇒ identical bytes (fixed key order,
/// `BTreeMap` exports, `serde_json::to_string_pretty`, single trailing newline).
pub fn render_root_package_json(cfg: &MeowConfig) -> String;

/// Regenerate `root/package.json` from `cfg`, unconditionally OWNING/overwriting it
/// (ADR-8 — package.json has no `extends`, so meow owns the real file). Skips the write
/// when on-disk bytes already equal the projection, to keep mtime stable (idempotent / I-9).
pub fn generate_root_package_json(cfg: &MeowConfig, root: &Path) -> Result<(), ConfigError>;

/// Provenance/staleness classification of the on-disk root package.json vs the projection.
/// This is the `meow doctor` staleness/hand-edit check — the ONLY doctor surface CFG-002 owns
/// (the rest of `meow doctor` is later; see Non-goals / Operator notes, I-11).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum PackageJsonStatus {
    /// No root package.json yet — `meow sync` will create it.
    Missing,
    /// Byte-identical to the projection — in sync.
    Fresh,
    /// Carries the meow marker but differs from the projection (config moved on since the
    /// last sync). `meow sync` regenerates; not a hand-edit.
    Stale,
    /// Differs AND lacks the meow marker — hand-written/hand-edited. `meow sync` WILL
    /// overwrite it (ADR-8 honest boundary).
    HandEdited,
}

/// Classify `root/package.json` against the projection of `cfg`. Read-only — never mutates.
pub fn classify_root_package_json(
    cfg: &MeowConfig,
    root: &Path,
) -> Result<PackageJsonStatus, ConfigError>;
```

**`cfg.publish` → root `package.json` projection** (fixed emission order ⇒ byte-stable):

| order | key | source | rule |
|---|---|---|---|
| 1 | `"//"` | `PACKAGE_JSON_MARKER` | always emitted (provenance, ADR-8) |
| 2 | `name` | `publish.name` | omitted when `None` |
| 3 | `version` | `publish.version` | omitted when `None` |
| 4 | `description` | `publish.description` | omitted when `None` |
| 5 | `type` | (fixed) | **always `"module"`** — first-party is ESM-only (I-2); not configurable |
| 6 | `license` | `publish.license` | omitted when `None` |
| 7 | `private` | `publish.private` | emitted only when `true` |
| 8 | `exports` | `publish.exports` | omitted when empty; else key-sorted map (never a half-baked partial map) |

`classify_root_package_json` logic (the tri-state that makes hand-edits detectable, I-9):
- file absent ⇒ `Missing`.
- on-disk bytes `==` `render_root_package_json(cfg)` ⇒ `Fresh`.
- bytes differ **and** the parsed JSON's top-level `"//"` equals `PACKAGE_JSON_MARKER` ⇒ `Stale` (meow generated it; config has since changed — regenerate).
- bytes differ **and** the marker is absent/tampered ⇒ `HandEdited`.

Determinism: build a `serde_json::Map` (insertion order preserved by `serde_json`'s `preserve_order`, OR an explicit ordered builder) in the fixed order above, `to_string_pretty`, append `"\n"`. No comment header line (unlike CFG-001's tsconfig) because package.json must stay parseable strict JSON — the marker rides in `"//"` instead.

### 3 — `meow sync` extension + minimal `meow doctor` (fenced edits in `crates/cli`)

`meow sync` (CANON §19 / §18.1) must regenerate the root `package.json` alongside CFG-001's shadows. Add a `// === CFG-002 ===` fence inside the `Command::Sync` arm (after CFG-001's tsconfig calls):

```rust
// === CFG-002 ===
meow_config::generate_root_package_json(&cfg, &root)?;
println!("synced root package.json (projected from meow.config)");
// === /CFG-002 ===
```

`meow doctor` (CANON §19 — full surface is later, CFG-002 owns ONLY the package.json staleness/hand-edit check). Add a `Command::Doctor` arm behind its own `// === CFG-002 ===` fence:

```rust
// === CFG-002 ===
Command::Doctor => {
    let root = std::env::current_dir()?;
    let cfg = meow_config::MeowConfig::load(&root)?;
    match meow_config::classify_root_package_json(&cfg, &root)? {
        PackageJsonStatus::Fresh   => println!("package.json: in sync"),
        PackageJsonStatus::Missing => println!("package.json: missing — run `meow sync`"),
        PackageJsonStatus::Stale   => println!("package.json: stale vs meow.config — run `meow sync`"),
        PackageJsonStatus::HandEdited => eprintln!(
            "warning: root package.json was hand-edited; meow owns it (ADR-8) and \
             `meow sync` will overwrite it. Move publishing metadata into meow.config.ts."),
    }
    // NOTE: package.json staleness is the ONLY check CFG-002's doctor performs; the full
    // environment/config/lockfile health surface is a later spec.
}
// === /CFG-002 ===
```

Coordinate the `Command::Doctor` variant with the CLI skeleton owner (DIST-001) over IRC if the dispatch shape differs.

## Non-goals

- **Full `npm publish` flow / registry interaction** — CFG-002 only writes the local root `package.json`; it does not pack, tarball, auth, or upload.
- **The full `meow doctor` surface** — environment, lockfile, cache, and config-graph health are later. CFG-002 wires ONLY the package.json staleness/hand-edit check into `doctor` (honestly labelled in code; see I-11).
- **Per-package `package.json` projection in a workspace** — CFG-002 projects the **root** file only. `workspace.packages` fan-out (a generated `package.json` per workspace member) is deferred; emitting only the root keeps the file correct-and-minimal, never a half-baked workspace map.
- **`bin`/`scripts`/`dependencies`/`devDependencies` projection** — scripts are replaced by `meow.tasks.ts` (CANON §17.x) and dependencies live in `meow.lock.jsonl` (§12.3); projecting them into `package.json` is out of scope. Only publishing-identity metadata (`name`/`version`/`description`/`type`/`license`/`private`/`exports`) is projected.
- **TS-config evaluation via the runtime** — inherited CFG-001 boundary: `MeowConfig::load` reads `meow.config.json` until RT-001 can execute `meow.config.ts` (I-11; see Operator notes).
- **Auto-regen on `meow install` / daemon config-watch** — CANON §18.1 lists `meow install` and config-watch as additional regen triggers; CFG-002 wires only the `meow sync` trigger (and read-only `meow doctor`). The other triggers call the same `generate_root_package_json` when their specs land.

## Interface

- `crates/config` additionally exports: `Publish`, `render_root_package_json`, `generate_root_package_json`, `classify_root_package_json`, `PackageJsonStatus`, `PACKAGE_JSON_MARKER`. `MeowConfig` gains a `publish: Publish` field.
- CLI: `meow sync` now also writes root `package.json`; `meow doctor` reports the package.json status (Fresh/Missing/Stale/HandEdited).
- On-disk contract:
  - `./package.json` (**committed and OWNED** — *not* gitignored, unlike `.meow/`; the ecosystem reads it) — strict JSON, top-level `"//"` = `PACKAGE_JSON_MARKER`, `"type": "module"`, plus projected publishing fields. Trailing newline.
  - No `.gitignore` edit: the root `package.json` stays tracked (ecosystem/CI/`npm publish` need it on disk and in VCS), unlike CFG-001's gitignored `.meow/` shadows.

## Implementation sketch

- `crates/config/Cargo.toml`: ensure `serde_json` has the `preserve_order` feature (for fixed-order map serialization), or build the object via an explicit ordered helper. No new crate deps otherwise.
- `crates/config/src/schema.rs`: add the `// === CFG-002 ===` fence with the `Publish` struct + the `publish: Publish` field on `MeowConfig`.
- `crates/config/src/package.rs` (new module; `pub mod package;` in `lib.rs` behind a `// === CFG-002 ===` re-export fence):
  - `render_root_package_json`: ordered builder per the table → `to_string_pretty` → `+ "\n"`.
  - `generate_root_package_json`: compute projection; read existing `root/package.json`; write only if bytes differ (mtime-stable); always overwrites a differing file (owned).
  - `classify_root_package_json`: read `root/package.json` (→ `Missing` on `NotFound`); compare bytes to projection; on mismatch, parse and inspect top-level `"//"` for the marker → `Stale` vs `HandEdited`.
- `crates/cli` (shared file): the two `// === CFG-002 ===` fences above (sync extension + `Command::Doctor`).
- Errors: reuse `ConfigError` (CFG-001). A malformed existing `package.json` during `classify` is NOT a parse-failure of *our* artifact — treat unparseable on-disk bytes as `HandEdited` (it differs and carries no valid marker), not a hard error, so `doctor` still warns instead of aborting.

## Tests required

`crates/config/tests/` (integration, `tempdir` root):

- **projection fidelity** (→ I-1): a `MeowConfig` with `publish { name, version, exports: {".": "./dist/index.js"} }` → `render_root_package_json` → re-parse JSON → assert `name`/`version` match, `type == "module"`, `exports["."]` matches, and top-level `"//"` == `PACKAGE_JSON_MARKER`. Proves package.json is a faithful projection of the single config source, not an independent authority.
- **minimal config projects valid JSON** (→ I-1): `MeowConfig::default()` (no `publish`) → projection parses as JSON, contains the marker and `"type": "module"`, and omits `name`/`version`/`exports` (no half-baked empty fields).
- **idempotent / byte-stable** (→ I-9): `render_root_package_json` called twice on the same `cfg` is byte-identical; `generate_root_package_json` twice yields a byte-identical file (capture bytes, regenerate, assert equal) and the second call leaves mtime unchanged (skip-write path).
- **hand-edit detection** (→ I-9, tri-state): (a) no file ⇒ `Missing`; (b) write the exact projection ⇒ `Fresh`; (c) generate from `cfgA` then classify against `cfgB` (different `publish.version`) ⇒ `Stale` (marker present, bytes differ); (d) write a hand file with no `"//"` marker that differs ⇒ `HandEdited`; (e) write unparseable bytes ⇒ `HandEdited` (not an error).
- **owned / overwrite on sync** (→ I-9, honest boundary): write a hand-edited `package.json`, run `generate_root_package_json` → file bytes now equal the projection (hand-edit clobbered, ADR-8).
- **integrates with CFG-001 shadows** (→ I-1, integration): after a single `meow sync` on a project with a `meow.config.json`, all three artifacts exist and are correct — `.meow/tsconfig.json` (header + compilerOptions), root `tsconfig.json` shim (CFG-001), and root `package.json` (marker + `type: module`, CFG-002) — proving one `sync` keeps the whole legacy surface in sync from one source.

GATES: `graph-integrity` (I-1 — `package.json` is a projection of the one `meow.config.ts`, never a second editable config authority), `types-fresh` (I-9 — generated artifact carries a provenance marker, regenerates to identical bytes, and hand-edits are detected rather than merged), `honesty` (I-11 — the OWNED/overwrite boundary and the doctor warning are stated truthfully; no CLI/doc string claims `doctor` checks more than package.json, and none claims TS-config evaluation works pre-RT-001).

## Rollout

- Additive: schema field + new `package.rs` module + two fenced CLI edits. No data migration. Flag-free.
- **The root `package.json` becomes a tracked, meow-owned file.** Unlike CFG-001's gitignored `.meow/` shadows, it stays committed (the ecosystem, CI, and `npm publish` need it on disk and in VCS). First `meow sync` after this lands generates/overwrites it from `meow.config.ts`.
- **Reversibility:** revert the `// === CFG-002 ===` fences in `crates/cli` and `schema.rs`/`lib.rs`, and delete `crates/config/src/package.rs`. The generated `package.json` then becomes an ordinary committed file again (a prior hand-maintained version can be restored via `git checkout`); nothing else in P1 depends on CFG-002.

## Operator notes

- **HONEST BOUNDARY (I-11, ADR-8):** the root `package.json` is **owned and overwritten** by `meow`. Hand-edits are clobbered on every `meow sync`; `meow doctor` warns when it detects a hand-edited (marker-absent) file. Publishing metadata MUST be edited in `meow.config.ts` (`publish: {...}`), never in `package.json`. No CLI/doc string may imply `package.json` is hand-maintainable.
- **HONEST BOUNDARY (I-11):** CFG-002's `meow doctor` performs ONLY the package.json staleness/hand-edit check. The code comment and this spec say so explicitly; the command must not advertise environment/lockfile/cache health it does not yet perform.
- **Inherited boundary (I-11, from CFG-001):** until RT-001 lands, `MeowConfig::load` evaluates `meow.config.json`, not a real `meow.config.ts` (a TS-only project returns `ConfigError::TsNotSupported`). So `publish` metadata is read from JSON pre-runtime; the projection logic is unchanged once TS-eval is wired behind the same `load` return type.
- **Assumption (default chosen, not a silent fork):** the projected publishing fields are the minimal identity set (`name`/`version`/`description`/`type`/`license`/`private`/`exports`); `type` is fixed to `"module"` (I-2, first-party ESM-only) rather than configurable. CANON §18.1 says "publishing metadata is projected" without enumerating fields; this set is the boring, reversible minimum (adding a field later is a one-row change to the projection table). Flagged to Main for `decisions.json` consolidation — not written to `decisions.json` here.
