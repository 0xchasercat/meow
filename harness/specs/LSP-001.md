## Motivation

ADR-4's whole package model rests on one consequence stated twice in CANON: *"the runtime and the language server **must share identical resolution logic**, or the editor and the runtime will disagree"* (ADR-4 consequence; §12.2). I-5 makes it law: there is **one** resolver, and a runtime that resolves a specifier one way while the editor resolves it another is *a guaranteed bug*, not a quality-of-life gap. LOAD-003 built that one resolver (`meow_loader::Resolver`) and its docs already name LSP-001 as the surface that proves the sharing is real; the `resolver-parity` gate (GATES.md, I-5) has no teeth until a second, editor-facing consumer resolves the same corpus and lands on the **same** results.

LSP-001 is that proof — and the prototype of the first-party language server CANON §20 insists on (*"not an afterthought… how the zero-`node_modules` model becomes pleasant instead of mysterious"*). It delivers exactly two things, no more:

1. **An LSP-facing resolution entry point** (`EditorResolver`) that consumes the **exact** `meow_loader::Resolver` — built from the **same** `meow_pkg::ResolutionGraph` (PKG-003) the runtime feeds its resolver — and answers editor "resolve this import" requests by delegating to `Resolver::locate`. No reimplementation, no second `exports`/`imports` walk, no second parser (I-1, P15).
2. **The Shadow `node_modules` Symlink Map** (CANON §20.1, Q8 resolved): a hidden `.meow/deps/` tree of OS-level directory symlinks pointing into the **global content-addressed unpacked store** (PKG-004's `UnpackedStore`, `~/.meow/cache/unpacked/…`), so stock TS-server/editors get ordinary filesystem traversal and go-to-definition while the project root keeps **no** real `node_modules`; this map is a tooling projection only and is not the runtime truth.

The keystone is the test: a specifier corpus resolved through the **runtime path** (`MeowModuleLoader`) and the **LSP path** (`EditorResolver`), asserted **identical** — that corpus *is* the `resolver-parity` gate's fixture.

Traceability: `plan_ref` → PLAN.md *Build sequence · P2 Packages & Resolution* (P2 exit: *"runtime and LSP resolve identically"*; gate `resolver-parity`) + *backlog Later phases · P2* (`LSP-001` — shared-resolver prototype + shadow symlink map). `constitution_ref` → **I-5** [`resolver-parity`] (the keystone), **I-1** [`graph-integrity`] (no second resolver/parser), **I-9** (first-party LSP exposing the cache + native `meow:*` types), **I-11** [`honesty`] (a *prototype* — resolution + symlink map only; the boundaries are stated, not blurred). CANON refs: §12.2, §20, §20.1, ADR-4.

## Acceptance criteria

Concrete, checkable Rust in a **new** crate `crates/lsp` (`meow-lsp`), library only. Every editor-triggerable path returns `Result`; the resolver and the symlink generator never panic on user input, a missing/dangling dep, a tampered blob, or a malformed `package.json` (CRAFT Part B). The LSP carries **no** resolution logic of its own — it holds and delegates to THE one `Resolver` (I-1, I-5). No ambient host reads in this crate (P16): `project_root`, the `Cache`, the `ResolutionGraph`, and the `UnpackedStore` are all supplied by the caller (the CLI/host edge), never resolved from `$HOME`/env here.

### A1 — `crates/lsp/src/resolver.rs` — `EditorResolver` (the LSP-facing entry point, I-5)

The editor resolver owns nothing but a handle to THE shared resolver plus the unpacked-store handle for projecting a result onto an on-disk path. It is constructed **only** through PKG-003's seam (`Resolver::from_resolution`) from the **shared** `ResolutionGraph` — there is no other construction path, so the LSP physically cannot build a divergent `root_deps`/lockfile.

```rust
use std::path::PathBuf;
use std::sync::Arc;

use deno_core::url::Url;
use meow_loader::{ModuleLocator, ResolveError, Resolver};
use meow_pkg::{Cache, ResolutionGraph, UnpackedStore};
use meow_runtime::native::NativeModuleSource;

/// The editor/LSP-facing resolution entry point. It holds THE `meow_loader::Resolver`
/// (built from the SAME `meow_pkg::ResolutionGraph` the runtime's `MeowModuleLoader`
/// uses) and answers "resolve this import from this file" by delegating to
/// `Resolver::locate` — then projects the result onto an on-disk path for go-to-definition.
/// There is NO second resolver, parser, or exports/imports walk here (I-1, I-5).
pub struct EditorResolver {
    /// THE shared resolver. Built via `Resolver::from_resolution(&graph, …)` from the
    /// SAME `Arc<ResolutionGraph>` the run-path feeds its resolver — identical inputs ⇒
    /// identical resolution (the parity guarantee, I-5). Single-thread: the resolver's
    /// `RefCell` PackageFs cache is `!Sync`, so the LSP serves resolution on one thread
    /// per `EditorResolver` and shares the *graph*, never a `Resolver`, across threads
    /// (PKG-003 contract).
    resolver: Resolver,
    /// The global unpacked content-addressed store (PKG-004). Maps a resolved
    /// `Cached { package, member }` to its on-disk file inside `~/.meow/cache/unpacked/…`
    /// for go-to-definition; never a project `node_modules` (I-5).
    store: UnpackedStore,
}

/// One resolution outcome for the editor. `url` + `locator` come from the ONE
/// `Resolver::locate` and MUST equal what the runtime resolved for the same
/// `(specifier, referrer)` — that equality is the `resolver-parity` invariant.
#[derive(Debug, Clone)]
pub struct EditorResolution {
    /// Identical to the runtime's resolved module URL (`file:` or `meow-cache://…`).
    /// This is the parity anchor compared in tests.
    pub url: Url,
    /// Identical to the runtime's `ModuleLocator` (LocalFile | Cached | Native).
    pub locator: ModuleLocator,
    /// The on-disk path the editor opens for go-to-definition:
    ///  - `Cached { package, member }` → `UnpackedStore::dir_for(&package).join(member)`
    ///    (inside the global unpacked cache — NOT a project `node_modules`),
    ///  - `LocalFile(p)` → `p`,
    ///  - `Native { .. }` → `None` (a `meow:*` module has no on-disk source; its types
    ///    come from generated `.d.ts`, I-9).
    pub editor_path: Option<PathBuf>,
}

impl EditorResolver {
    /// Build the editor resolver from the SAME resolution graph the runtime uses.
    /// `graph` is the one `ResolutionGraph` shared with the run-path (pass `&*arc`);
    /// `Resolver::from_resolution` is the ONLY supported construction path (PKG-003 is
    /// the sole resolver-input provider — the LSP never hand-builds `root_deps`/lockfile).
    pub fn new(
        graph: &ResolutionGraph,
        cache: Arc<Cache>,
        project_root: Url,
        native: Arc<dyn NativeModuleSource>,
        store: UnpackedStore,
    ) -> EditorResolver;

    /// Resolve `specifier` from `referrer` EXACTLY as the runtime would, then project the
    /// result onto an on-disk path. `referrer` is an already-parsed `file:`/`meow-cache:`
    /// URL (the editor converts its open-document URI once) so the comparison against the
    /// runtime is apples-to-apples. Errors are the SAME typed `ResolveError` the runtime
    /// surfaces — there is no LSP-private error taxonomy (I-1, I-11).
    pub fn resolve_module(
        &self,
        specifier: &str,
        referrer: &Url,
    ) -> Result<EditorResolution, ResolveError>;

    /// THE shared resolver, for callers that need raw `locate`/`resolve` (the
    /// resolver-parity test drives this and the runtime loader off one shared graph).
    pub fn resolver(&self) -> &Resolver;
}
```

Behaviors:
- `resolve_module(spec, ref)` reduces to `self.resolver.locate(spec, ref)` and **adds nothing to resolution** — the only LSP-specific work is mapping the returned `ModuleLocator` to `editor_path`. A `Cached` result's `editor_path` is `store.dir_for(package).join(member)`, i.e. the same bytes the runtime reads from the archive, on disk in the unpacked store.
- For every `(specifier, referrer)`, `EditorResolver::resolve_module(...).url` **byte-equals** `MeowModuleLoader::resolve(specifier, referrer.as_str(), ResolutionKind::Import)` — because both reduce to the one `Resolver::locate` (the parity assertion, A4).
- Failure parity: a specifier that errors in the runtime resolver (`BareSpecifierNotInLockfile`, `SubpathNotExported`, `NoMatchingCondition`, `UnknownNativeModule`, …) produces the **same** `ResolveError` variant from the LSP path. CommonJS is no longer a resolver/load refusal after LOAD-004; it is a shared successful locate that the runtime later lowers.

### A2 — `crates/lsp/src/shadow.rs` — `ShadowDeps` (the symlink-map generator, CANON §20.1)

```rust
use std::collections::BTreeMap;
use std::path::{Path, PathBuf};

use meow_pkg::{MaterializeError, ResolutionGraph, UnpackedStore, Version};

/// Generator + record for the Shadow `node_modules` Symlink Map (CANON §20.1, Q8).
/// Writes a hidden `<project_root>/.meow/deps/` tree of OS-level **directory symlinks**,
/// one per resolvable package name, each pointing at that package's unpacked dir in the
/// GLOBAL content-addressed store (`~/.meow/cache/unpacked/<algo>-<hex>/`, PKG-004). The
/// editor/TS-server gets ordinary filesystem traversal + go-to-definition while the project
/// root keeps NO real `node_modules` (I-5, ADR-4). `ShadowDeps` is for foreign tooling/editor
/// ergonomics only; runtime resolution still uses `ResolutionGraph` + `Resolver::locate`.
#[derive(Debug, Clone)]
pub struct ShadowDeps {
    /// Absolute `<project_root>/.meow/deps`.
    root: PathBuf,
    /// name → the unpacked-store dir its `.meow/deps/<name>` symlink targets (sorted).
    links: BTreeMap<String, PathBuf>,
    /// Names present at >1 version in the root-reachable closure. A FLAT-by-name map can
    /// expose only one version per name; the chosen version is the root-reachable (else
    /// lowest) pick, and the rest are recorded here so the full LSP can layer a nested
    /// per-package tree later. Harmless for the single-version common case; the *runtime*
    /// resolver stays multi-version-correct via the lockfile regardless. (Honest boundary, I-11.)
    collisions: BTreeMap<String, Vec<Version>>,
}

impl ShadowDeps {
    /// Build (or refresh) `.meow/deps/` for `project_root` from the SAME `ResolutionGraph`
    /// the resolver uses. For each package in the root-reachable closure (`graph.packages()`)
    /// — and each direct dep (`graph.root_deps()`) — ensure it is unpacked
    /// (`UnpackedStore::ensure(&pkg.integrity)`: recompute+verify the hash before gzip-tar
    /// decode, I-7) and write a directory symlink `.meow/deps/<name>` → that unpacked dir.
    /// Scoped names create the `@scope/` parent first, then `.meow/deps/@scope/<name>`.
    ///
    /// Idempotent and drift-free: `.meow/deps` is rebuilt from scratch each call, so a
    /// removed/renamed/repinned dependency's stale link is pruned and the map always equals
    /// the current graph. Pure projection — it surfaces nothing the resolver doesn't know.
    pub fn generate(
        project_root: &Path,
        graph: &ResolutionGraph,
        store: &UnpackedStore,
    ) -> Result<ShadowDeps, ShadowError>;

    /// Absolute `.meow/deps` root.
    pub fn root(&self) -> &Path;
    /// The written links (name → unpacked-store target), sorted.
    pub fn links(&self) -> &BTreeMap<String, PathBuf>;
    /// Multi-version names not fully representable in the flat map (see field doc).
    pub fn collisions(&self) -> &BTreeMap<String, Vec<Version>>;

    /// The `compilerOptions.paths` mapping the shadow `.meow/tsconfig.json` needs so
    /// TS-server resolves bare specifiers through `.meow/deps/` (CANON §20.1). Emitted for
    /// CFG-001's shadow-tsconfig generator to MERGE — this prototype does NOT write
    /// `tsconfig.json` itself (CFG owns it; see Operator notes). Shape:
    /// `{ "*": ["./.meow/deps/*"], "@scope/*": ["./.meow/deps/@scope/*"] }`.
    pub fn tsconfig_paths(&self) -> BTreeMap<String, Vec<String>>;
}

#[derive(Debug, thiserror::Error)]
pub enum ShadowError {
    #[error("unpacking {name} for the shadow deps map")]
    Unpack {
        name: String,
        #[source]
        source: MaterializeError,
    },
    #[error("writing shadow symlink {} -> {}", link.display(), target.display())]
    Symlink {
        link: PathBuf,
        target: PathBuf,
        #[source]
        source: std::io::Error,
    },
    #[error("preparing the shadow deps dir {}", path.display())]
    Io {
        path: PathBuf,
        #[source]
        source: std::io::Error,
    },
    /// Windows directory symlinks need Developer Mode / `SeCreateSymbolicLinkPrivilege`.
    /// The LSP-001 prototype is Unix-first (see Operator notes); on Windows the planned
    /// path is directory junctions or `meow install --materialize`.
    #[cfg(windows)]
    #[error(
        "the shadow symlink map needs directory-symlink privilege on Windows; enable \
         Developer Mode or run `meow install --materialize` (LSP-001 prototype is Unix-first)"
    )]
    UnsupportedPlatform,
}
```

- **Targets the cache, never the project.** Every `.meow/deps/<name>` symlink resolves (`fs::canonicalize`) to a path **under** `UnpackedStore`'s root (`~/.meow/cache/unpacked/…`); none resolves under `project_root`. The project root has **no** `node_modules` after generation (I-5). Runtime and LSP selection do not read from `.meow/deps`.
- **Integrity is enforced at the seam (I-7):** `UnpackedStore::ensure` recomputes+verifies the blob hash before decode, so a tampered cache blob makes `generate` return `ShadowError::Unpack` (wrapping `MaterializeError`) and the bad tree is **never** linked — refuse, never serve.
- **Idempotent:** two `generate` calls on an unchanged graph yield the identical link set; a dependency removed from the graph loses its `.meow/deps/<name>` on the next call.

### A4 — Resolver-parity corpus (`crates/lsp/tests/resolver_parity.rs`) — the gate fixture

```rust
/// The resolver-parity corpus: (specifier, referrer) pairs spanning bare, scoped, subpath,
/// conditional-exports, self-reference, `#imports`, relative, and nested/multi-version deps —
/// each resolved through BOTH the runtime loader and the editor resolver, built from ONE
/// shared `ResolutionGraph`, and asserted to land on the IDENTICAL URL (and identical typed
/// error). This corpus IS the `resolver-parity` gate's fixture (GATES.md, I-5). It mirrors
/// LOAD-003's `resolution_corpus.rs` cases (same archives/lockfile) so the runtime-side
/// (`graph-integrity`) and editor-side (`resolver-parity`) checks exercise one shape.
fn assert_parity(graph: &ResolutionGraph, cache: Arc<Cache>, project_root: Url);
```

The assertion is: build `graph = ResolutionGraph::assemble(Arc::new(lockfile), root_deps)?` once; from it build a **runtime** `MeowModuleLoader::new(Resolver::from_resolution(&graph, cache.clone(), root.clone(), native.clone()), GraphDb)` and an **LSP** `EditorResolver::new(&graph, cache.clone(), root.clone(), native.clone(), store)`. For each corpus specifier: `loader.resolve(spec, ref.as_str(), Import)?` (the deno_core entry the runtime actually uses) **==** `editor.resolve_module(spec, &ref)?.url`. For each error specifier: the same `ResolveError` discriminant from both. The two consumers share one `Arc<ResolutionGraph>` → parity is guaranteed by construction; the test is the standing regression guard against a future second resolver.

## Non-goals

- **Not a full LSP.** No diagnostics, hover, completion, code actions, rename, formatting-on-save, or JSON-RPC/`tower-lsp` server. Those are later LSP specs (P3+). LSP-001 ships only the resolution entry point + the shadow symlink map (CANON §20 lists the rest as the server's eventual responsibilities; this is the prototype of the resolution piece).
- **No second resolver, parser, or graph.** LSP-001 reuses `meow_loader::Resolver` verbatim; it never constructs an Oxc parser (P15), never reimplements `exports`/`imports`/conditions, and does not build a `GraphDb` for resolution (the parity test instantiates one only to drive the runtime `MeowModuleLoader`, which ignores it during `resolve`).
- **No CHK / `tsc`/`tsgo` daemon (P3).** LSP-001 does not launch, embed, or proxy the reference typechecker (ADR-5); it only makes the cache *traversable* so a later `meow check`/editor daemon (CHK-001) and the shadow `.meow/tsconfig.json` can consume it.
- **No shadow-`tsconfig.json` writing.** `ShadowDeps::tsconfig_paths()` *emits* the `paths` mapping; injecting it into `.meow/tsconfig.json` is CFG-001's generator (ADR-8) — LSP-001 does not own or rewrite tsconfig.
- **No install / unpack ownership.** Populating the blob cache is PKG-002; the global **unpacked** store and its extraction are PKG-004 (`UnpackedStore`) — LSP-001 *consumes* `ensure`/`dir_for`, it does not extract archives itself.
- **No multi-version nested shadow tree.** The flat `.meow/deps/<name>` map exposes one version per name (CANON §20.1's flat-`paths` model); a nested per-package layout for transitive multi-version precision is a full-LSP refinement (recorded via `ShadowDeps::collisions`).
- **No file watching / incremental invalidation.** `generate` is a one-shot regeneration (run on `meow install`/`meow sync`); the salsa-style watch loop (§7.2) belongs to the full LSP.
- **No Windows-first symlink support.** Unix directory symlinks ship in the prototype; Windows is flagged (junctions / `--materialize`), not implemented here.

## Interface

- **New crate** `crates/lsp` (`meow-lsp`), library only. Public surface: `EditorResolver`, `EditorResolution`, `ShadowDeps`, `ShadowError`. No binary, no CLI command, no JSON-RPC server in this spec. The workspace `members = ["crates/*"]` glob picks it up automatically — **no root `Cargo.toml` membership edit**.
- **Consumes (do not redefine):**
  - `meow_loader::{Resolver, ModuleLocator, ResolveError, MeowModuleLoader}` and `Resolver::from_resolution(graph: &ResolutionGraph, cache: Arc<Cache>, project_root: Url, native: Arc<dyn NativeModuleSource>) -> Resolver` (PKG-003 seam) — the ONE resolver + its construction path.
  - `meow_pkg::{ResolutionGraph, ResolvedPackage, Cache, ContentHash, PackageName, Version}` and `ResolutionGraph::{assemble(Arc<Lockfile>, BTreeMap<PackageName,Version>) -> Result<_, PnpError>, root_deps(), lockfile(), packages()}` (PKG-003) — the shared resolved closure; `packages()` yields `ResolvedPackage { name, version, integrity, dependencies }`.
  - `meow_pkg::{UnpackedStore, MaterializeError}` and `UnpackedStore::{ensure(&ContentHash) -> Result<&Path, MaterializeError>, dir_for(&ContentHash) -> PathBuf}` (PKG-004) — the global unpacked content-addressed store the symlinks target.
  - `meow_runtime::native::NativeModuleSource` (RT-005) — the `meow:*` source *trait*; the LSP **receives** an `Arc<dyn NativeModuleSource>` from the caller and forwards the **same** instance the run-path uses, so `meow:*` resolution is parity-identical. The lib needs only the trait (`meow-runtime { default-features = false }`, exactly as `meow-loader` consumes it — I-10); the concrete `native_module_registry()` is supplied by the CLI/host edge in production and by the dev-dep in the parity-test fixture.
  - `deno_core::url::Url`, `deno_core::ResolutionKind` (via `meow_loader`/`meow_runtime` re-exports) for referrer URLs and the runtime `resolve` call.
- **No new external crate pins** → **no `[workspace.dependencies]` fence.** `meow-lsp`'s lib deps (`meow-loader`, `meow-pkg`, `meow-runtime { default-features = false }` for the trait, `thiserror`, `deno_core`) are all workspace-internal or already declared (DIST-001/RT-002). Symlinks use `std::os::{unix,windows}::fs` only.
- **On-disk artifact:** `<project_root>/.meow/deps/` — a tree of directory symlinks (`<name>` and `@scope/<name>`) into `~/.meow/cache/unpacked/<algo>-<hex>/`. Gitignored (`.meow/`, P14/ADR-8); regenerated by `meow install`/`meow sync`.

## Implementation sketch

New crate `crates/lsp` with `Cargo.toml`: lib path-deps on `meow-loader`, `meow-pkg`, and `meow-runtime { default-features = false }` (the `NativeModuleSource` trait only — keeps the LSP lean, I-10); `thiserror` + `deno_core` workspace deps; dev-deps `meow-graph`, full `meow-runtime` (for `native_module_registry()`), and `deno_core` to build the runtime-side parity fixture. Files: `src/lib.rs` (re-exports), `src/resolver.rs` (`EditorResolver`), `src/shadow.rs` (`ShadowDeps`), `tests/resolver_parity.rs`, `tests/shadow_deps.rs`.

**Shared-file edits: none.** LSP-001 is a fully additive new crate — every file is new, so there is no comment-marker fence to place in existing source (P5 fences guard *shared* files; there are none here). The one *anticipated future* shared-file edit is **not** in this spec: when the full LSP wires the shadow `paths` into CFG-001's `.meow/tsconfig.json` generator, that edit will carry a `// === LSP-001 ===` fence in CFG's shadow-tsconfig module — flagged here so the orchestrator can see it coming.

1. **`EditorResolver::new`** → `Resolver::from_resolution(graph, cache, project_root, native)`; store the `UnpackedStore` handle. No other state. (Construction is parity-by-design: the caller hands the *same* `Arc<ResolutionGraph>` to the run-path and here.)
2. **`EditorResolver::resolve_module`** → `let (url, locator) = self.resolver.locate(spec, referrer)?;` then `match locator { LocalFile(p) => Some(p.clone()), Cached { package, member } => Some(self.store.dir_for(package).join(member)), Native { .. } => None }` for `editor_path`. Borrow `&str`/`&Url`; one `clone` of the `PathBuf` only on the `LocalFile`/`Cached` editor-path branch.
3. **`ShadowDeps::generate`** →
   - `let root = project_root.join(".meow").join("deps");` remove any existing `root` (prune), `create_dir_all(&root)`.
   - Collect `name → (integrity, version)` from `graph.packages()` (root-reachable, sorted, dangling-validated by `assemble`); on a duplicate name keep the root-reachable (else lowest `Version`) pick and push the rest into `collisions`.
   - For each kept entry: `let target = store.ensure(integrity).map_err(|e| ShadowError::Unpack{ name, source: e })?;` (integrity-gated extract-once), then create the parent (`@scope/`) and the directory symlink `root/<name>` → `target` via `cfg(unix)` `std::os::unix::fs::symlink` (on `cfg(windows)`, `std::os::windows::fs::symlink_dir`, surfacing `UnsupportedPlatform` on the privilege error — Unix-first prototype).
   - Record `links` and return.
4. **`ShadowDeps::tsconfig_paths`** → constant flat mapping `{"*": ["./.meow/deps/*"]}` plus a `@scope/*` entry per distinct scope present in `links` (so scoped packages resolve through the same `.meow/deps/@scope/` dirs).

CRAFT discipline: no `unwrap`/`panic!` on any input-reachable path (a malformed dep, a dangling edge — already rejected by `assemble` — an integrity failure, a symlink EPERM all map to typed errors); no `unsafe` (std symlink APIs only); the resolver hot path borrows and delegates (the LSP adds at most one `PathBuf` join per resolution).

## Tests required

`crates/lsp/tests/resolver_parity.rs` + `crates/lsp/tests/shadow_deps.rs`, plus unit tests in `resolver.rs`/`shadow.rs`. Proves **I-5** [`resolver-parity`] (primary) and **I-1** [`graph-integrity`]; touches **I-7** [`lockfile-integrity`] (the unpacked-store seam) and **I-11** [`honesty`] (prototype boundaries). Floor: `cargo test/clippy/fmt`, `harness/principles-check.sh`.

**`resolver-parity` (I-5 — the keystone; this corpus IS the gate's fixture):**
- **Identical resolution over the corpus.** Build one `ResolutionGraph::assemble(...)`; from it a runtime `MeowModuleLoader` and an `EditorResolver`. For each of: a bare dep with conditional `exports` (`import` wins), a `@scope/name`, a `name/subpath` over a pattern key, a self-reference, a relative `./x` sibling inside a cached package, a `#internal` import, and a **nested multi-version** dep (A→B@1, C→B@2) — assert `loader.resolve(spec, ref, Import)? == editor.resolve_module(spec, &ref)?.url`.
- **Identical failures.** A non-lockfile bare specifier → both `BareSpecifierNotInLockfile`; a `require`-only package in import context → both `NoMatchingCondition`; a non-exported subpath → both `SubpathNotExported`; an unknown `meow:` module → both `UnknownNativeModule`. A CJS dependency member is now the opposite check: both paths must locate the **same** CJS URL/locator, and the runtime load must lower it successfully.
- **No `node_modules` (I-5).** After the full corpus run + a `ShadowDeps::generate`, assert no `node_modules` path was opened or exists under `project_root`; every cached resolution URL is `meow-cache://…`.
- **Single-resolver guard (I-1, graph-integrity).** Structurally: `EditorResolver` resolves only via `self.resolver.locate`; the crate references no Oxc parser and no second resolver/exports walk (mirrors LOAD-003's parity test; backed by `principles-check.sh` P15).

**Shadow symlink map (`generate` correctness + I-7 touch):**
- **Points into the cache, not the project.** `.meow/deps/<name>` is a symlink whose `canonicalize` is under the `UnpackedStore` root and equals `store.dir_for(integrity)`; it is **not** under `project_root`; the project root has no `node_modules`.
- **Editor traversal.** `read(.meow/deps/<name>/package.json)` equals the cached package's manifest bytes; a member file (`.meow/deps/<name>/<member>`) is readable through the link.
- **Scoped packages.** `@scope/name` produces `.meow/deps/@scope/` + the nested symlink.
- **Idempotent + drift-free.** Two `generate` calls → identical link set; dropping a dep from the graph removes its link on regeneration.
- **Integrity refusal (I-7, `lockfile-integrity`).** Tamper a cached blob, then `generate` → `ShadowError::Unpack` (via `UnpackedStore::ensure` hash mismatch); the bad tree is never linked.
- **Multi-version honesty (I-11).** A graph with two versions of one name links one and records the other in `collisions()` (no panic, no silent wrong link). Runtime remains exact per-referrer (`A→B@1` vs `C→B@2` are preserved by `ResolutionGraph` + `Resolver::locate`) and not by `ShadowDeps`.

GATES: **`resolver-parity`** (I-5 — primary; the corpus is this gate's fixture, resolved through runtime + LSP to identical URLs), **`graph-integrity`** (I-1 — single resolver), with secondary coverage of **`lockfile-integrity`** (I-7 — the unpacked-store integrity seam) and **`honesty`** (I-11 — the prototype's stated boundaries: resolution + symlink map only, flat single-version map, Unix-first).

## Rollout

- **Additive, greenfield.** New crate; no existing behavior changes, no persisted production state, no migration. `meow run` is untouched. The only on-disk side effect is `<project_root>/.meow/deps/` — a gitignored, fully regenerable symlink tree (P14/ADR-8); `rm -rf .meow/deps` is always safe (it is a cache projection, not a source of truth).
- **Sequencing.** Lands after **LOAD-003** (the resolver + algorithm), **PKG-003** (`ResolutionGraph` + `Resolver::from_resolution` + `assemble`), and **PKG-004** (`UnpackedStore`). ADR-4 ships PKG-003 and PKG-004 in the same phase (P2), so all three deps are co-waved; LSP-001 follows in P2 as the resolver-parity proof.
- **Reversibility.** Delete `crates/lsp` and remove `.meow/deps/`; nothing else depends on it yet (no run-path call site, no CLI command). The `resolver-parity` gate loses its editor-side fixture but the resolver itself is unaffected.
- **Forward integration (not in this spec):** the full LSP adds (a) a CFG-001 fence to inject `ShadowDeps::tsconfig_paths()` into `.meow/tsconfig.json`, (b) a `meow lsp`/daemon entry that calls `EditorResolver` + `ShadowDeps::generate` on a watch loop, and (c) diagnostics/hover/completion. Each is a separate later LSP spec.

## Operator notes

**Integration points (named):**
- **LOAD-003:** `meow_loader::{Resolver, ModuleLocator, ResolveError, MeowModuleLoader}` consumed verbatim; the LSP resolves only via `Resolver::locate`.
- **PKG-003 (coordinated over `irc`):** seam **pinned** — type `meow_pkg::ResolutionGraph`; constructors `ResolutionGraph::assemble(Arc<Lockfile>, BTreeMap<PackageName,Version>) -> Result<_, PnpError>` (pure, disk-free fixture seam) and the disk path `load`/`for_project`; resolver factory `Resolver::from_resolution(&ResolutionGraph, Arc<Cache>, Url, Arc<dyn NativeModuleSource>) -> Resolver` (borrows `&graph` → share one `Arc<ResolutionGraph>`, each side builds its own `Resolver`; the `RefCell` PackageFs cache is single-thread per `Resolver`). Accessors `root_deps()`, `lockfile()`, `packages() -> ResolvedPackage { name, version, integrity, dependencies }`.
- **PKG-004 (coordinated over `irc`):** `meow_pkg::UnpackedStore::{ensure(&ContentHash) -> Result<&Path, MaterializeError>, dir_for(&ContentHash) -> PathBuf}` — the global unpacked store `~/.meow/cache/unpacked/<algo>-<hex>/`; `ensure` is integrity-gated (`Cache::read` recompute+verify, I-7) + idempotent. PKG-003/PKG-004 converged the shared model name on `ResolutionGraph` (PKG-004 dropped its earlier `PnpManifest` name); all three specs cite one type. Both `--materialize` and this shadow map are projections over the **same** store — one extraction path.
- **RT-005:** `meow_runtime::native::native_module_registry()` — the LSP passes the **same** native source as the runtime so `meow:*` resolution is also parity-identical.
- **CFG-001 (deferred):** `ShadowDeps::tsconfig_paths()` is emitted for CFG's shadow-`tsconfig.json` generator; wiring it (and the `// === LSP-001 ===` fence) is a later full-LSP spec, not this one.

**Forks (logged to `harness/decisions.json` as `assumption`/`needs-input` records — IDs `LSP-001-A1..A3`; surfaced here, not buried):**
1. **`LSP-001-A1` (assumption, medium):** Shadow map scope = a **flat-by-name** tree over the root-reachable closure (`graph.packages()` + `root_deps()`); on a multi-version name collision, link the root-reachable (else lowest) version and record the rest in `ShadowDeps::collisions`. Matches CANON §20.1's flat `.meow/deps/` + tsconfig-`paths` model; a nested per-package multi-version layout is a full-LSP refinement. The *runtime* resolver stays multi-version-correct regardless (this only bounds the editor projection). Reversible.
2. **`LSP-001-A2` (assumption, high):** Editor resolution surface = `EditorResolver::resolve_module(specifier, &Url) -> EditorResolution { url, locator, editor_path }`, returning the runtime-identical `url`+`locator` plus an `editor_path` into the **unpacked** store; the LSP holds its **own** `Resolver` built from the **shared** `Arc<ResolutionGraph>` (not a shared `Resolver` instance — its `RefCell` cache is single-thread, per PKG-003). Parity is by construction, asserted by the corpus test. Reversible.
3. **`LSP-001-A3` (assumption, low — surfaces loud):** **Windows portability fork.** The prototype ships **Unix** directory symlinks (`std::os::unix::fs::symlink`). Windows directory symlinks need Developer Mode / `SeCreateSymbolicLinkPrivilege`; the planned Windows path is **directory junctions** (no privilege) or falling back to `meow install --materialize`'s real `node_modules`. Default chosen: Unix-first prototype (the dev target is darwin), Windows deferred — flagged for the human because committing to junctions vs. requiring `--materialize` on Windows is a product/platform call the full LSP must settle. Reversible.

**Honest scope (report, I-11):** DELIVERED — one editor-facing resolution entry point on THE single resolver (parity proven over a corpus), and the §20.1 shadow symlink map pointing into the content-addressed unpacked cache with no project `node_modules`. NOT delivered (by design, not gaps to hide) — diagnostics/hover/completion, a JSON-RPC server, file-watch incrementality, the `tsc`/`tsgo` CHK daemon (P3), shadow-`tsconfig.json` writing (CFG owns it), multi-version nested shadow trees, and Windows symlink support. This is the resolver-parity keystone and the symlink-map mechanism — the prototype CANON §20 calls for — not the finished language server.
