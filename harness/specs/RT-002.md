## Motivation

P0 needs a real async I/O substrate so the runtime can do host I/O without blocking V8's event loop (PLAN.md *Build sequence · P0 Foundations* lists "the **async I/O layer** (`tokio`; `io_uring` on Linux — ADR-9)" as a P0 deliverable; *Initial spec backlog · Wave 1* lists `RT-002`). This is the concrete substrate behind ADR-9's positioning: `meow` wins on I/O/FFI/cold-start, never on steady-state JS. CANON §6.2 places this in the **Runtime** subsystem.

The committed cross-platform layer is **`tokio`/`mio`** (ADR-9 consequence: *"the cross-platform commitment is the `tokio`/`mio` abstraction, with `io_uring` as a per-platform accelerant — not the portability story"*). `io_uring` is a Linux-only accelerant behind a `cfg` + cargo feature; `kqueue`/IOCP are reached transparently through `mio` elsewhere.

This wires to **I-6 (Determinism & hermeticity** — gate `determinism`): *ungranted host env, clock, and randomness cannot influence execution*. The mechanism that makes that enforceable is that **all** host I/O flows through one seam (deno_core ops behind a capability hook); there is no second, ungoverned path from JS to the host. RT-002 builds that seam; enforcement on it lands at P6 (`SEC-001`).

## Acceptance criteria

Concrete, checkable. Signatures are illustrative of the deno_core `op2` model; exact attribute spelling tracks the pinned `deno_core` from `DIST-001` `[INFERENCE]`.

### 1. tokio ↔ deno_core driver (shared file `crates/runtime/src/runtime.rs`, RT-001-owned)

RT-001 owns `MeowRuntime { js: deno_core::JsRuntime, .. }`. RT-002 adds, inside a `// === RT-002 ===` fence:

```rust
// === RT-002 ===
/// Current-thread tokio runtime that drives the deno_core event loop.
/// Current-thread (not multi_thread) because V8 isolates are single-threaded
/// and ops resolve on the same thread that polls the loop.
pub fn build_io_runtime() -> std::io::Result<tokio::runtime::Runtime> {
    tokio::runtime::Builder::new_current_thread()
        .enable_all() // io + time drivers (mio under the hood)
        .build()
}

impl MeowRuntime {
    /// Register the host-I/O ops + the capability seam onto this runtime's
    /// OpState. MUST be called once before `run_to_completion`.
    pub fn install_io(&mut self, caps: std::rc::Rc<dyn crate::io::CapabilityCheck>);

    /// Poll the event loop to quiescence (all pending ops + microtasks done).
    pub async fn run_to_completion(&mut self) -> Result<(), deno_core::error::CoreError> {
        self.js
            .run_event_loop(deno_core::PollEventLoopOptions::default())
            .await
    }
}
// === RT-002 ===
```

The `meow_io` extension (below) is appended to RT-001's `extensions` vec inside a second `// === RT-002 ===` fence at the `JsRuntimeOptions` construction site.

### 2. `op_read_file`

`crates/runtime/src/io/ops.rs`:

```rust
#[deno_core::op2(async)]
#[buffer]
pub async fn op_read_file(
    state: std::rc::Rc<std::cell::RefCell<deno_core::OpState>>,
    #[string] path: String,
) -> Result<Vec<u8>, crate::io::RuntimeIoError> {
    let p = std::path::PathBuf::from(&path);
    // seam, NOT enforcement (P6): default impl returns Ok.
    let caps = state.borrow().borrow::<std::rc::Rc<dyn crate::io::CapabilityCheck>>().clone();
    caps.check(&crate::io::CapRequest::ReadFile(&p))?;
    crate::io::backend::read_file(&p)
        .await
        .map_err(|source| crate::io::RuntimeIoError::Read { path, source })
}
```

Behavior: resolves a `Promise<Uint8Array>` in JS with the file bytes; a missing/denied path rejects with a typed error (never panics — CRAFT: *"runtime does not panic on user input"*). No `unwrap`/`expect` on any user-reachable line.

### 3. `op_tcp_connect`

```rust
#[deno_core::op2(async)]
#[smi]
pub async fn op_tcp_connect(
    state: std::rc::Rc<std::cell::RefCell<deno_core::OpState>>,
    #[string] addr: String,
) -> Result<deno_core::ResourceId, crate::io::RuntimeIoError> {
    let sock: std::net::SocketAddr = addr
        .parse()
        .map_err(|_| crate::io::RuntimeIoError::BadAddr(addr.clone()))?;
    let caps = state.borrow().borrow::<std::rc::Rc<dyn crate::io::CapabilityCheck>>().clone();
    caps.check(&crate::io::CapRequest::NetConnect(&addr))?;
    let stream = crate::io::backend::tcp_connect(sock)
        .await
        .map_err(|source| crate::io::RuntimeIoError::Connect { addr, source })?;
    let rid = state.borrow_mut().resource_table.add(crate::io::TcpStreamResource::new(stream));
    Ok(rid)
}
```

Behavior: resolves to a `ResourceId` into the deno_core `resource_table`. Read/write ops on that resource are out of scope (see Non-goals); `connect` proves the async-net seam end-to-end.

### 4. Capability seam (`crates/runtime/src/io/capability.rs`)

```rust
pub enum CapRequest<'a> {
    ReadFile(&'a std::path::Path),
    NetConnect(&'a str),
}

#[derive(Debug, thiserror::Error)]
#[error("permission denied: {0}")]
pub struct CapDenied(pub String);

pub trait CapabilityCheck {
    fn check(&self, req: &CapRequest<'_>) -> Result<(), CapDenied>;
}

/// Default seam impl. Defaults to ALLOW so P0 is runnable.
/// TODO(SEC-001, P6): replace with real tiered enforcement (I-8 `capability`).
/// This is the seam only; it is NOT a security boundary yet — see Operator notes.
pub struct AllowAll;
impl CapabilityCheck for AllowAll {
    fn check(&self, _req: &CapRequest<'_>) -> Result<(), CapDenied> { Ok(()) }
}
```

`AllowAll` is stored in `OpState` as `Rc<dyn CapabilityCheck>` by `install_io`. Every op calls `caps.check(..)` *before* touching the host — verified by test #4.

### 5. Platform-accelerant `cfg` layout (`crates/runtime/src/io/backend.rs`)

Both arms expose an **identical** signature; only the body differs:

```rust
// io_uring accelerant — Linux only, feature-gated, default OFF.
#[cfg(all(target_os = "linux", feature = "io-uring"))]
mod uring;
#[cfg(all(target_os = "linux", feature = "io-uring"))]
pub use uring::{read_file, tcp_connect};

// Portable committed layer (tokio/mio: epoll/kqueue/IOCP). The default everywhere.
#[cfg(not(all(target_os = "linux", feature = "io-uring")))]
mod portable;
#[cfg(not(all(target_os = "linux", feature = "io-uring")))]
pub use portable::{read_file, tcp_connect};

// contract both modules satisfy:
//   pub async fn read_file(path: &Path) -> std::io::Result<Vec<u8>>;
//   pub async fn tcp_connect(addr: SocketAddr) -> std::io::Result<tokio::net::TcpStream>;
```

`portable.rs` = `tokio::fs::read` / `tokio::net::TcpStream::connect`. `uring.rs` = `tokio-uring` equivalents. The `io-uring` cargo feature is declared in `crates/runtime/Cargo.toml`, default-off; it pulls `tokio-uring` only `[target.'cfg(target_os = "linux")'.dependencies]`. Acceptance is **compile-gating only** (test #3): the uring arm compiles on Linux under `--features io-uring`; the portable arm compiles and is the wired default everywhere — **no perf assertion** (I-11, see Non-goals).

## Non-goals

- **No capability enforcement.** The seam exists and defaults to allow; real tiered enforcement is P6 `SEC-001` (I-8, gate `capability`). RT-002 must not claim any security property.
- **No FFI / N-API.** ADR-9's FFI half is a later spec.
- **No performance claims, numbers, or benchmarks.** Per I-11 + ADR-9 §24.1, "faster I/O" is workload-specific and needs a named workload + repro; RT-002 ships neither. `io_uring` is described as an accelerant, never "Nx".
- **No full `io_uring` ↔ event-loop integration.** `tokio-uring` needs its own current-thread uring driver; marrying it to the deno_core loop is a named follow-up (`RT-002a`). RT-002 keeps the **default/wired** backend = tokio/mio and only compile-checks the uring arm.
- **No broad fs/net surface.** Only `op_read_file` + `op_tcp_connect` (+ a `TcpStreamResource` shell). No write/stat/readdir, no socket read/write/listen, no `meow:*` public API exposure — these are internal ops feeding later loader/Web-API specs.
- **No new resolver/parser.** Reuses RT-001's `JsRuntime`; one event loop, one OpState (CRAFT: reuse the ecosystem we bet on).

## Interface

New module tree under the **RT-001-owned** `crates/runtime`:

```
crates/runtime/
  Cargo.toml                  # +tokio (rt, fs, net, macros), thiserror; [feature] io-uring
  src/
    runtime.rs                # RT-001-owned; RT-002 adds driver + ext reg in `// === RT-002 ===` fences
    io/
      mod.rs                  # pub mod ops/backend/capability; re-exports; `deno_core::extension!`
      ops.rs                  # op_read_file, op_tcp_connect, RuntimeIoError, TcpStreamResource
      backend.rs              # cfg dispatch (uring vs portable)
      backend/portable.rs     # tokio/mio impl (default)
      backend/uring.rs        # tokio-uring impl (cfg linux + feature io-uring)
      capability.rs           # CapRequest, CapDenied, CapabilityCheck, AllowAll
```

The deno_core extension (in `io/mod.rs`):

```rust
deno_core::extension!(
    meow_io,
    ops = [crate::io::ops::op_read_file, crate::io::ops::op_tcp_connect],
);
```

Typed error (`io/ops.rs`), `thiserror`, conforming to deno_core's error-class trait so it surfaces as a JS exception rather than a panic `[INFERENCE]` (exact trait = pinned `deno_core`/`deno_error`):

```rust
#[derive(Debug, thiserror::Error)]
pub enum RuntimeIoError {
    #[error(transparent)]
    Denied(#[from] crate::io::CapDenied),
    #[error("read {path}: {source}")]
    Read { path: String, #[source] source: std::io::Error },
    #[error("invalid socket address {0:?}")]
    BadAddr(String),
    #[error("connect {addr}: {source}")]
    Connect { addr: String, #[source] source: std::io::Error },
}
```

## Implementation sketch

1. `Cargo.toml` (crates/runtime): add `tokio = { features = ["rt", "fs", "net", "macros", "io-util"] }`, `thiserror`; declare `[features] io-uring = ["dep:tokio-uring"]` with `tokio-uring` as an optional Linux-only target dep. Keep the default feature set OFF for `io-uring` (footprint/I-10 friendliness — gate `footprint` is DIST-001's, but don't regress it).
2. `io/capability.rs`: the seam (trait + `AllowAll`) with the `TODO(SEC-001)` marker naming the P6 owner.
3. `io/backend.rs` + `backend/{portable,uring}.rs`: the `cfg` dispatch; portable body first (this is what everything else links against), uring body second (compile-checked).
4. `io/ops.rs`: the two ops + `RuntimeIoError` + `TcpStreamResource` (a `deno_core::Resource` wrapper around `tokio::net::TcpStream`; AsyncRefCell as in deno_net `[INFERENCE]`).
5. `io/mod.rs`: `extension!` macro + re-exports.
6. `runtime.rs` — two `// === RT-002 ===` comment-marker fences (coordinate with RT-001 / peer `RT001` over IRC before editing): one adds `build_io_runtime` + `install_io` + `run_to_completion`; the other appends `meow_io::init_ops()` to RT-001's `extensions` vec at the `JsRuntimeOptions` site.
7. Wire `main`/entry (RT-001) to `build_io_runtime().block_on(rt.run_to_completion())` — additive only.

`unsafe`: none introduced (CRAFT: `unsafe` only at the V8/FFI boundary; this layer is safe tokio). Buffers: `op_read_file` returns owned `Vec<u8>` once (no extra clone on the way to V8 via `#[buffer]`).

## Tests required

Location `crates/runtime/tests/io_*.rs` (+ `#[cfg]` unit tests). Invariants proved and governing gate:

- **`io_async_completes`** — write a temp file; from JS, `await` the read op under `run_to_completion`; assert returned bytes == file bytes and the loop reaches quiescence. *Proves: an async op completes under the event loop.*
- **`io_concurrent_resolve`** — `Promise.all` of N `op_read_file` over distinct temp files + 2 `op_tcp_connect` to a `tokio::net::TcpListener` bound on `127.0.0.1:0`; assert all resolve, count matches, listener accepts both. *Proves: concurrent ops resolve (the I/O-concurrency story behind ADR-9, without any perf number).*
- **`io_seam_on_path`** — install a recording `CapabilityCheck` that denies `ReadFile`; assert `op_read_file` rejects with `RuntimeIoError::Denied` and the recorder saw exactly one `CapRequest::ReadFile`. *Proves: every host op traverses the seam (I-6 determinism posture — host I/O has a single governed entry; pre-stages the P6 `capability` gate).*
- **`io_backend_cfg`** — a `#[cfg(not(all(target_os="linux", feature="io-uring")))]` test asserts the portable path is active; CI matrix builds `cargo build -p runtime --features io-uring` on `target_os="linux"` (compile gate) and the default elsewhere. *Proves: uring arm compiles on Linux, fallback compiles + runs elsewhere.*
- **`io_no_panic_on_bad_input`** — read a nonexistent path and connect to an unparseable addr; assert typed `Err` (no panic/abort). *Proves: CRAFT no-panic-on-user-input.*

**Gates.** Governing invariant: **I-6 → `determinism`** (host I/O only via the seam; ungranted host state invisible). The full `determinism` gate (two-machine + scrambled env/clock/randomness, GATES.md) runs at P1 over `meow run`; RT-002 stands up its precondition (single governed I/O entry) and proves it at unit level. **`honesty` (I-11)** applies to this surface: the audit checks that nothing in code/comments/docs asserts an `io_uring` speedup or any I/O multiplier without a named workload + repro — RT-002 ships none, so the surface must read as accelerant-not-portability with zero perf numbers.

## Rollout

- Pure addition on top of RT-001; no user-visible flag and no `meow:*` API change (ops are internal). `meow run` (P1) consumes the driver later.
- `io-uring` is a default-off cargo feature; release builds (DIST-001) stay on the portable backend until `RT-002a` lands the real uring↔loop integration. This keeps `footprint`/`determinism` unaffected by an experimental accelerant.
- **Reversibility:** revert is the two `// === RT-002 ===` fences in `runtime.rs` + deletion of `src/io/` and the `Cargo.toml` additions. No migrations, no persisted state, no schema. Dropping the `io-uring` feature removes the accelerant with zero effect on the default path.

## Operator notes

- **Capability seam is NOT a security boundary yet.** `AllowAll` defaults to allow; enforcement is P6 `SEC-001` (I-8). The `TODO(SEC-001)` marker is intentional. Do not describe RT-002 as enforcing anything (I-11).
- **Assumption / fork (default chosen, flag for Main → `decisions.json`):** full `tokio-uring` ↔ deno_core event-loop integration is **deferred**; RT-002 wires the portable tokio/mio backend as default and only *compile-checks* the uring arm. Rationale: `tokio-uring` requires its own current-thread uring driver, and ADR-9 explicitly makes tokio/mio the committed portability layer with uring as an accelerant — so a compile-gated accelerant + portable default is the honest P0 scope. Follow-up: `RT-002a`.
- **Assumption:** ops are named `op_read_file`/`op_tcp_connect` (internal), not yet public `meow:*` surface; later loader/Web-API specs decide the public shape.
- deno_core attribute spelling (`#[op2]`, `#[buffer]`, `#[smi]`, error-class trait) tracks the version pinned by `DIST-001`; verify against that crate at implementation time `[INFERENCE]`.
- Coordinate the `crates/runtime/src/runtime.rs` edits with RT-001 (peer `RT001`) via the comment-marker fences to avoid a merge collision.
