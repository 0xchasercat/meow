## Motivation

P1's MVP exit is *"a small TS web server runs with no emitted JS"* and the phase's required gates include **`types-fresh`** (PLAN.md → Build sequence · P1 Minimal Runtime; backlog Wave 2 · `RT-005`). Two things are needed for that and neither exists yet:

1. **A way to actually serve HTTP.** RT-004 ships the Web-standard *types* (`Request`/`Response`/`Headers`/`URL` as ambient globals) and RT-002 the async-I/O seam (`tokio`/`mio` ops behind `CapabilityCheck`), but nothing turns `(Request) => Response` into a listening server. `meow:http`'s `serve(handler)` is the first user-reachable `meow:*` capability and the thing the MVP web service imports (CANON §8.2, F5).

2. **The mechanism that makes `meow:*` types real (the load-bearing piece).** `import { serve } from "meow:http"` must type-check **in-editor with nothing installed** — no `@types/meow`, no community package, no hand-maintained `.d.ts` that drifts from the runtime. CANON §8.2 / principle 8 / **I-9** require the declarations to be *generated from the same source of truth as the implementation, so they cannot drift*, and GATES.md binds I-9 to the **`types-fresh`** gate (*regenerate → diff against committed `.d.ts` must be empty; no `@types/meow` exists*). This spec designs that generation mechanism and proves it; `meow:http` is its first subject.

Spine: `Wave 2 (P1 · MVP)` backlog item `RT-005` (PLAN.md). It serves **I-9** (runtime types generated from the implementation, no drift — `types-fresh`) and **I-6** (the server runs through the one governed host-I/O seam; the type-emit is byte-deterministic). The `meow:` namespace being *the only* runtime-API shape (PRODUCT.md lexicon: *"the `meow:` namespace is the only runtime-API shape, and its types are always present in-editor without installing anything"*) is the product invariant this realizes.

## Acceptance criteria

Builds on the merged runtime: `meow_runtime::{Runtime, RuntimeOptions}` (RT-001), the `MeowRuntime` op/extension + `install_io(caps)` driver and `crate::io::{CapRequest, CapabilityCheck, CapDenied}` seam (RT-002), RT-004's ambient `Request`/`Response`/`Headers` globals, and the single `meow_loader::Resolver`/`MeowModuleLoader` (LOAD-001). Errors are typed (`thiserror`); **no `unwrap`/`expect`/`panic!` on any path reachable from user JS or a handler** (CRAFT Part B); the runtime surfaces diagnostics that name the cause **and** the fix.

### A1 · `meow:http` public surface — the authored TS implementation (`crates/runtime/src/js/meow/http.ts`)

This file is **the single source of truth** for both the executed module and the generated declarations (A4). Its `export`ed signatures are the API; its body is the implementation. It consumes RT-004's ambient `Request`/`Response`/`Headers` (no import — they are Web globals on `globalThis`).

```ts
// meow:http  (executed as a type-stripped module via the graph/RT-003; A3)
// The internal op accessor is the established deno_core convention; not exported,
// so it never appears in the emitted .d.ts.
const ops = (globalThis as { Deno: { core: { ops: Record<string, any> } } }).Deno.core.ops;

export interface NetAddr {
  readonly hostname: string;
  readonly port: number;
}

export interface ServeOptions {
  /** TCP port to bind. Default 8000. */
  port?: number;
  /** Interface to bind. Default "0.0.0.0". */
  hostname?: string;
  /** Abort to stop accepting and drain in-flight requests. */
  signal?: AbortSignal;
  /** Called once the listener is bound, with the resolved address. */
  onListen?: (addr: NetAddr) => void;
}

export interface Server {
  /** The bound address (resolved port — `0` becomes the OS-assigned port). */
  readonly addr: NetAddr;
  /** Stop accepting, drain in-flight requests, release the listener. Idempotent. */
  shutdown(): Promise<void>;
  /** Resolves when the accept loop has fully stopped (after shutdown / signal). */
  readonly finished: Promise<void>;
}

export type Handler = (request: Request) => Response | Promise<Response>;

/**
 * Start a Web-standard HTTP/1.1 server. `handler` is invoked per request with a
 * `Request` and must return a `Response`. Requires the **network** capability;
 * without a grant the returned server's bind rejects with a fix-pointing error.
 */
export function serve(handler: Handler, options?: ServeOptions): Server;
```

Behavior of `serve` (the impl body, over the A2 ops):
- Calls `op_http_serve(hostname, port)` to bind (capability checked in Rust, A2) → server resource id + resolved `NetAddr`; invokes `onListen(addr)`.
- Runs an accept loop: `await op_http_next(rid)` yields the next request's parts + a response-slot id, or `null` once drained. For each, it constructs a `Request` from the parts (using the ambient global), awaits `handler(request)`, reads the returned `Response` (status, headers, body), and calls `op_http_respond(slot, status, headers, body)`. Requests are handled concurrently (each in its own microtask); a handler that throws or returns a non-`Response` yields a `500` and is reported, never crashing the loop.
- `signal` abort and `shutdown()` both stop `op_http_next`, drain, and resolve `finished`.

### A2 · Rust op layer + network capability gate (`crates/runtime/src/ext/http/`)

The HTTP/1.1 machinery reuses **`hyper` + `hyper-util`** over `tokio::net::TcpListener` (CRAFT: reuse the ecosystem we bet on; do not hand-roll a parser/server — that is the "hand-roll of a solved problem" symptom and would also grow footprint, I-10). A `deno_core::extension!` registers the ops; `meow_runtime` installs it alongside the RT-002 I/O extension.

```rust
// crates/runtime/src/ext/http/ops.rs
#[derive(Debug, thiserror::Error)]
pub enum HttpError {
    #[error("network capability is required to bind {addr} — add \"net\" to permissions in meow.config.ts")]
    Denied { addr: String },
    #[error("could not bind {addr}: {source}")]
    Bind { addr: String, #[source] source: std::io::Error },
    #[error("invalid bind address {addr:?}")]
    BadAddr { addr: String },
    #[error("http server resource {rid} is gone")]
    NoServer { rid: u32 },
}

/// Bind the listener and spawn the hyper accept loop feeding a request channel.
/// THE NETWORK CAPABILITY IS CHECKED HERE, before any socket is created (A-test capability).
#[op2(async)]
#[serde]
async fn op_http_serve(
    state: Rc<RefCell<OpState>>,
    #[string] hostname: String,
    #[smi] port: u16,
) -> Result<ServeHandle, HttpError>; // ServeHandle = { rid: ResourceId, hostname: String, port: u16 }

/// Await the next request for `rid`. Resolves to the request parts + a response-slot id,
/// or `None` once the server is shut down / aborted and drained.
#[op2(async)]
#[serde]
async fn op_http_next(state: Rc<RefCell<OpState>>, #[smi] rid: u32)
    -> Result<Option<IncomingRequest>, HttpError>; // { slot: u32, method, url, headers: Vec<(String,String)>, body: Vec<u8> }

/// Send the handler's response for `slot`.
#[op2(async)]
async fn op_http_respond(
    state: Rc<RefCell<OpState>>,
    #[smi] slot: u32,
    #[smi] status: u16,
    #[serde] headers: Vec<(String, String)>,
    #[buffer] body: JsBuffer,
) -> Result<(), HttpError>;

/// Graceful shutdown: stop accepting, drain in-flight, drop the listener.
#[op2(async)]
async fn op_http_shutdown(state: Rc<RefCell<OpState>>, #[smi] rid: u32) -> Result<(), HttpError>;
```

Capability gate (reuses RT-002's seam — extends, never forks it). `op_http_serve` does, **before binding**:

```rust
let addr: SocketAddr = format!("{hostname}:{port}").parse().map_err(|_| HttpError::BadAddr { .. })?;
let caps = state.borrow().borrow::<Rc<dyn crate::io::CapabilityCheck>>().clone();
caps.check(&crate::io::CapRequest::NetListen(&addr)).map_err(|_| HttpError::Denied { addr: addr.to_string() })?;
let listener = tokio::net::TcpListener::bind(addr).await.map_err(|e| HttpError::Bind { .. })?;
```

This requires **one fenced extension** to RT-002's `CapRequest` (it has `NetConnect`, not `NetListen`):

```rust
// crates/runtime/src/io/capability.rs
pub enum CapRequest<'a> {
    // … existing ReadFile / NetConnect …
    // === RT-005 ===
    /// Bind a listening socket (meow:http serve). Tier-2/scoped enforcement is SEC-001/RT-006.
    NetListen(&'a std::net::SocketAddr),
    // === /RT-005 ===
}
```

At P1 the wired `CapabilityCheck` is RT-002's `AllowAll` (the honest default; full tiered/scoped enforcement is RT-006/SEC-001, I-8 — see Operator notes). The *gate is on the path*: a denying check makes `serve` reject with `HttpError::Denied`. No claim of enforcement is made beyond "defense-in-depth" (I-11).

### A3 · `meow:` scheme resolution — importable `meow:http` (single resolver, I-1/I-5)

`import "meow:http"` must resolve through **the one** `meow_loader::Resolver` (LOAD-001 reserved the `meow:` namespace precisely for this). The runtime owns the native module *sources* (so the impl + its types live together, A1/A4); the loader owns *resolution*. The runtime exposes a registry; the loader gains a fenced `meow:`-scheme arm that consults it.

```rust
// crates/runtime/src/native.rs  (RT-005)
/// Embedded source of every meow:* module — the same .ts authored in src/js/meow/
/// (A1), embedded with include_str!. Single source of truth shared with type-gen (A4).
pub fn native_module_source(name: &str) -> Option<&'static str>; // "http" -> http.ts source
pub const NATIVE_MODULES: &[&str] = &["http"]; // grows as fs/process/… land
```

```rust
// crates/loader/src/resolver.rs — fenced arm in the single locate()/resolve()
// === RT-005 ===
// `meow:<name>` → a native module. Validates <name> against the runtime's registry;
// an unknown meow: specifier errors with the fix ("meow:http is the only … available").
// Native source is served from the injected NativeModuleSource (no disk, no cache).
// === /RT-005 ===
```

The native source is type-stripped through the shared graph like any TS (RT-003 / I-3) and executed; it references the A2 ops via the internal `Deno.core.ops` accessor (the ops exist because `meow_runtime` installs the `meow_http` extension). Acceptance: a user module doing `import { serve } from "meow:http"; serve(...)` resolves, runs, and serves — through one resolver, with no second resolution path (I-1).

### A4 · Native type-generation mechanism (`meow types`) — **I-9, the load-bearing piece**

**Single source of truth = the authored impl** (`src/js/meow/http.ts`, A1). The committed `.d.ts` is *derived from it*, never hand-written. Mechanism:

- **`meow types --emit`** runs **declaration-only emit** over every `src/js/meow/*.ts` and writes one `.d.ts` per module to the **committed** path `crates/runtime/types/meow/<name>.d.ts` (these ARE the shipped types; checked into git and embedded into the binary via `include_str!`).
  - Emit is **delegated to the reference compiler** (`tsc --emitDeclarationOnly`, or the `tsgo` daemon as it stabilizes — ADR-5 / **I-4**: meow builds **no** native typechecker and therefore **no** native `.d.ts` emitter). The emit runs against a generated tsconfig that pulls in RT-004's ambient global lib (so `Request`/`Response` resolve) plus the meow:* sources.
  - Output is **normalized for byte-determinism** (I-6/I-9): a fixed `GENERATED — do not edit (run: meow types)` header, stable member order as tsc emits it, LF newlines, trailing newline. Same sources ⇒ byte-identical `.d.ts`.
- **`meow types --check`** regenerates to a temp dir and **diffs against the committed `.d.ts`**; a non-empty diff exits non-zero with the offending file(s) and *"run `meow types --emit` and commit the result."* **This is the `types-fresh` gate's executable form** (GATES.md: regenerate → diff committed must be empty; no `@types/meow`).

Because the executed module and the declaration both come from the *same* `http.ts`, the shipped types cannot drift from the shipped implementation — the I-9 guarantee. (Honest boundary: this proves *shipped-types == impl-shim*, not *impl-shim == Rust-op-behavior*; the latter is covered by the A1/A2 runtime tests, not the type gate. Stated in Operator notes.)

### A5 · Editor resolution with nothing installed (shadow tsconfig `paths` → bundled `.d.ts`)

`import { serve } from "meow:http"` type-checks in any editor that reads the generated `.meow/tsconfig.json` (CFG-001 / ADR-8), with **no install**:

- `meow sync` (and `meow install`) writes the binary-embedded `.d.ts` to `.meow/types/meow/<name>.d.ts` and adds a `paths` mapping so the `meow:` specifier resolves to it.

```jsonc
// added to .meow/tsconfig.json compilerOptions (RT-005)
"paths": { "meow:*": ["./types/meow/*"] }
```

`meow:http` → `meow:*` (`*` = `http`) → `./types/meow/http.d.ts`. Standard TS `paths` resolution; no `declare module` gymnastics, no `@types/meow`, no community package. (`.meow/` is a gitignored build artifact regenerated by sync/install — the same honest residual as all shadows, CANON §24.5; stated in Operator notes.)

### A6 · CLI surface

- **`meow types [--emit | --check]`** — new verb (CANON §19 grammar; not previously listed — additive, flagged in Operator notes). `--emit` regenerates the committed `.d.ts`; `--check` is the freshness check (A4). Bare `meow types` = `--check`.
- **`meow sync`** also refreshes `meow:*` types into `.meow/` + the `paths` entry (A5) — coherent with its existing "regenerate shadow configs" role.

`import { serve } from "meow:http"` running a server that handles a request → response (capability-gated), and `meow types --check` passing on freshly-emitted `.d.ts`, are the two acceptance anchors.

## Non-goals

- **No full Node `http`/`http2`/`net` surface.** Only `meow:http`'s Web-standard `serve` (`Request`→`Response`). `node:http` is `node-compat`/P5 (`RT-007`).
- **No WebSocket / HTTP upgrade.** `serve` returns `Response`; `101`/upgrade and `WebSocket` are a later spec (CANON §8.1 lists `WebSocket` outside the Stateless-Edge subset).
- **No HTTP/2, TLS, or `Deno.serveHttp`-style connection API.** HTTP/1.1 cleartext only; TLS termination and h2 are later.
- **No capability *enforcement* / scoped or per-package grants.** RT-005 only adds `CapRequest::NetListen` to the existing seam; tiered/scoped enforcement (Trust Zones) is RT-006/SEC-001 (I-8). RT-005 claims no security property beyond "defense-in-depth."
- **No native typechecker or native `.d.ts` emitter.** Declaration emit is delegated to `tsc`/`tsgo` (I-4, ADR-5). RT-005 owns orchestration + normalization + the freshness check, not a TS compiler.
- **No type generation for non-`meow:*` surfaces.** RT-004's ambient Web-global lib is curated/vendored upstream decls (RT-004 scope, confirmed with that drafter); RT-005's gen mechanism is for the `meow:*` modules only.
- **No new resolver or parser.** The `meow:` arm lives inside the one `meow_loader::Resolver`; native source is type-stripped via the shared graph (I-1, I-3).

## Implementation sketch

1. **TS impl** `src/js/meow/http.ts` (A1) — the authored module; the only place the API shape exists.
2. **Op layer** `src/ext/http/{ops.rs, mod.rs}` (A2) — `hyper`/`hyper-util` over `tokio::net::TcpListener`; a `ServerResource` (deno_core `Resource`) holding the accept-loop handle + an `mpsc` of `(IncomingRequest, oneshot<Response>)`; `op_http_next` pops, `op_http_respond` completes the matching `oneshot`. `extension!(meow_http, ops = [op_http_serve, op_http_next, op_http_respond, op_http_shutdown])`. **No `unsafe`** (safe tokio/hyper). Capability checked before bind.
3. **CapRequest** — fenced `NetListen` variant in `io/capability.rs` (A2); coordinate with RT-002 owner over the fence.
4. **Native registry** `src/native.rs` (A3) — `include_str!` the meow:* sources; `meow_runtime` installs `meow_http` and exposes the registry. Loader arm (fenced) in `crates/loader/src/resolver.rs`.
5. **Type-gen** `src/typegen.rs` + the `meow types` command (A4/A6) — drive `tsc --emitDeclarationOnly` (resolve the binary like the ADR-5 daemon does), normalize, write committed `.d.ts`; `--check` = regen-to-temp + diff.
6. **Shadow wiring** — fenced `// === RT-005 ===` in `crates/config/src/shadow.rs` (A5).
7. **CLI** — fenced `// === RT-005 ===` in `crates/cli` (A6).

Comment-marker fences for shared-file edits: **`// === RT-005 ===`** in `crates/runtime/src/io/capability.rs`, `crates/loader/src/resolver.rs`, `crates/config/src/shadow.rs`, `crates/cli`. Coordinate each with its owner (RT001/RT002 for runtime, LOAD owner, CFG owner) over IRC before editing — fences MUST be balanced (`principles-check.sh`).

## Tests required

In-crate tests (`crates/runtime/tests/`), run via `cargo test --workspace`. They prove invariants, not plumbing (CRAFT).

- **`serve_handles_request` (→ I-6 happy path; the MVP exit):** install `meow_http` + RT-002 I/O with `AllowAll`; run a module: `serve((req) => new Response("hi " + new URL(req.url).pathname), { port: 0, onListen })`; from the test (a `tokio` client / `reqwest`-free `hyper` client) issue `GET /world` to the resolved `addr`; assert body `"hi /world"`, status `200`, and that the handler saw a real `Request` (method/url/headers). Then `shutdown()` and assert `finished` resolves. *Proves: a Web `(Request)=>Response` server runs end-to-end through the runtime.*
- **`serve_capability_gated` (→ capability seam, A2):** install a recording `CapabilityCheck` that **denies** `NetListen`; assert `serve(...)`'s bind rejects with `HttpError::Denied` (the diagnostic names `net` + `meow.config.ts`), the recorder saw exactly one `CapRequest::NetListen`, and **no socket was bound** (port still free). *Proves: bind traverses the seam before touching the host (I-6 posture; pre-stages the P6 `capability` gate).*
- **`serve_handler_error_is_500` (→ no-crash):** a handler that `throw`s and one that returns a non-`Response`; assert each request gets `500`, the error is reported, and the loop keeps serving the next request. *Proves: CRAFT no-panic / deliberate edge handling.*
- **`meow_import_resolves` (→ I-1):** `import { serve } from "meow:http"` resolves through the one `Resolver`; an unknown `meow:nope` errors with the fix-pointing diagnostic (not a disk walk). *Proves: single resolver owns the `meow:` scheme.*
- **`typegen_roundtrips` (→ I-9, the `types-fresh` gate):** `meow types --emit` to a temp tree, then `--check` ⇒ empty diff / exit 0; mutate a committed `.d.ts` by hand ⇒ `--check` exits non-zero naming the file. A second case asserts emit is **byte-stable** (emit twice ⇒ identical bytes). And assert **no `@types/meow`** dependency exists anywhere in the workspace. *Proves: declarations are generated-from-impl and cannot drift.*
- **`editor_resolves_meow_http` (→ I-9 editor surface):** after `meow sync` in a temp project, `.meow/types/meow/http.d.ts` exists and `.meow/tsconfig.json` carries `paths["meow:*"] = ["./types/meow/*"]`; run the reference compiler over a fixture `import { serve } from "meow:http"; serve(() => new Response("x"))` against that tsconfig ⇒ **no diagnostics**, and a wrong call (`serve(123)`) ⇒ a type error. *Proves: types resolve in-editor with nothing installed.*

**Applicable gates:** **`types-fresh`** (I-9 — regen == committed; no `@types/meow`) is the headline gate this spec stands up; **`determinism`** (I-6 — server runs via the governed seam; type-emit byte-stable); **`honesty`** (I-11 — no security/perf claim beyond what is enforced; the `tsc`-delegation and capability boundaries are stated, not papered over).

## Operator notes

- **HONEST BOUNDARY — `.d.ts` emit is delegated, not native (I-4/I-9).** `meow types --emit/--check` shells out to the reference compiler (`tsc --emitDeclarationOnly`; `tsgo` as it stabilizes — ADR-5) to produce declarations; meow builds **no** native `.d.ts` emitter. Consequence: **regeneration and the `types-fresh` gate require the reference compiler available** (the same dependency `meow check` already has). End-users and editors need **nothing** — the committed `.d.ts` ship in-repo and embedded in the binary; only the dev/CI freshness step touches `tsc`. State this plainly; do not claim a self-contained type generator.
- **HONEST BOUNDARY — capability is the process-tier default at P1 (I-8).** `serve` checks `CapRequest::NetListen` on the existing RT-002 seam, but the wired `CapabilityCheck` is `AllowAll` until RT-006/SEC-001. No string/doc/comment in this change may say "sandboxed"/"blocked"/"isolated" for the network — it is **defense-in-depth**, scoped/per-package enforcement is later (CANON §24.3). The diagnostic points at `permissions` in `meow.config.ts`, which is the eventual grant surface.
- **HONEST BOUNDARY — `types-fresh` proves types==impl-shim, not shim==ops.** Generating the `.d.ts` from `http.ts` guarantees the *shipped types match the shipped TS implementation* (kills `@types/meow` drift — the I-9 target). It does **not** prove the TS shim's annotations match the Rust ops' runtime behavior; that correctness is covered by the A1/A2 runtime tests (`serve_handles_request` et al.), not the type gate. The two checks are complementary and both run.
- **HONEST BOUNDARY — editor types need a synced `.meow/`.** In-editor resolution depends on `meow sync`/`meow install` having written `.meow/types/` + the `paths` entry (`.meow/` is a gitignored build artifact, CANON §24.5 residual — `meow doctor` flags staleness). This is the existing shadow-config contract, not new fragility.
- **Assumption / fork (default chosen — flag for Main → `decisions.json`, not written here):**
  1. **HTTP machinery = `hyper`/`hyper-util`** over `tokio`, not a hand-rolled HTTP/1.1 parser (CRAFT: reuse the solved problem; I-10: hyper is small vs. correctness risk). Reversible behind the op layer.
  2. **`meow:*` source-of-truth lives in `crates/runtime/src/js/meow/*.ts`** and the committed `.d.ts` in `crates/runtime/types/meow/`. Chosen so impl + types are one file; the loader serves the embedded source and the type-gen reads the same file — neither can drift.
  3. **New CLI verb `meow types`** (not in CANON §19's list) — additive, fits the `meow <verb>` grammar; folded into `meow sync` too. Minor CANON/Plan drift, additive and reversible; flag for the intent-gate to reconcile.
  4. **`meow:` scheme served via an injected `NativeModuleSource` consulted by the one `Resolver`** (vs. a deno_core `ext:` snapshot module) — keeps a single resolver/algorithm (I-1) and lets user code import `meow:http` directly. Coordinate the injection point with the LOAD owner.
- **deno_core attribute spelling** (`#[op2]`, `#[serde]`, `#[buffer]`, `#[smi]`, `JsBuffer`, resource/`AsyncRefCell` patterns) tracks the version DIST-001 pinned; verify against that crate at implementation time `[INFERENCE]`.
- **Coordinate fences** with RT001/RT002 (`io/capability.rs`), the LOAD owner (`resolver.rs`), and the CFG owner (`shadow.rs`) over IRC before editing — balanced markers, no merge collisions.
