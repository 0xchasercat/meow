## Motivation

Determinism is the contract (CONSTITUTION Part B · Articles; the core bet, CANON §1 #5). The product promise is that *same `source + lockfile + meow version + capabilities` ⇒ same behavior, and the host environment, clock, and randomness cannot influence a run unless explicitly granted* (I-6, CANON §1 #5). RT-001 and RT-002 deliberately introduced **no** ambient host reads (RT-001 §A6/T5, RT-002's single governed I/O entry) — but neither *closed* the three holes through which the host still leaks into a V8 program: V8's built-in `Date`/`Math.random`, the Web `crypto` entropy source (RT-004), and any environment read. This spec makes the runtime **hermetic by default**: those three nondeterminism sources are routed through one governed seam where, by default, the clock is a fixed virtual clock, randomness is a seeded stream, and host env is invisible — and a grant swaps in the real host source.

This is the same architectural seam RT-002 established (a policy object injected into `OpState`, every host touch passing through it; RT-002 §Motivation: *"all host I/O flows through one seam … there is no second, ungoverned path from JS to the host"*). RT-006 extends that seam from fs/net resources to the **§15.2 capability categories** `system time · randomness · environment-variable access`. It is also the **substrate the test runner reuses** (CANON §16, PLAN.md `TEST`/P6): *deterministic by default — fake clock, fake network, seeded randomness*. The clock/RNG sources defined here are exactly what `meow test` (P6) drives; building them once, in the runtime, is the I-1/CRAFT "one mechanism, reused" decision rather than a second clock for tests.

Traces to **I-6 [`determinism`]** (CANON §1, CRAFT *"Determinism & hermeticity are structural, not best-effort"*). The cheap floor tripwire already exists: `principles-check.sh` P16 greps for `std::env::var`/`SystemTime::now`/`Instant::now`/`rand::` outside `/(host|hermetic)/` — so this spec's host calls live in `crates/runtime/src/hermetic/` and are the *only* sanctioned instances in the workspace. The adversarial proof is the `determinism` gate (GATES.md).

Concrete and checkable. New module tree under the **RT-001-owned** `crates/runtime`; deno_core `op2`/`extension!` attribute spelling tracks the pin DIST-001 owns `[INFERENCE]`.

### A1 · The hermetic config — deterministic by default (`crates/runtime/src/hermetic/config.rs`)

The three categories are modelled as **source selection**, not allow/deny: denying a clock outright would break almost every program, so the correct shape is a deterministic *substitute* vs the real host source (see Operator notes — this is the deliberate divergence from RT-002's binary `CapabilityCheck`).

```rust
/// The clock/rng/env slice of a run's capability set. `Default` is fully deterministic:
/// this is what makes a bare `meow run` reproducible (I-6). A grant flips one field to the
/// real host source. P6 `SEC-001` populates this from the unified grant model; until then
/// the CLI flags (A6) build it directly.
#[derive(Debug, Clone)]
pub struct HermeticConfig {
    pub clock: ClockSource,   // default: Virtual
    pub rng: RngSource,       // default: Seeded
    pub env: EnvPolicy,       // default: Deny
}

/// Fixed origin so two runs agree (I-6). 2026-06-07T00:00:00Z in ms; a named constant, not a literal at the callsite.
pub const MEOW_VIRTUAL_EPOCH_MS: f64 = 1_780_531_200_000.0;
/// Fixed 32-byte default seed → the default RNG stream is identical across runs/machines.
pub const MEOW_DEFAULT_SEED: [u8; 32] = [0u8; 32];

#[derive(Debug, Clone)]
pub enum ClockSource {
    /// Deterministic: starts at `origin_ms`, advances ONLY via the runtime's timer queue
    /// (RT-004 `setTimeout`); frozen at origin until that lands (honest boundary, Operator notes).
    Virtual { origin_ms: f64 },
    /// Granted real wall-clock + monotonic time. The ONLY `SystemTime::now`/`Instant::now` in the workspace.
    Real,
}

#[derive(Debug, Clone)]
pub enum RngSource {
    /// Deterministic CSPRNG (ChaCha20) seeded from `seed`. Backs Math.random + crypto.getRandomValues.
    Seeded { seed: [u8; 32] },
    /// Granted OS entropy (`getrandom`). The ONLY OS-entropy call in the workspace.
    Os,
}

#[derive(Debug, Clone)]
pub enum EnvPolicy {
    /// Ungranted host env is invisible: every lookup returns `None` (I-6).
    Deny,
    /// Scoped allowlist (§15.1 — grants are scoped, not "all env"): only these names resolve to the
    /// real value; everything else is `None`. The ONLY `std::env::var` in the workspace.
    Allow(std::collections::BTreeSet<String>),
}

impl Default for HermeticConfig {
    fn default() -> Self {
        Self {
            clock: ClockSource::Virtual { origin_ms: MEOW_VIRTUAL_EPOCH_MS },
            rng: RngSource::Seeded { seed: MEOW_DEFAULT_SEED },
            env: EnvPolicy::Deny,
        }
    }
}

impl HermeticConfig {
    pub fn with_real_clock(self) -> Self;                       // grant: real clock
    pub fn with_os_rng(self) -> Self;                           // grant: OS entropy
    pub fn with_env_allow(self, names: impl IntoIterator<Item = String>) -> Self; // grant: scoped env
}
```

### A2 · Live per-run state — the single home of every host read (`crates/runtime/src/hermetic/state.rs`)

`HermeticState` is built once from `HermeticConfig` and stored in `OpState`. It holds the *live* virtual clock counter and the *seeded RNG instance* (so successive draws advance one deterministic stream). **This file is the sole location in the entire workspace where `SystemTime::now`, `Instant::now`, `getrandom`, and `std::env::var` may appear** (`principles-check.sh` P16 allowlists `/hermetic/`).

```rust
pub struct HermeticState {
    clock: ClockState,           // Virtual { origin_ms, advanced_ms } | Real { wall epoch + Instant base }
    rng: RngState,               // Seeded(rand_chacha::ChaCha20Rng) | Os
    env: EnvPolicy,
}

impl HermeticState {
    pub fn new(cfg: &HermeticConfig) -> Self;   // seeds ChaCha20Rng from the seed; captures Real bases once

    /// Wall-clock ms for `Date.now()` / `new Date()`. Virtual → origin + advanced. Real → SystemTime epoch ms.
    pub fn now_ms(&self) -> f64;
    /// Monotonic ms for `performance.now()`. Virtual → advanced counter. Real → Instant::elapsed since base.
    pub fn mono_ms(&self) -> f64;
    /// Advance the virtual clock (called by the timer queue when a timer fires; no-op under Real). I-6 hook.
    pub fn advance_virtual_ms(&mut self, delta_ms: f64);
    /// Fill `buf` with bytes. Seeded → next bytes of the ChaCha stream (deterministic). Os → getrandom.
    pub fn fill_random(&mut self, buf: &mut [u8]) -> Result<(), HermeticError>;
    /// Env lookup. Deny → None. Allow(set) → Some(value) iff name ∈ set and the host has it; else None.
    pub fn env_get(&self, name: &str) -> Option<String>;
}

#[derive(Debug, thiserror::Error)]
pub enum HermeticError {
    #[error("entropy source unavailable: {0}")]
    Entropy(String),   // only reachable under RngSource::Os; surfaces as a JS exception, never a panic (CRAFT)
}
```

Invariant: `now_ms`/`mono_ms`/`fill_random`/`env_get` are the only ways JS obtains time/entropy/env — no other op or global exposes a second path (the I-6 *single governed entry*, mirroring RT-002's single I/O entry).

### A3 · The ops + extension (`crates/runtime/src/hermetic/ops.rs`, `src/hermetic/mod.rs`)

```rust
#[deno_core::op2(fast)]
pub fn op_hermetic_now_ms(state: &mut deno_core::OpState) -> f64;     // Date.now / new Date()
#[deno_core::op2(fast)]
pub fn op_hermetic_mono_ms(state: &mut deno_core::OpState) -> f64;    // performance.now
#[deno_core::op2(fast)]
pub fn op_hermetic_random_fill(
    state: &mut deno_core::OpState,
    #[buffer] buf: &mut [u8],
) -> Result<(), crate::hermetic::HermeticError>;                       // crypto.getRandomValues + Math.random seed
#[deno_core::op2]
#[string]
pub fn op_hermetic_env_get(
    state: &mut deno_core::OpState,
    #[string] name: &str,
) -> Option<String>;                                                   // env reads

deno_core::extension!(
    meow_hermetic,
    ops = [op_hermetic_now_ms, op_hermetic_mono_ms, op_hermetic_random_fill, op_hermetic_env_get],
    esm_entry_point = "ext:meow_hermetic/hermetic.js",
    esm = [dir "src/hermetic/js", "hermetic.js"],
);
```

Each op borrows `HermeticState` out of `OpState` (stored by `install_hermetic`, A5). `op_hermetic_random_fill` and `op_hermetic_now_ms`/`mono_ms` take `&mut OpState` because the seeded RNG and the virtual counter mutate; no `unwrap` on any user-reachable line (CRAFT — runtime never panics on user input).

### A4 · Global shadowing — close the V8/Web nondeterminism holes (`crates/runtime/src/hermetic/js/hermetic.js`)

The bootstrap ESM rebinds the three JS-visible nondeterminism sources to the ops. This is the only place a program reads them, so default determinism is structural.

- **`Date`** — wrap, preserving full `Date` semantics; only the two clock-reading entry points are redirected:

```js
const Original = globalThis.Date;
function Date(...args) {
  if (!new.target) return new Original(op_hermetic_now_ms()).toString(); // Date() as function → current-time string
  return args.length === 0 ? new Original(op_hermetic_now_ms()) : new Original(...args);
}
Date.now = () => op_hermetic_now_ms();
Date.parse = Original.parse;            // pure → unchanged
Date.UTC = Original.UTC;                // pure → unchanged
Date.prototype = Original.prototype;    // instances keep the real prototype
Object.defineProperty(Date, Symbol.hasInstance, { value: (x) => x instanceof Original });
globalThis.Date = Date;                 // `new Date(2020, 0)` etc. (args) stay deterministic already
```

- **`Math.random`** — seed a small in-JS PRNG **once** from one `op_hermetic_random_fill` draw, then advance it in JS (no FFI per call — `Math.random` is hot; CRAFT *"don't allocate/cross the boundary gratuitously"*). Under the default `Seeded` source the bootstrap draw is identical every run ⇒ the whole `Math.random` sequence is reproducible.

```js
const _s = new Uint8Array(16); op_hermetic_random_fill(_s);   // deterministic under Seeded
// seed xorshift128+ from _s; Math.random = () => <next double in [0,1)>
```

- **`crypto.getRandomValues`** — route through `op_hermetic_random_fill` so granted-OS-vs-seeded applies. RT-004 owns the `crypto` global (`crypto.subtle`, Stateless Edge §8.1) and is **not** a dependency of this spec, so the bootstrap guards: `if (globalThis.crypto?.getRandomValues) { globalThis.crypto.getRandomValues = (b) => { op_hermetic_random_fill(b); return b; }; }`. The durable wiring is a `// === RT-006 ===` fence in RT-004's crypto bootstrap routing its entropy here (Operator notes — coordinate over IRC). `crypto.randomUUID` (if RT-004 ships it) MUST likewise consume this op.
- **`performance.now`** — if RT-004's `performance` exists, rebind to `op_hermetic_mono_ms` (same guard pattern).

### A5 · Runtime wiring (`crates/runtime/src/runtime.rs`, RT-001-owned — `// === RT-006 ===` fences)

### A6 · CLI grants (`crates/cli`, `// === RT-006 ===` fence)

`meow run <file>` is deterministic by default. Three honest grant flags flip individual sources (final capability CLI is SEC/P6 — Non-goals):

```
meow run app.ts                       # deterministic: virtual clock, seeded RNG, env invisible
meow run app.ts --allow-clock         # real wall-clock + monotonic time
meow run app.ts --allow-random        # OS entropy for crypto.getRandomValues + Math.random
meow run app.ts --allow-env=HOME,PATH # scoped: only HOME/PATH resolve; everything else is undefined
meow run app.ts --allow-env           # (bare) all host env — flagged loud as the widest grant
```

These build a `HermeticConfig` passed to `install_hermetic`; absence of a flag = the deterministic default. Help text states scope honestly (I-11): e.g. `--allow-clock  expose the real system clock (run is no longer reproducible)`.

### A7 · End-to-end observable behavior

- `meow run prog.ts` twice, where `prog.ts` prints `Date.now()`, `new Date().toISOString()`, `Math.random()`, and (if crypto present) `crypto.getRandomValues(new Uint8Array(8))` → **byte-identical stdout** across the two runs (I-6 happy path).
- A program reading an ungranted env var observes `undefined`/`None` (e.g. via `op_hermetic_env_get` exposed to a test global, A-test); with `--allow-env=FOO` and `FOO` set in the host, it observes the real value.
- `meow run prog.ts --allow-clock` twice with a wall-clock-printing program → stdout **differs** between runs (proves the grant actually changes the source; the gate is not a no-op).

## Non-goals

- **No capability ENFORCEMENT UI / unified grant model.** The persistent, per-package, suggested-grant capability system is **SEC-001 (P6)** + Trust Zones (P7) (I-8, CANON §15.3). RT-006 ships only the clock/rng/env *source selection* with deterministic defaults + three CLI flags. It claims no security property (I-11).
- **No sandbox against adversarial dynamic access.** Global shadowing closes the *ambient* path (`Date.now`, `Math.random`, `crypto.getRandomValues`). A determined program that retains a pre-shadow reference, reaches an unshadowed intrinsic, uses `eval`/`Function`, or calls native/FFI code can still read the true clock/entropy — that soundness is the tier-3 research track (CANON §24.3, SEC P7). Stated plainly; never called "blocked"/"sandboxed" (Operator notes, honest boundary).
- **No cross-machine bit-for-bit reproducibility of native deps.** Determinism is of *observable JS behavior* given identical inputs, not reproducible native builds (CANON §24.7 — "reproducible selection, not reproducible builds"). Wasm/native artifacts are pinned, not re-derived.
- **No timer subsystem.** `setTimeout`/timer scheduling is RT-004 (Stateless Edge, §8.1). RT-006 exposes `advance_virtual_ms` as the hook the timer queue calls; until RT-004 wires it the virtual clock is frozen at origin (honest boundary).
- **No `meow:env` / `process.env` surface.** A first-party env-reading API (`node-compat` `process.env`, a future `meow:env`) is out of scope; RT-006 provides the gated op those MUST consume. The `meow:*` public shape is RT-005/I-9.
- **No new parser/resolver/event loop.** Reuses RT-001's `JsRuntime` + RT-002's OpState/event loop. One isolate, one OpState (I-1, CRAFT).

## Interface

New module tree under the RT-001-owned `crates/runtime` (the `hermetic/` directory name is load-bearing: `principles-check.sh` P16 allowlists `/(host|hermetic)/` for host calls):

```
crates/runtime/
  Cargo.toml                     # + rand_chacha, rand_core, getrandom (all confined to src/hermetic/)
  src/
    runtime.rs                   # RT-001-owned; RT-006 adds install_hermetic + ext reg in `// === RT-006 ===` fences
    hermetic/
      mod.rs                     # pub mod config/state/ops; re-exports; `deno_core::extension!(meow_hermetic, …)`
      config.rs                  # HermeticConfig, ClockSource, RngSource, EnvPolicy, constants, Default
      state.rs                   # HermeticState, HermeticError — the SOLE home of SystemTime/Instant/getrandom/std::env
      ops.rs                     # op_hermetic_now_ms / mono_ms / random_fill / env_get
      js/hermetic.js             # global shadows: Date, Math.random, crypto.getRandomValues, performance.now
```

- **Rust API:** `HermeticConfig` (+ builders), `ClockSource`, `RngSource`, `EnvPolicy`, `HermeticState`, `HermeticError`; `MeowRuntime::install_hermetic`; `meow_hermetic` extension — exactly as A1–A5.
- **CLI surface:** `--allow-clock`, `--allow-random`, `--allow-env[=NAMES]` on `meow run` (A6). Default with no flags = deterministic.
- **JS-observable contract:** `Date`/`Date.now`/`Math.random` are deterministic by default; `crypto.getRandomValues`/`performance.now` deterministic when present; ungranted env reads return undefined.
- **Hermeticity invariant:** the only `SystemTime::now`/`Instant::now`/`getrandom`/`std::env::var` edges in the workspace are in `crates/runtime/src/hermetic/state.rs`, each behind a granted source (asserted by `principles-check.sh` P16 + the `determinism` gate).

## Implementation sketch

1. **`Cargo.toml`** — add `rand_chacha`, `rand_core` (for `SeedableRng`/`RngCore`), `getrandom` (OS source). All usages confined to `src/hermetic/state.rs`; declare via workspace pins where DIST-001 owns them, else add to `[workspace.dependencies]` first (coordinate with DIST). No feature flags.
2. **`config.rs`** — the enums + `Default` (deterministic) + builder methods + the two named constants.
3. **`state.rs`** — `HermeticState::new` seeds `ChaCha20Rng::from_seed(seed)` for `Seeded`, and for `Real`/`Os` captures the wall epoch + `Instant` base once. `now_ms`/`mono_ms`/`fill_random`/`env_get`/`advance_virtual_ms` per A2. This is the **only** file touching the host clock/entropy/env crates — keep it small and obviously the seam.
4. **`ops.rs` + `mod.rs`** — four ops borrowing `Rc<RefCell<HermeticState>>` from `OpState`; `extension!` macro with the esm bootstrap.
5. **`js/hermetic.js`** — the global shadows (A4). The `Date` wrapper is the delicate part: preserve `instanceof`, statics, and the function-call form; only the zero-arg / `now` paths read the virtual clock. Math.random seeded once. crypto/performance rebinds guarded by presence checks.
6. **`runtime.rs`** — two `// === RT-006 ===` fences (A5): `install_hermetic`, and the extension append **after** RT-004's globals so the shadows win. Coordinate with `RT001`/`RT002` over IRC.
7. **CLI** — `// === RT-006 ===` fence parsing the three flags → `HermeticConfig` → `install_hermetic` (A6). Default path passes `HermeticConfig::default()`.

Comment-marker fences for shared-file edits: **`// === RT-006 ===`** in `crates/runtime/src/runtime.rs`, `crates/cli` (run dispatch), and (deferred, when RT-004 lands) RT-004's crypto/performance bootstrap. Fences MUST be balanced (`principles-check.sh`).

`unsafe`: none introduced (CRAFT — `unsafe` only at the V8/FFI boundary; this layer is safe Rust over `rand_chacha`/`getrandom`). No `unwrap`/`expect` on any user-reachable path; `getrandom` failure → `HermeticError::Entropy` → JS exception.

## Tests required

Location `crates/runtime/tests/hermetic_*.rs` (+ `#[cfg(test)]` units in `state.rs`), run via `cargo test --workspace`. They prove I-6 behaviorally (CRAFT — assert behavior, not plumbing). A test-only extension exposes the four ops to JS where a public global doesn't exist yet (the `crypto`/`process.env` consumers are RT-004/P5).

- **`hermetic_reproducible_default`** — run a module that prints `Date.now()`, `new Date(0).toISOString()` is unchanged, `new Date().getTime()`, and a sequence of `Math.random()` values, twice under the default config; capture `op_print` bytes both times; assert **identical**. *Proves: deterministic-by-default observable behavior (I-6 happy path; the `determinism` gate's core claim at unit scope).*
- **`hermetic_seeded_rng_stream`** — assert `op_hermetic_random_fill` over the default `Seeded` source yields a fixed known byte prefix (golden), and that two fresh `HermeticState`s with the same seed produce the same stream while different seeds diverge. *Proves: randomness is seeded + reproducible, and the seed actually drives it.*
- **`hermetic_env_invisible_until_granted`** — with `EnvPolicy::Deny`, set a real host env var in the test, call `op_hermetic_env_get("MEOW_TEST_VAR")` from JS → `None`/`undefined`; with `EnvPolicy::Allow({"MEOW_TEST_VAR"})` → the real value; a *different* ungranted name under `Allow` still → `None` (scoped, not all-or-nothing). *Proves: ungranted host env is invisible; grants are scoped (I-6, §15.1).*
- **`hermetic_real_clock_changes_behavior`** — `ClockSource::Real`: two reads of `op_hermetic_now_ms` separated by a real sleep differ and track the system clock; AND running the same clock-printing program twice under `--allow-clock` yields differing output (vs identical under default). *Proves: the grant flips the source — the gate is not a no-op (the assignment's "proves the gate" check).*
- **`hermetic_date_wrapper_fidelity`** — `new Date(2020, 0, 1)` (args) is unchanged by the wrapper; `x instanceof Date` holds for both wrapped and arg-constructed instances; `Date.parse`/`Date.UTC` behave as native; only the zero-arg / `Date.now` paths read the virtual clock. *Proves: shadowing preserves `Date` semantics (no correctness regression while gating the clock).*
- **`hermetic_no_panic_on_entropy_failure`** — inject an `Os` source whose entropy call errors; assert `op_hermetic_random_fill` returns a typed `Err` surfaced as a JS exception, no panic/abort. *Proves: CRAFT no-panic-on-user-input.*
- **`hermetic_floor_tripwire`** — assert (or reference `principles-check.sh` P16) that `crates/runtime/src` contains no `SystemTime::now`/`Instant::now`/`getrandom`/`std::env::var`/`rand::` **outside** `src/hermetic/`. *Proves: the single-seam invariant structurally (the I-6 floor).*

**Applicable gates.** Governing invariant **I-6 → `determinism`** (GATES.md): the adversarial form runs the same project across two machines + with a *scrambled host env/clock/randomness* and asserts identical observable output + invisible ungranted host state — RT-006 stands up exactly that mechanism and proves it at unit scope. **`honesty` (I-11)** applies to this surface: the audit checks that no code/comment/help-string calls the shadowing a "sandbox" or claims it stops adversarial access — it is hermeticity-by-default + honest grants, with the residual named (CANON §24.3). The full two-machine `determinism` proof is a P1 exit gate over `meow run`; RT-006 is its substrate.

## Rollout

- **Sequencing:** depends on RT-001 (the `JsRuntime` + bootstrap/extension seam + `meow run`) and RT-002 (the OpState-injected policy pattern this extends). Lands in P1 (Wave 2). Coordinates with RT-004 (crypto/performance shadows) and is consumed by the test runner (TEST/P6) and SEC-001 (P6, which populates `HermeticConfig` from the unified grant model).
- **Flag:** behavior-changing for any program that reads the clock/randomness — under RT-006 a bare `meow run` becomes deterministic. This is the intended I-6 behavior, not a regression; the three `--allow-*` flags restore real sources. No persisted config.
- **Reversibility:** fully reversible within scope. Revert = delete `crates/runtime/src/hermetic/`, the `// === RT-006 ===` fences in `runtime.rs` + `crates/cli`, and the three `Cargo.toml` deps. No migration, no persisted state, no schema. With the module gone the runtime returns to RT-001/RT-002 behavior (raw V8 `Date`/`Math.random`).

## Operator notes

- **Honest boundary — what this does and does NOT stop (I-11, flag for the honesty gate).** RT-006 makes the runtime hermetic *by default* against **ambient** nondeterminism: the JS program does not see the host clock/entropy/env unless granted. It is **not** a sandbox against *adversarial* code — a program that stashes a pre-shadow `Date` reference, reaches an unshadowed intrinsic, or uses `eval`/`Function`/native FFI can still read the true host. That soundness is tier-3 (CANON §24.3, SEC P7). No string/doc/comment in this change may call the shadowing "sandboxed" or "blocked"; the correct words are "hermetic by default" + "defense-in-depth," with the residual pointed at `CANON §24.3`.
- **Assumption (design fork — log to `decisions.json`):** clock/rng/env are modelled as **source selection (deterministic substitute ↔ real)**, deliberately *not* RT-002's binary `CapabilityCheck` allow/deny. Rationale: denying a clock/RNG outright breaks ordinary programs; the I-6-correct shape is a deterministic stand-in by default, real on grant. RT-002's `CapabilityCheck` stays the model for *resource* access (fs/net, where deny is correct). P6 `SEC-001` composes both slices (`HermeticConfig` + `CapabilityCheck`) into the one grant model — they are two slices of one capability set, not two competing mechanisms.
- **Assumption:** the default seed is the fixed constant `MEOW_DEFAULT_SEED = [0u8;32]` and the virtual epoch is `MEOW_VIRTUAL_EPOCH_MS` (2026-06-07T00:00:00Z). These are part of the reproducibility contract — changing them changes default output and is a deliberate, documented act, never incidental.
- **Assumption:** the virtual clock is **frozen at origin** until RT-004's timer subsystem calls `advance_virtual_ms` on timer firing. A program measuring elapsed wall-time under the default clock sees zero progression — correct for determinism, and exactly the behavior the test runner wants (CANON §16).
