## Motivation

PKG-001 landed the two passive foundations — the `meow.lock.jsonl` schema and the content-addressed `Cache` — but nothing populates them. LOAD-003 landed THE resolver, but it reads an **already-populated** cache + lockfile (LOAD-003 Non-goals: "Install / registry fetch / lockfile generation / archive population — **PKG-002 (P2)**"). Between them is a hole: today a project's only dependencies are whatever a test hand-`store`d into the cache, and `meow run` derives its direct-dependency map from a P1 **stand-in** (`root_deps_from_lockfile`, LOAD-001) that treats *every* lockfile line as a root and breaks the moment a real transitive graph (with multiple versions) exists.

PKG-002 is **the command that makes dependencies real**: `meow install` reads the project's declared deps from `meow.config.ts` (the single source, ADR-8 / CFG), resolves them against the npm registry, downloads + integrity-checks + content-addresses every tarball into the cache, writes the complete deterministic `meow.lock.jsonl`, and replaces the run-path stand-in so the runtime (and, via I-5, the LSP) resolve the *installed* graph. This is the spine of P2 (CANON §12.1 cache, §12.2 install modes, §12.3 lockfile; ADR-4 PnP-by-default): after this, **a project installs and runs pure-ESM dependencies with no `node_modules`, and the same lockfile reproduces the same graph** (the P2 exit condition).

Tracing: `plan_ref` → PLAN.md *Build sequence · P2 Packages & Resolution* + *later-phases* `PKG-002 install + integrity`. `constitution_ref` → **I-7** [`lockfile-integrity`] (content-hash pin + integrity check; strictly-sorted lockfile — CANON §12.1/§12.3), **I-5** [`resolver-parity`] (install writes **no** `node_modules`; feeds the one resolver — ADR-4), **I-6** [`determinism`] (same inputs ⇒ byte-identical lockfile — the core bet, §1), **I-11** [`honesty`] (the sha512↔sha256 model, the node-semver coverage gap, and advisory-only provenance are stated truthfully, never overclaimed — §24).

## Acceptance criteria

Concrete, checkable Rust. The resolution engine lives in `crates/pkg` and is **network-free** — it depends only on a `RegistrySource` trait, so unit tests inject an in-memory fixture (deterministic, no network/clock) and the binary edge injects the real HTTPS client; `meow-pkg` gains **no** network/TLS dependency (I-10 footprint). Every reachable failure is a typed `thiserror` error; no path `unwrap`/`panic!`s on registry bytes, a malformed manifest, or a corrupt download (CRAFT Part B). Ambiguity / a tampered download is an honest typed error, never a silent wrong resolution (I-11).

### A1 — Declared deps live in the config (fenced edit to `crates/config/src/schema.rs`)

The project's *desired* direct dependencies are the single human-edited source (ADR-8, I-1). Add a `dependencies` map to `MeowConfig` behind a `// === PKG-002 ===` fence (CFG owns the file — P5 comment-marker concurrency, exactly as CFG-002 added `publish`):

```rust
// === PKG-002 ===
/// Direct dependencies: package name → requirement (a semver range like `"^5.0.0"`
/// or a dist-tag like `"latest"`). The SINGLE declared source `meow install`
/// resolves (CANON §12, §18); the lockfile pins the exact transitive graph, this
/// map is the human-edited intent. `BTreeMap` ⇒ key-sorted ⇒ byte-stable config.
#[serde(default)]
pub dependencies: std::collections::BTreeMap<String, String>,
// === /PKG-002 ===
```

An absent `dependencies` key ⇒ empty map (a project with no deps), which `meow install` resolves to an empty lockfile. Values are raw strings here (a config may carry a range *or* a tag); they are parsed into a typed `DepSpec` (A2) at resolution.

### A2 — `RegistrySource` seam + npm metadata model (`crates/pkg/src/registry.rs`, new)

The seam between resolution and "where bytes come from". The engine depends ONLY on this trait:

```rust
use std::collections::BTreeMap;
use serde::Deserialize;
use crate::{ContentHash, PackageName, Version, VersionReq};

/// Where package metadata + bytes come from. The resolver holds a `&dyn RegistrySource`,
/// so tests inject `FixtureRegistry` and the CLI injects `NpmRegistry`. No network code
/// lives in `meow-pkg` — the real HTTPS impl is at the binary edge (A8).
pub trait RegistrySource {
    /// The registry's package document (npm: `GET <registry>/<name>` → JSON).
    fn fetch_metadata(&self, name: &PackageName) -> Result<PackageMetadata, RegistryError>;
    /// The exact, verbatim tarball bytes for one version (npm: `GET <dist.tarball>`).
    /// Returned bytes are the gzip-tar archive LOAD-003's `PackageFs::from_archive`
    /// already decodes — the caller verifies + content-addresses them, the source
    /// never writes the cache.
    fn fetch_tarball(&self, name: &PackageName, version: &Version) -> Result<Vec<u8>, RegistryError>;
}

/// The subset of an npm package document resolution consults. Unknown keys are
/// ignored (forward-compatible); deserialized straight from the registry JSON.
#[derive(Debug, Clone, Deserialize)]
pub struct PackageMetadata {
    /// `dist-tags` (e.g. `latest` → "5.0.0"); values validated as exact `Version`s.
    #[serde(rename = "dist-tags", default)]
    pub dist_tags: BTreeMap<String, Version>,
    /// `versions.<v>` → that version's resolution-relevant manifest fields.
    #[serde(default)]
    pub versions: BTreeMap<Version, VersionMetadata>,
}

/// One published version's manifest subset.
#[derive(Debug, Clone, Deserialize)]
pub struct VersionMetadata {
    /// Runtime deps: name → raw requirement string (range or tag). Absent ⇒ empty.
    /// Raw `String` (not `VersionReq`) so a node-semver form the `semver` crate can't
    /// parse surfaces as a typed `UnsupportedRange` at resolution, not a deserialize
    /// failure of the whole document (I-11 honest boundary, A4).
    #[serde(default)]
    pub dependencies: BTreeMap<PackageName, String>,
    /// `dist` — tarball URL + publisher integrity.
    pub dist: DistInfo,
}

#[derive(Debug, Clone, Deserialize)]
pub struct DistInfo {
    /// Absolute tarball URL (npm: `https://registry.npmjs.org/<name>/-/<base>-<v>.tgz`).
    pub tarball: String,
    /// Publisher integrity, an SRI string — npm emits **sha512** (`sha512-<base64>`).
    /// The SUPPLY-CHAIN check, verified at download (A4); NOT the meow cache key.
    pub integrity: String,
    /// Legacy sha1 hex (`shasum`). Recorded by the registry; meow ignores it (sha1 is
    /// broken) — a package whose only integrity is sha1 is `UnsupportedIntegrity` (A4).
    #[serde(default)]
    pub shasum: Option<String>,
}

/// A dependency requirement: a semver range (the `semver` crate's grammar) or a
/// dist-tag. `parse` never fails — a string the `semver` crate rejects becomes `Tag`,
/// which resolves against `dist-tags` or, failing that, errors honestly (A3/A4).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum DepSpec {
    Range(VersionReq),
    Tag(String),
}

impl DepSpec {
    pub fn parse(s: &str) -> DepSpec {
        match VersionReq::parse(s) {
            Ok(req) => DepSpec::Range(req),
            Err(_) => DepSpec::Tag(s.to_owned()),
        }
    }
}

#[derive(thiserror::Error, Debug)]
pub enum RegistryError {
    #[error("registry request for {name} failed: {reason}")]
    Fetch { name: String, reason: String },
    #[error("registry returned HTTP {status} for {url}")]
    Status { url: String, status: u16 },
    #[error("malformed registry metadata for {name}: {reason}")]
    Metadata { name: String, reason: String },
}
```

`BTreeMap<Version, VersionMetadata>` keys deserialize via `Version`'s string `Deserialize` (validated semver), so a registry document with a garbage version key is a typed `RegistryError::Metadata`, never a panic.

### A3 — Resolution algorithm (`crates/pkg/src/install.rs`, new)

```rust
use std::collections::{BTreeMap, BTreeSet, VecDeque};
use crate::{Cache, ContentHash, Lockfile, LockEntry, PackageName, RegistryProvenance, Version, VersionReq};
use crate::registry::{DepSpec, PackageMetadata, RegistrySource};

/// Resolves a project's direct deps into a complete pinned graph and populates the cache.
pub struct Installer<'a> {
    source: &'a dyn RegistrySource,
    cache: &'a Cache,
    /// Recorded as provenance on every `LockEntry` (CANON §15.4 — advisory at P2, A7).
    registry_url: String,
    /// The meow runtime-version constraint stamped on every entry (§12.3, §26.3). Passed
    /// in (the CLI derives `^MAJOR.MINOR` from the running binary), so a test fixes it ⇒
    /// the lockfile is a pure function of `(direct, registry answers)` ⇒ byte-stable (I-6).
    meow_req: VersionReq,
}

impl<'a> Installer<'a> {
    pub fn new(
        source: &'a dyn RegistrySource,
        cache: &'a Cache,
        registry_url: impl Into<String>,
        meow_req: VersionReq,
    ) -> Installer<'a>;

    /// Resolve `direct` to a complete graph: download, **verify**, content-address every
    /// package into the cache, and return the lockfile. Pure w.r.t. discovery order — the
    /// returned `Lockfile` is a function of the resolved SET, so `to_canonical_string()`
    /// is byte-identical regardless of insertion order (I-6).
    pub fn resolve(&self, direct: &BTreeMap<PackageName, DepSpec>) -> Result<Lockfile, InstallError>;
}
```

`resolve` (deterministic):

1. **Metadata memo** `BTreeMap<PackageName, PackageMetadata>`; fetch each name at most once.
2. **Select** the direct versions: for each `(name, spec)` in `direct`, `select_version(meta(name), spec)` → exact `Version`; enqueue the exact `(name, version)` on a worklist; record nothing else (roots are re-derived later, A6).
3. **Worklist** (`VecDeque<(PackageName, Version)>`, exact pairs), `done: BTreeSet<(PackageName, Version)>`:
   - Pop `(name, version)`; if `done` contains it, continue (dedup; multi-version is inherent in the key).
   - `vmeta = meta(name).versions.get(&version)` (missing ⇒ `InstallError::MissingVersion`).
   - For each `(dep, raw)` in `vmeta.dependencies`: `dep_ver = select_version(meta(dep), DepSpec::parse(raw))`; record `deps_map[dep] = dep_ver`; enqueue `(dep, dep_ver)`.
   - `bytes = source.fetch_tarball(&name, &version)?`.
   - **Integrity**: `verify_npm_integrity(&vmeta.dist.integrity, &bytes)?` (A4) — on mismatch the bytes are dropped and **nothing is cached**.
   - `integrity = cache.store(&bytes)?` (the meow **sha256** content hash + I-7 anchor).
   - `lockfile.upsert(LockEntry { name, version, integrity, dependencies: deps_map, registry: RegistryProvenance::new(&self.registry_url), capabilities: vec![], wasm: vec![], meow: self.meow_req.clone() })`; `done.insert(key)`.
4. Return the lockfile.

`select_version(meta, spec) -> Result<Version, InstallError>`:
- `DepSpec::Range(req)`: among `meta.versions` keys, keep those a re-parsed `semver::VersionReq` (from `req.as_str()`) matches, parsing each candidate as `semver::Version`; return the **maximum** (semver order). Pre-releases are excluded unless the requirement names one (the `semver` crate's matching rule). None ⇒ `InstallError::NoMatchingVersion`.
- `DepSpec::Tag(tag)`: `meta.dist_tags.get(tag)` → that version; else ⇒ `InstallError::UnsupportedRange` (an unknown tag, or a node-semver form the `semver` crate cannot parse — honest, A4).

The maximum-satisfying choice makes the resolved set a deterministic function of `(direct, registry answers)`; combined with PKG-001's order-independent `to_canonical_string`, the lockfile bytes are stable across runs and machines (I-6).

### A4 — Integrity model: npm sha512 verify-on-download, meow sha256 cache key (the resolved fork)

```rust
/// Verify downloaded bytes against the publisher SRI. npm emits **sha512**
/// (`sha512-<base64>`, possibly several space-separated hashes — the first sha512
/// is used). This is the SUPPLY-CHAIN check (the bytes ARE what the registry
/// published); it does NOT become the cache key. `sha2::Sha512` is already in
/// `meow-pkg`'s dep set (no new dep, I-10).
fn verify_npm_integrity(sri: &str, bytes: &[u8]) -> Result<(), InstallError>;
```

The two hashes have **two distinct roles**:

| hash | who computes it | role | persisted? |
|---|---|---|---|
| npm `dist.integrity` (**sha512** SRI) | the publisher | supply-chain check at download — confirms the bytes are exactly what npm published | no (verified-then-discarded at P2) |
| meow `ContentHash` (**sha256**, PKG-001) | `Cache::store(bytes)` | the cache key + `LockEntry.integrity` + the I-7 anchor the cache re-verifies on every read | **yes** (the lockfile pin) |

Why sha256 is the lockfile/cache key, not the npm sha512: PKG-001 deliberately froze `HashAlgo = Sha256` and the cache layout `<algo>/<hex>` ("No second hash algorithm" — PKG-001 Operator notes). Reusing npm's sha512 as the key would force a `HashAlgo::Sha512` + cache-layout change PKG-001 explicitly deferred. Verifying the sha512 **on download** preserves the supply-chain provenance without that churn: the bytes are proven against the publisher, then meow re-addresses them under its own content hash. On mismatch:

```rust
#[error("integrity check FAILED for {name}@{version}: registry published {expected}, downloaded bytes hash to {got}")]
IntegrityMismatch { name: String, version: String, expected: String, got: String },
#[error("package {name}@{version} has no usable sha512 integrity (only sha1/`shasum`); meow refuses sha1")]
UnsupportedIntegrity { name: String, version: String },
```

`InstallError` (full):

```rust
#[derive(thiserror::Error, Debug)]
pub enum InstallError {
    #[error(transparent)] Registry(#[from] crate::registry::RegistryError),
    #[error(transparent)] Cache(#[from] crate::CacheError),
    #[error("no published version of {name} satisfies {req}")]
    NoMatchingVersion { name: String, req: String },
    #[error("unsupported requirement {req:?} for {name}: meow resolves the `semver` crate's range grammar + dist-tags; node-semver `||`/hyphen/x-range forms are not yet supported")]
    UnsupportedRange { name: String, req: String },
    #[error("registry metadata for {name} is missing version {version}")]
    MissingVersion { name: String, version: String },
    UnsupportedIntegrity { name: String, version: String },
    IntegrityMismatch { name: String, version: String, expected: String, got: String },
}
```

### A6 — Replace the run-path `root_deps` stand-in (`crates/pkg/src/install.rs` + `crates/cli/src/cli.rs`)

LOAD-001's `root_deps_from_lockfile` (which treats every lockfile line as a root and errors on multi-version) is **removed** (clean cutover). Roots are re-derived from the config + the lockfile:

```rust
/// Re-derive the project's direct-dependency pins for the runtime/LSP `Resolver`
/// from the declared `direct` deps + the lockfile. For each declared dep, pick the
/// lockfile entry whose version is the MAX satisfying the spec — which is exactly the
/// version `meow install` pinned as the direct resolution (lockfile versions ⊆ the
/// registry's, so max-in-lockfile == the direct selection). Pure, deterministic; no
/// network — the run path never touches the registry (I-5/I-6).
pub fn resolve_roots(
    direct: &BTreeMap<PackageName, DepSpec>,
    lockfile: &Lockfile,
) -> Result<BTreeMap<PackageName, Version>, RootResolveError>;

#[derive(thiserror::Error, Debug)]
pub enum RootResolveError {
    #[error("dependency {name} is declared but not in meow.lock.jsonl — run `meow install`")]
    NotInLockfile { name: String },
    #[error("unsupported requirement {req:?} for {name} (see InstallError::UnsupportedRange)")]
    UnsupportedRange { name: String, req: String },
}
```

`cmd_run` (fenced `// === PKG-002 ===`, replacing the LOAD-001 stand-in call): load `MeowConfig` from the project root; build `direct` from `cfg.dependencies`; `root_deps = meow_pkg::resolve_roots(&direct, &lockfile)?`. Robustness: a `ConfigError::NotFound` ⇒ empty `direct` (local-only run, as today); `ConfigError::TsNotSupported` ⇒ empty `direct` only when the lockfile is empty, else an honest error (deps were installed but roots can't be derived until RT-001 evaluates `meow.config.ts` — same boundary CFG-001/CFG-002 carry).

### A7 — CLI: `meow install [name[@range]] [--mode]` (`crates/cli`)

`InstallArgs` gains an optional positional (fenced); the dispatch arm flips from honest stub to real:

```rust
// in InstallArgs, // === PKG-002 ===
/// Optional packages to add then install, e.g. `lodash` or `is-odd@^3`. None ⇒
/// install everything declared in meow.config.
#[arg(value_name = "PKG")]
pub packages: Vec<String>,
```

`cmd_install`:
- `--mode pnp` (the default, ADR-4) is the only mode PKG-002 implements: resolve → download → verify → cache → write `meow.lock.jsonl`. **No `node_modules` is created** (I-5). `--mode materialize|vfs|vendor` print an honest single-line "lands in PKG-004 (P2)" to stderr and exit `EXIT_UNIMPLEMENTED` — no fake success (CRAFT); PKG-004 flips those arms in the same phase.
- For each `name[@range]` positional: parse (`name`, `range`); a bare name resolves `latest` then records `^<resolved>` in the config (npm convention); persist via the CFG seam (A9). Then run install.
- Install: resolve project root (cwd) + `host_home()` for `Cache::in_home`; `MeowConfig::load`; build `direct: BTreeMap<PackageName, DepSpec>` from `cfg.dependencies`; construct `NpmRegistry` (A8) + `Installer::new(&npm, &cache, "https://registry.npmjs.org", meow_req)` where `meow_req = VersionReq::parse("^MAJOR.MINOR")` from `env!("CARGO_PKG_VERSION")`; `lockfile = installer.resolve(&direct)?`; `lockfile.write_canonical(&root.join("meow.lock.jsonl"))?`.
- Regenerate shadows: `meow install` is an ADR-8 §18.1 regen trigger — call `meow_config::generate_root_package_json(&cfg, &root)` (CFG-002) after a successful install.
- Print a summary: `installed <N> packages → meow.lock.jsonl (no node_modules)`.

### A8 — `NpmRegistry` HTTPS impl (`crates/cli`, the binary edge)

```rust
// === PKG-002 ===
/// The production `RegistrySource`: HTTPS to an npm-protocol registry. Lives at the
/// binary edge so `meow-pkg` stays network-free (I-10). Network is a CLI-edge
/// privilege (like `host_home`), not ambient subsystem access (P16/I-6).
pub struct NpmRegistry { base: String }
impl NpmRegistry { pub fn npm() -> NpmRegistry; /* base = https://registry.npmjs.org */ }
impl meow_pkg::RegistrySource for NpmRegistry {
    fn fetch_metadata(&self, name) -> ... { /* GET {base}/{name}; scoped @s/p → @s%2fp */ }
    fn fetch_tarball(&self, name, version) -> ... { /* GET {base}/{name}/-/{base}-{version}.tgz */ }
}
```

`fetch_metadata` GETs `<base>/<name>` (scoped names URL-encode the `/` as `%2f`), parses the body as `PackageMetadata`. `fetch_tarball` reconstructs the standard npm tarball URL (`<base>/<name>/-/<unscoped-name>-<version>.tgz`; the `/` in scoped names is **not** encoded in the tarball path) and returns the bytes. HTTP client: a small blocking client with rustls (A-PKG002-4 in Operator notes); the installer is a batch CLI op, so blocking I/O is simpler than driving tokio for downloads.

### Behaviors (the acceptance bar)

- `meow install` with `dependencies: { "escape-string-regexp": "^5" }` and no other config: writes `meow.lock.jsonl` with one entry (`integrity` = a `sha256-…` SRI, `dependencies: {}`, `registry: {registry:"https://registry.npmjs.org"}`), populates `~/.meow/cache`, and creates **no `node_modules`** directory anywhere.
- A package with transitive deps (`p-limit@^5` → `yocto-queue`): the lockfile pins both, the parent's `dependencies` map names the child's exact version, both archives are cached, and `Lockfile::get(parent).dependencies` is what LOAD-003 walks.
- Two packages requiring different majors of a shared dep each get their own `(name, version)` lockfile entry (multi-version) — no flattening.
- A download whose bytes do not match the publisher sha512 ⇒ `InstallError::IntegrityMismatch`, **nothing cached**, non-zero exit, no panic.
- A requirement the `semver` crate cannot parse and is not a dist-tag ⇒ `InstallError::UnsupportedRange` (honest), not a silent mis-resolution.
- Running `meow install` twice (deleting the lockfile between) ⇒ byte-identical `meow.lock.jsonl`; the second run is a cache hit (no re-download needed) yet produces identical bytes.
- After install, `meow run main.ts` (importing the installed package) resolves it through LOAD-003 to a `meow-cache://…` URL with no `node_modules` consulted, using roots derived from config + lockfile (A6).

## Non-goals

- **PnP in-memory loading itself** — **PKG-003 (P2)**. PKG-002 *populates* the cache + lockfile and supplies `resolve_roots`; how PKG-003 wires the full installed tree into LOAD-003's `Resolver` (a new data source beyond `root_deps`) is PKG-003's contract (PKG-003/PKG-004 coordinate per ADR-4). PKG-002 does not change `Resolver::new`.
- **`--materialize` / `--vfs` / `--vendor`** — **PKG-004 (P2)**. PKG-002 implements `pnp` only and stubs the others honestly (A7); PKG-004 ships in the same phase (ADR-4).
- **Provenance *verification*** (Sigstore signatures, OSV) — **SEC-002 (P6)**. PKG-002 *records* registry provenance (the registry URL, per PKG-001's `RegistryProvenance`) and *verifies the publisher sha512 at download*, but does not verify signatures, mirror OSV, or persist the sha512 (CANON §15.4 is advisory and later). "Provenance" in any PKG-002 surface means *recorded*, never *attested* (I-11).
- **`add`/`remove` as separate verbs beyond reusing this engine** — `meow install <pkg>` covers the add path (A7). Wiring the standalone `meow add`/`meow remove` arms is a thin reuse of `add_dependency`/`remove_dependency` + `Installer` and may ride this spec or an immediate follow-up; PKG-002's acceptance bar is `meow install`.
- **A node-semver-faithful range engine** — PKG-002 uses the already-pinned `semver` crate (PKG-001). node-semver `||` unions, hyphen ranges, `x`-ranges, and "bare version == exact" differ; these are documented honest gaps (A4, Operator notes), surfaced as typed errors, not silently mis-resolved.
- **Registry auth / private registries / scopes-to-registries** — out of scope (default public `registry.npmjs.org` only). No `.npmrc`, tokens, or per-scope registry mapping.
- **Install/postinstall lifecycle scripts, native-binary build, git/file/url specifiers** — out (pure-ESM npm-registry tarballs only at P2).
- **Lockfile *update* policy** (`--frozen`, dedup minimization, partial updates) — PKG-002 always resolves the full graph from the declared deps and writes the complete lockfile.

## Interface

- **`meow-pkg` adds** (`crates/pkg/src/{registry.rs,install.rs}` + `lib.rs` re-exports): `RegistrySource`, `PackageMetadata`, `VersionMetadata`, `DistInfo`, `DepSpec`, `RegistryError`, `FixtureRegistry`, `Installer`, `InstallError`, `resolve_roots`, `RootResolveError`. **No new external dep** (reuses `serde`/`serde_json`/`semver`/`sha2`(+Sha512)/`thiserror` already pinned — I-10).
- **`meow-pkg` consumes (do not redefine):** PKG-001 `Cache::{in_home,store,read,contains}`, `Lockfile::{new,upsert,get,iter,write_canonical,to_canonical_string}`, `LockEntry`, `RegistryProvenance::new`, `ContentHash`, `PackageName`, `Version`, `VersionReq`.
- **`meow-config` adds** (fenced): `MeowConfig.dependencies` field; `add_dependency`/`remove_dependency` (A9).
- **CLI surface:** `meow install [PKG…] [--mode pnp|vfs|materialize|vendor]` (default `pnp`); `pnp` real, others honest-stub. The `install` (and `add`/`remove`) `Command::landing` rows flip P2→real; `why-dep` stays a stub.
- **On-disk contract:** `meow.lock.jsonl` at the project root (PKG-001 canonical form) is the *output*; `~/.meow/cache/sha256/<hex>` holds verbatim gzip-tar bytes (the exact archive LOAD-003 decodes). **No `node_modules`** is ever written (I-5).
- **Feeds LOAD-003:** `LockEntry.integrity` (sha256) addresses the cached tarball; `Lockfile::get(name,version).{integrity,dependencies}` is what `Resolver` walks; `resolve_roots` supplies `root_deps`. The PKG-002↔LOAD-003 archive contract (flagged in LOAD-003 Operator note #1) is **resolved**: `LockEntry.integrity` addresses the **whole gzip-tar tarball** (`package/`-prefixed), exactly `PackageFs::from_archive`'s input.

## Implementation sketch

New, network-free engine in `crates/pkg`; the network + CLI wiring at the binary edge. Files: `crates/pkg/src/registry.rs` (trait, model, `DepSpec`, `FixtureRegistry`, `RegistryError`), `crates/pkg/src/install.rs` (`Installer`, `select_version`, `verify_npm_integrity`, `resolve_roots`, `InstallError`, `RootResolveError`), `crates/pkg/src/lib.rs` (module wiring + re-exports), `crates/pkg/tests/install_corpus.rs` (new).

Shared-file edits — comment-marker fences (`// === PKG-002 ===`):
- `crates/config/src/schema.rs` — the `dependencies` field on `MeowConfig` (A1).
- `crates/config/src/{package.rs or deps.rs}` + `lib.rs` — `add_dependency`/`remove_dependency` (A9), persisting to `meow.config.json` (pre-RT-001 boundary; honest error when only `meow.config.ts` exists — A9).
- `crates/cli/src/cli.rs` — `InstallArgs.packages` (A7); the `Command::Install`/`Add`/`Remove` dispatch arms → `cmd_install`/`cmd_add`/`cmd_remove`; `cmd_install` + `NpmRegistry` (A7/A8); **remove `root_deps_from_lockfile`** and add `root_deps` derivation via `MeowConfig::load` + `meow_pkg::resolve_roots` in `cmd_run` (A6).
- `Cargo.toml` (workspace) — `# === PKG-002 ===` pin for the HTTPS client (A-PKG002-4), consumed **only** by `crates/cli`.
- `crates/cli/Cargo.toml` — the HTTP client under a `# === PKG-002 ===` dep.

Determinism discipline: `Installer::resolve` returns a `Lockfile` whose bytes depend only on the resolved set (BTreeMap/BTreeSet + max-satisfying selection + a fixed `meow_req`); never read the clock/env/rng (P16) — the only inputs are the deps and the `RegistrySource`'s answers. CRAFT: no `unwrap`/`panic!` on registry bytes; borrow `&[u8]`/`&str`; the tarball bytes move once (`fetch_tarball` → verify → `store`), no gratuitous clone.

## Tests required

`crates/pkg/tests/install_corpus.rs` (integration, `FixtureRegistry` + a `Cache::with_root(tempdir)`) + unit tests in `install.rs`/`registry.rs`; a real-network integration test in `crates/cli/tests/` (`assert_cmd`) backing the reality-check. Proves **I-7** [`lockfile-integrity`], **I-6** [`determinism`], **I-5** [`resolver-parity`], **I-11** [`honesty`].

- **Happy path (zero-dep)** (I-7): publish `A@1.0.0`; `resolve({A: ^1})` ⇒ lockfile has one entry, `integrity` is a `sha256-…` SRI, `dependencies == {}`, `registry.registry == "https://registry.npmjs.org"`; `cache.contains(integrity)` and `cache.read(integrity) == bytes`.
- **Transitive + exact-version recording** (I-7): `A@1.0.0` deps `B@^1`; `B@1.2.0`; `resolve({A: ^1})` ⇒ both entries, `get(A).dependencies == {B: 1.2.0}`, both cached.
- **Multi-version** (I-7): `A` deps `C@^1`(→1.5.0), `D` deps `C@^2`(→2.1.0); `resolve({A:^1, D:^1})` ⇒ `C@1.5.0` **and** `C@2.1.0` both present.
- **Version selection** (property where cheap): max-satisfying (`^1.0` over {1.0.0,1.1.0,1.2.0} ⇒ 1.2.0; `~1.1` ⇒ 1.1.0); pre-releases excluded; a `latest` dist-tag resolves via `dist_tags`.
- **Determinism / byte-identical lockfile** (I-6): `resolve` twice on the same fixture ⇒ identical `to_canonical_string()`; resolving with the **direct map in shuffled iteration order** ⇒ identical bytes; the written `meow.lock.jsonl` is strictly sorted (PKG-001 `read` round-trips it).
- **Integrity-mismatch rejection (no panic)** (I-7, red-team): `publish_with_integrity(A, …, "sha512-<wrong>")` (or bytes that don't match the published SRI) ⇒ `InstallError::IntegrityMismatch`; assert `!cache.contains(...)` (nothing stored) and the call returns `Err`, never panics. Also: a package whose `dist` has only `shasum` (sha1) ⇒ `UnsupportedIntegrity`.
- **No matching / unsupported (honest, no panic)** (I-11): `{A: ^9}` with only 1.x ⇒ `NoMatchingVersion`; `{A: "1 || 2"}` (node-semver union the `semver` crate rejects) ⇒ `UnsupportedRange`; garbage registry JSON ⇒ `RegistryError::Metadata`.
- **`resolve_roots`** (I-5): lockfile with `A@1.2.0` plus a transitive `A@1.0.0`, config `{A: ^1}` ⇒ root `A → 1.2.0` (max satisfying = the direct pin); a config dep absent from the lockfile ⇒ `RootResolveError::NotInLockfile`.
- **Reality-check — REAL install + run with no `node_modules`** (I-5/I-7/I-6, the gate evidence): in a tempdir with a `meow.config.json` declaring `dependencies: {"escape-string-regexp":"^5"}`, run `meow install` against the live registry ⇒ `meow.lock.jsonl` written (one entry), `~/.meow/cache` populated, **no `node_modules` directory exists**; then `meow run main.ts` importing the package executes and the imported function's behavior is observed (resolved via `meow-cache://…`). Repeat with `p-limit@^5` to exercise a real transitive (`yocto-queue`). Re-run `meow install` (lockfile deleted) ⇒ **byte-identical** `meow.lock.jsonl`. Evidence: `harness/reality-checks/lockfile-integrity-<N>.md` (+ cross-referenced by `resolver-parity-<N>.md`).

GATES: `lockfile-integrity` (I-7 — integrity verify + tamper refusal + strict-sorted lockfile), `determinism` (I-6 — byte-identical lockfile), `resolver-parity` (I-5 — install writes no `node_modules`; the installed graph resolves through the one resolver), `honesty` (I-11 — sha512 verified-not-keyed, node-semver gap, advisory provenance, honest mode stubs), `footprint` (I-10 — `meow-pkg` stays network-free; the HTTP client is a single small CLI-edge dep). Floor: `cargo test/clippy/fmt`, `principles-check.sh`.

## Rollout

- **Additive engine; one behavioral cutover.** New `meow-pkg` modules (no new workspace member). The cutover is `crates/cli`: `meow install` flips from honest stub to real, and `cmd_run`'s `root_deps_from_lockfile` stand-in is **removed** in favor of config+lockfile root derivation. Both are internal call sites (one each), so it is a single-wave fence edit, not a deprecation.
- **No data migration.** `meow.lock.jsonl` and `~/.meow/cache` are PKG-001 formats already; PKG-002 is their first writer. A pre-PKG-002 hand-seeded cache/lockfile keeps working (same schema).
- **New committed surface:** `meow.config.(ts|json)` may now carry `dependencies`; `meow.lock.jsonl` becomes a generated, committed artifact (the execution contract — committed, unlike `.meow/`).
- **Reversibility:** revert the `// === PKG-002 ===` fences in `schema.rs`/config/`cli.rs`/`Cargo.toml` and delete `crates/pkg/src/{registry.rs,install.rs}` + the re-exports; the LOAD-001 `root_deps_from_lockfile` stand-in returns. No persisted production state depends on it — a populated cache is rebuildable (`rm -rf ~/.meow/cache`), a lockfile is regenerable by re-installing.

## Operator notes

Forks surfaced for Main to consolidate into `decisions.json` (matching the PKG-001/LOAD-003 convention — drafters flag, the sole integrator writes the records; this spec is foundational and coordinates with no peer):

- **A-PKG002-1 · sha512 verify-on-download, sha256 cache key (kind: assumption, confidence: high, reversible: yes).** npm publishes **sha512** SRI; PKG-001 froze the cache/lockfile key at **sha256** (`HashAlgo = Sha256`, "no second algo"). Resolved (A4): verify the publisher sha512 against the bytes at download (supply-chain check), then content-address by meow's sha256 (the lockfile pin + I-7 anchor); the sha512 is verified-then-discarded at P2. Alternative considered (extend `HashAlgo::Sha512` and/or persist the npm SRI in `RegistryProvenance`): deferred — it touches PKG-001's frozen schema and belongs to SEC-002/P6 provenance. **Reversible:** persisting the sha512 later is an additive `RegistryProvenance` field.
- **A-PKG002-2 · default install mode = PnP (kind: assumption, confidence: high, reversible: yes).** ADR-4 + the existing `InstallMode` defaults (config `pnp`, CLI `--mode pnp`) make this a confirmation, not an invention: PKG-002 implements `pnp` and honest-stubs the rest for PKG-004 (same phase). Flagged only because it sets the default user behavior.
- **A-PKG002-3 · declared deps live in `meow.config` `dependencies` (kind: assumption, confidence: medium, reversible: yes).** CANON §18 does not enumerate a `dependencies` field, but §19 (`meow add/remove`) and ADR-8 (config is the single source) imply one. PKG-002 adds `MeowConfig.dependencies: BTreeMap<String,String>` (range or tag) as the human-edited intent; the lockfile pins the exact graph. **Honest boundary (I-11):** pre-RT-001, `add`/`remove` write `meow.config.json` (the loaded source); once `meow.config.ts` evaluation lands they round-trip the TS — the same inherited boundary CFG-001/CFG-002 carry. **Reversible:** a one-field change if Main prefers a different declaration shape.
- **A-PKG002-4 · HTTP client choice (kind: assumption, confidence: medium, reversible: yes, footprint-bounded).** The `NpmRegistry` HTTPS impl uses a small blocking client with **rustls** (proposed: `ureq` w/ rustls — static, no system OpenSSL, off the JS `fetch` path), pinned under `# === PKG-002 ===` and consumed **only** by `crates/cli` so `meow-pkg` stays network-free (I-10). If the rustls duplication footprint bites, swap to the in-tree `hyper-util` + `hyper-rustls` (already pinned for RT-004/RT-005). **Reversible:** a single dep swap behind the `RegistrySource` impl.
- **A-PKG002-5 · node-semver vs the `semver` crate (kind: assumption, confidence: medium, reversible: yes — honest gap).** PKG-002 resolves with the already-pinned `semver` crate (dtolnay/Cargo grammar), which differs from node-semver: `||` unions, hyphen ranges, `x`-ranges, and "bare `1.2.3` == exact" (npm) vs "`^1.2.3`" (semver crate). Unparseable/unknown forms ⇒ `UnsupportedRange` (never a silent mis-resolve). A node-semver-faithful engine is deferred to a later PKG spec. Surfaced because it bounds which real packages install at P2 (common caret/tilde ranges work; exotic ranges error honestly).

**Out of scope (stated, not silently dropped):** registry auth / private registries / `.npmrc` / per-scope registries; install/postinstall scripts; git/file/url specifiers; provenance *verification* (Sigstore/OSV — P6); `--materialize`/`--vfs`/`--vendor` (PKG-004); PnP loading (PKG-003).

**Honest coverage report (I-11):** COVERED — npm metadata + semver(-crate) range/dist-tag resolution, transitive + multi-version graphs, sha512 supply-chain verify, sha256 content-address + I-7 cache store, deterministic byte-identical lockfile, no-`node_modules` PnP install, config-driven root derivation feeding LOAD-003. GAPS (by design, honest): node-semver-only range forms (typed error), registry auth/private registries, lifecycle scripts, non-tarball specifiers, provenance *attestation* (recorded only), `--materialize`/PnP-loading (sibling P2 specs).
