## Motivation

Amendment 001 changes `meow` from a standards-first runtime with opt-in Node compatibility into a Node/Bun drop-in replacement. A stock app that imports `fs`, `path`, `process`, `Buffer`, or `node:*` must run without a flag. Deferring Node built-ins makes the 5-minute test fail (`cd existing-project && meow install && meow run dev`).

The internal architecture stays opinionated: built-ins resolve through the existing loader/native-module seam and host I/O routes through the RT-002 capability op layer. The adoption path is not opinionated: default mode exposes Node APIs. `strict-web` becomes the opt-in withdrawal mode.

## Acceptance criteria

- Bare and `node:` built-in specifiers resolve through the one `meow_loader::Resolver` to `ModuleLocator::Native`:
  - `import path from "path"` and `import path from "node:path"` resolve to the same module.
  - Unknown `node:*` names still surface `ResolveError::UnknownNativeModule`.
- Default runtime installs Node globals and built-in modules:
  - `globalThis.Buffer` exists and `import { Buffer } from "node:buffer"` works.
  - `globalThis.process` exists with `argv`, `env`, `cwd()`, `platform`, `arch`, `version`, `versions`, `stdout`, `stderr`, `nextTick`, and `exit`.
- Common-surface built-ins ship now:
  - `node:path` / bare `path`: `join`, `resolve`, `normalize`, `dirname`, `basename`, `extname`, `relative`, `parse`, `format`, `posix`, `win32`, `sep`, `delimiter`.
  - `node:buffer` / bare `buffer`: `Buffer.from`, `Buffer.alloc`, `Buffer.isBuffer`, `Buffer.byteLength`, UTF-8/hex/base64/utf16le/latin1/ascii round-trips.
  - `node:process` / bare `process`: process metadata, env proxy, cwd, stdout/stderr, nextTick, exit code propagation.
  - `node:fs` / bare `fs`: `readFileSync`, `writeFileSync`, `existsSync`, `statSync`, `readdirSync`, `mkdirSync`, `rmSync`, `accessSync`, plus `fs.promises` async equivalents for the same common subset.
  - `node:fs/promises` / bare `fs/promises`: promise API for the common subset.
  - `node:os`, `node:url`, `node:util`, `node:events` cover the common functions needed by real CLIs and package bins.
- Host-backed APIs route through the RT-002 op/capability seam:
  - default mode is permissive (drop-in).
  - `NodeMode::StrictWeb` withdraws Node globals and denies host-backed built-in operations with `ERR_STRICT_WEB_WITHDRAWN` / capability denial rather than silently reading host state.
- No second resolver, no second native registry, no Node compatibility flag in default mode.
- No `node_modules` is written or required for built-ins.

## Non-goals

- Full bug-for-bug Node parity for every module in this slice. Long-tail modules (`net`, `tls`, `http`, `https`, `child_process`, `worker_threads`, `zlib`, `crypto` beyond basic web-compatible primitives, TTY/REPL/inspector) are not claimed by RT-007 unless tests name them.
- Security hardening of capability grants. RT-007 uses the existing RT-002 seam; SEC-001/Trust Zones later replace the permissive default for strict modes.
- CJS `require()` interop. LOAD-004 consumes these built-ins for `require("fs")`, but RT-007 only provides the modules and globals.

## Interface

Runtime API:

```rust
pub mod node;

pub enum node::NodeMode {
    DropIn,
    StrictWeb,
}

pub struct node::NodeOptions {
    pub mode: NodeMode,
    pub cwd: PathBuf,
    pub argv: Vec<String>,
}

impl node::NodeOptions {
    pub fn drop_in(cwd: impl Into<PathBuf>, argv: Vec<String>) -> Self;
    pub fn strict_web(cwd: impl Into<PathBuf>, argv: Vec<String>) -> Self;
}

pub fn node::extensions(opts: NodeOptions) -> Vec<deno_core::Extension>;
pub fn node::take_process_exit_code(runtime: &deno_core::JsRuntime) -> Option<i32>;
```

Native registry additions:

```rust
pub const NATIVE_MODULES: &[&str] = &[
    "http",
    "node:buffer",
    "node:events",
    "node:fs",
    "node:fs/promises",
    "node:os",
    "node:path",
    "node:process",
    "node:url",
    "node:util",
];
```

Loader additions:

```rust
// Resolver::locate recognizes both node-prefixed and bare built-in specifiers.
Resolver::locate("node:fs", referrer) -> ModuleLocator::Native { name: "node:fs" }
Resolver::locate("fs", referrer) -> ModuleLocator::Native { name: "node:fs" }
```

JavaScript module shape mirrors Node's common ESM import surface:

```ts
import fs from "node:fs";
import { readFileSync } from "node:fs";
import { Buffer } from "node:buffer";
import process from "node:process";
```

## Implementation sketch

- `crates/runtime/src/node.rs` owns `NodeMode`, `NodeOptions`, process state, the `meow_node` extension, and strict-web capability withdrawal.
- `crates/runtime/src/js/node/*.ts` contains embedded native module sources. They are TypeScript and must be lowered through `GraphDb`; the loader maps `node:` native graph paths to `.ts` so the existing type-strip pipeline handles interfaces/annotations.
- `crates/runtime/src/native.rs` registers the built-in module sources and declarations in stable order.
- `crates/runtime/src/io/ops.rs` adds host-backed Node fs ops. Every op checks `CapabilityCheck` before touching host state. Sync Node APIs use `std::fs`; async promise APIs use the RT-002 `backend` / tokio layer.
- `crates/loader/src/resolver.rs` recognizes Node built-ins before package bare-specifier resolution so `fs` cannot be shadowed by an npm package in default mode.
- `crates/runtime/src/lib.rs` wires `node` extensions into the runtime construction path used by `meow run`.
- Shared-file edits are fenced `// === RT-007 ===` / `// === /RT-007 ===`.

## Rollout

RT-007 flips the default runtime surface. Existing strict-web tests must opt into `NodeMode::StrictWeb` if they assert Node globals are unavailable. `strict-web` is retained as an explicit mode for edge/security-sensitive projects.

Rollback: remove the `node` extension from default runtime options and leave the native registry entries behind as unused; no persistent migration is involved.

## Operator notes

FORK[RT-007:surface] Ship the common Node built-in slice now instead of claiming full Node parity; full long-tail parity is test-driven by the drop-in corpus because false completeness claims are worse than missing APIs.

FORK[RT-007:bare-shadowing] Built-ins win over npm packages named `fs`/`path` in default mode, matching Node; npm packages can still import via package subpaths if real.

FORK[RT-007:strict-web] Strict-web withdraws Node globals/modules at API-use time instead of import-time where practical, so diagnostics are catchable and tests can prove withdrawal without aborting module instantiation.
