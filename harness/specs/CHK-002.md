## Motivation

ADR-5 splits TypeScript into two concerns: **execution** (Oxc type-stripping, instant, native — RT-003) and **diagnostics** (delegated to the reference compiler `tsc`/`tsgo`, never reimplemented). CHK-001 is the diagnostics authority: an out-of-process `tsc`/`tsgo` daemon consuming the shadow `.meow/tsconfig.json` (ADR-8/CFG-001) — correct, but only as fast as the reference compiler and explicitly **not** part of the "10× toolchain" claim (CANON §24.2, I-11). That latency is the gap: an editor that waits on the daemon for *every* keystroke feels sluggish, and a CLI pre-commit hook paying full-`tsc` cost on a one-line change is too slow for the inner loop.

ADR-5 closes the gap with its third clause, stated three times in CANON (ADR-5, §7.1 stage-3 row, §9.1): *"a fast, intentionally-incomplete type-aware linter runs in-process on the Oxc semantic graph to catch obvious mismatches cheaply; absolute soundness is left to the reference compiler… The linter MUST be labeled a fast preview and is never authoritative."* CHK-002 **is** that linter: a set of tsc-class diagnostics (undefined names, unused bindings, statically-visible floating promises, obvious literal/annotation mismatches) computed in-process from `meow-graph`'s **stage-2 `SemanticGraph`** (scopes/bindings/symbols/references) — **no `tsc` pass, no type graph, no second parser** (I-1). It is surfaced as **`meow check --preview`**: the *same* command as the authoritative check, in a faster, honestly-incomplete mode.

This is a load-bearing instance of the project's cardinal honesty rule (CRAFT Part B, I-11): two type engines (the fast preview and the reference checker) *can disagree*, so the preview's output is structurally labelled (its diagnostics carry a `"preview/…"` code namespace, and — pending an additive `Tool::CheckPreview` variant — the `tool` field) and never claims completeness; a clean preview is **not** a clean `meow check`. And it is the parse-once-native half of CHK's diagnostics: unlike CHK-001 (which re-parses out-of-process inside `tsc`), CHK-002 reads the **already-parsed** `SemanticGraph` the runtime/lint/format/bundle share, so a file checked-preview in the same `GraphDb` as a lint/format is parsed exactly once (I-1, the P3 exit condition).

Traceability: `plan_ref` → PLAN.md *Build sequence · P3 Parse-Once Toolchain* (exit: *"a file is parsed once and reused across multiple tool operations in one invocation"*; daemon **+ fast-preview linter**) + *backlog Later phases · P3* (`CHK-002 fast-preview type-aware linter`). `constitution_ref` → **I-1** [`graph-integrity`] (consumes the shared `SemanticGraph`; constructs no parser/semantic pass — the spec's **primary gate**), **I-4** [`check-parity`] (the in-process linter is *labelled a fast preview and never authoritative* — CHK-001's daemon stays the source of truth), **I-11** [`honesty`] (the preview↔truth boundary is stated in code, output, and help, never blurred). CANON refs: ADR-5, §7.1, §9.1, §24.2.

## Acceptance criteria

A new leaf crate `crates/check-preview` (`meow-check-preview`) plus a fenced `--preview` flag + dispatch branch in CHK-001's `cmd_check`. Every editor/CLI-triggerable path returns its diagnostics without panic — a malformed/partial file is **input, not a bug**: Oxc recovers, `GraphDb::semantic` always yields a graph, and a retired/unknown `FileId` is skipped, never `unwrap`ed (CRAFT Part B). No `unwrap`/`expect`/`panic!` on any file-reachable path. The crate reads **no host state** (P16): the `GraphDb`, the file set, and the known-global names are all caller-supplied; the only ambient reads (cwd, file bytes) live at the CLI edge (`cmd_check_preview`), exactly as `cmd_run`/`cmd_sync` already do.

### A1 — `crates/check-preview/src/lib.rs` — the in-process entry (the locked tool seam)

```rust
use std::path::Path;
use std::sync::Arc;

use meow_diag::Diagnostic;          // OWNED by TOOL-002 (Main ruling); CHK-002 only emits it
use meow_graph::{FileId, GraphDb};  // GRAPH-001 — the ONE parse pipeline (I-1)

/// Run the fast-preview type-aware rule set over an ALREADY-PARSED set of files and return
/// the diagnostics. This is the locked P3 tool-entry seam — `(&GraphDb, &[FileId])` in,
/// `Vec<Diagnostic>` out, **never `set_file`, never a parser** (I-1, the shape every P3 tool
/// uses incl. `meow_lint::lint`): the caller (the CLI `cmd_check_preview`, or TOOL-001's
/// shared `ToolSession` driver) owns the one `GraphDb` and has already loaded each file
/// exactly once, so a file lint-ed/formatted in the same invocation is parsed once (the P3
/// parse-once guarantee).
///
/// Every returned `Diagnostic` is stamped `tool: Tool::CheckPreview` — the first-class
/// "fast preview, never authoritative" label (I-4; Main-ruled canonical, see A4) — and
/// `code: DiagCode("check/<id>")` sharing the check-domain code identity with CHK-001's
/// authoritative daemon (same diagnostic class, different `tool` ⇒ the editor supersedes a
/// preview with the daemon's verdict). A `FileId` that is unknown/retired (file-watch churn)
/// is silently skipped; Oxc's error recovery means a syntactically-broken file still yields a
/// `SemanticGraph`, so the preview degrades to "what is still analyzable", never a panic.
pub fn preview_check(
    db: &GraphDb,
    files: &[FileId],
    registry: &PreviewRegistry,
) -> Vec<Diagnostic>;
```

Behaviors:
- `preview_check` constructs **no** Oxc parser or `SemanticBuilder`; for each `file` it reads `db.semantic(file)` (stage 2, memoized) + `db.path(file)` (to stamp `Diagnostic.file: Arc<Path>`) and runs each `PreviewRule` over that one graph. If `db.semantic(file)` is `None` (retired id), the file is skipped.
- Parse-once is by construction: `db.semantic(file)` is memoized on the file's slot (GRAPH-001), so a file already touched by lint/format/the runtime in the *same* `GraphDb` is **not** re-analyzed — provable via `db.recomputes().semantic` (A6 test).
- The result preserves rule order per file and file order across files (deterministic); diagnostics are not sorted here (the CLI renderer sorts by `(file, span.start)`, matching `meow lint`).

### A2 — `PreviewRegistry`, `PreviewRule`, `KnownGlobals` (`crates/check-preview/src/registry.rs`)

CHK-002 owns a **self-contained** preview-rule abstraction that walks the shared stage-2 `SemanticGraph` — mirroring the codebase's existing stage-2-consumption idiom, `meow_graph::strip::ErasablePolicy::check(sem: &SemanticGraph) -> Result<(), Vec<StripDiagnostic>>` (it iterates `sem.nodes()`, matches `AstKind`, pushes diagnostics). It does **not** route through `meow-lint`'s engine (see `FORK[CHK-002:engine-reuse]`). Rules are modeled as **data** (a `Vec<Box<dyn PreviewRule>>`), never a per-rule `if`-ladder.

```rust
use std::path::Path;
use std::sync::Arc;

use meow_diag::Diagnostic;
use meow_graph::SemanticGraph;

/// A single fast-preview rule: read-only over ONE file's already-parsed stage-2 graph,
/// pushing zero or more `Diagnostic`s. Every diagnostic a rule emits MUST carry
/// `tool: Tool::CheckPreview` and `code: DiagCode("check/<id>")` (A4) — the `report` helper
/// stamps both so a rule body cannot forget the I-4 label.
pub trait PreviewRule: Send + Sync {
    /// Stable id; the emitted `DiagCode` is `"check/<id>"` — `&'static str` (a closed set),
    /// stored as `Cow::Borrowed` in the canonical `meow_diag::DiagCode(Cow<'static, str>)`.
    fn id(&self) -> &'static str;
    /// Walk `sem` and push diagnostics. `file` is the `Arc<Path>` for stamping
    /// `Diagnostic.file` (the caller resolved it once via `GraphDb::path`).
    fn run(&self, sem: &SemanticGraph, file: &Arc<Path>, out: &mut Vec<Diagnostic>);
}

/// The fast-preview rule set. Constructed once and reused across files/invocations.
pub struct PreviewRegistry {
    rules: Vec<Box<dyn PreviewRule>>,
}

impl PreviewRegistry {
    /// The standard preview rule set (A3), parameterized by the names legal WITHOUT a binding
    /// in a file (`KnownGlobals`) so `check/cannot-find-name` never false-positives on a
    /// legitimate global. `globals` is injected into the rules that need it. `globals` is DATA
    /// supplied by the caller — sourced from the runtime's global registry (RT-004 strict-web
    /// set + `meow:*`), NOT read from the host (P16).
    pub fn standard(globals: KnownGlobals) -> PreviewRegistry;
    pub fn rules(&self) -> &[Box<dyn PreviewRule>];
}

/// The set of names a reference may resolve to WITHOUT a binding in the analyzed file:
/// standard ES globals, RT-004's strict-web "Stateless Edge" globals (`fetch`, `Response`,
/// `URL`, `crypto`, `TextEncoder`, `setTimeout`, …), and the bare `meow:*` module identifiers.
/// Caller-supplied DATA (the runtime exposes the canonical list, I-9) — this crate never
/// enumerates globals by reading the host (P16). Backed by `rustc_hash::FxHashSet<Box<str>>`,
/// interned once; `contains` is O(1).
#[derive(Clone, Default)]
pub struct KnownGlobals(Arc<rustc_hash::FxHashSet<Box<str>>>);

impl KnownGlobals {
    pub fn from_names(names: impl IntoIterator<Item = String>) -> KnownGlobals;
    pub fn contains(&self, name: &str) -> bool;
}
```

### A3 — The preview rule set (`crates/check-preview/src/rules/*.rs`) — the honest boundary

The set is deliberately the diagnostics **decidable from the stage-2 `SemanticGraph` alone** — scopes, bindings, references, and literal AST shape — with **zero type inference**. Each rule's doc states the `meow check` (tsc) diagnostic it corresponds to (so a user sees the preview↔truth bridge) **and** whether `meow check` actually corroborates it, and states what the preview provably **cannot** see. Two honest classes (I-11): rules **1–3** preview real `tsc` diagnostics — a strict subset of `meow check` (modulo strictness flags, noted per rule); rule **4** is a **type-aware lint heuristic that `meow check` does NOT report** (tsc has no floating-promise diagnostic — that is a typescript-eslint-class rule), so it is preview-only, neither corroborated nor contradicted by `meow check`. Governing discipline (CRAFT Part B, I-11): **a fast preview that cries wolf is worse than useless** — every rule is biased to **false-negatives (a miss) over false-positives (flagging valid code)**, because CHK-001 is the authority and a noisy preview trains users to ignore it.

1. **`check/cannot-find-name`** — corresponds to `tsc` **TS2304** ("Cannot find name 'x'"), which `meow check` always reports. Fires on each reference in `sem.scoping().root_unresolved_references()` (the names Oxc proved bind to **no** symbol in any scope) whose name is not in `KnownGlobals`. `Severity::Error`. **Sees:** typos, missing imports, use-before-any-declaration. **Cannot see:** a name that *is* bound but used at the wrong type (TS2345/TS2322 — needs types); a global the `KnownGlobals` set does not list (skipped, not flagged — bias to miss).
2. **`check/no-unused`** — corresponds to `tsc` **TS6133**, which `meow check` reports **only when the project's tsconfig enables `noUnusedLocals`/`noUnusedParameters`** (otherwise the preview surfaces it but the authoritative check stays silent — stated honestly, not as a disagreement). Fires on a binding whose symbol has **zero** resolved references (`sem.scoping().get_resolved_references(symbol_id)` empty), excluding exported bindings, `_`-prefixed names (the conventional "intentionally unused" marker), ambient (`declare`) declarations, and parameters before the last used one. `Severity::Warning`. May carry a conservative `Fix` for an unused *import specifier* (delete the specifier span — semantics-preserving). **Cannot see:** a binding consumed only in another file via a re-export/type position (needs the module graph + types → CHK-001).
3. **`check/type-mismatch`** — corresponds to a strict SUBSET of `tsc` **TS2322/TS2345** that `meow check` reports: a `VariableDeclarator` (or a typed parameter with a default) carrying an **explicit primitive annotation** (`number`/`string`/`boolean`/`bigint`) initialized with a **literal** of an obviously incompatible primitive — `const n: number = "x"`, `let b: boolean = 0`. Pure local literal-vs-annotation comparison. `Severity::Error`. **Cannot see:** any mismatch needing inference — assignability of object/array/union/generic types, control-flow narrowing, `as` assertions, structural typing, declaration merging. Those are the bulk of TS2322/TS2345 and belong to `meow check`.
4. **`check/floating-promise`** — a **type-aware lint heuristic, preview-only** (NOT a `tsc` diagnostic — `meow check` will neither corroborate nor contradict it; the analogue is typescript-eslint's `no-floating-promises`). Fires on an `ExpressionStatement` whose expression is a `CallExpression` (not `await`ed, not `void`ed, return value discarded) whose callee is **statically, locally** known to return a promise: a same-file `async function`/`async` method, or a callee binding initialized to an async function. `Severity::Warning`. **Cannot see** the common real case — a discarded call to an *imported*/annotated function whose promise-ness is known only from its **type signature**; that requires the type graph (a full type-aware linter, post-1.0 stretch per CANON). The preview catches only the in-file, syntactically-obvious subset and its `help` says so.

Sketch of one rule body (the established `ErasablePolicy::check` idiom + the stamping helper):

```rust
// crates/check-preview/src/rules/cannot_find_name.rs
pub struct CannotFindName { globals: KnownGlobals }

impl PreviewRule for CannotFindName {
    fn id(&self) -> &'static str { "cannot-find-name" }
    fn run(&self, sem: &SemanticGraph, file: &Arc<Path>, out: &mut Vec<Diagnostic>) {
        let scoping = sem.scoping();
        for (name, refs) in scoping.root_unresolved_references() {
            if self.globals.contains(name.as_str()) { continue; } // a legal global — bias to miss
            for &reference_id in refs {
                let span = /* the reference's identifier span via sem.nodes() */;
                report(out, file, self.id(), Severity::Error, span,
                    format!("Cannot find name `{name}`."),
                    Some("Declare it, import it, or check the spelling. This is a fast \
                          preview — run `meow check` for authoritative type diagnostics.".into()),
                    None);
            }
        }
    }
}

/// The single stamping seam: builds a `meow_diag::Diagnostic` stamped with the check-preview
/// tool + the `"check/<id>"` code namespace, so NO rule body can emit an unlabelled (non-preview)
/// diagnostic (I-4 by construction).
fn report(out: &mut Vec<Diagnostic>, file: &Arc<Path>, id: &'static str, severity: Severity,
          span: oxc_span::Span, message: String, help: Option<String>, fix: Option<Fix>) {
    out.push(Diagnostic {
        file: file.clone(),
        span: meow_diag::Span { start: span.start, end: span.end }, // same layout — free conversion
        severity,
        code: DiagCode(check_code(id)),     // Cow::Borrowed("check/<id>") — &'static, zero-alloc
        message, help, fix,
        tool: PREVIEW_TOOL,                 // Tool::CheckPreview (A4)
    });
}
```

### A4 — Diagnostic labelling: the I-4 mechanism (Main-ruled canonical `meow-diag`)
During P3 coordination the shipped `TOOL-002.md` and CHK-001's `irc` "LOCKED" message diverged on `meow-diag`; **Main ruled the canonical shape at merge** (see Operator notes). CHK-002 cites that canonical shape:
```rust
// crates/diag (OWNED by TOOL-002; Main-reconciled canonical) — consumed verbatim, NOT redefined here.
pub struct Diagnostic { pub file: Arc<Path>, pub span: Span, pub severity: Severity,
    pub code: DiagCode, pub message: String, pub help: Option<String>,
    pub fix: Option<Fix>, pub tool: Tool }
pub struct Span { pub start: u32, pub end: u32 }       // == oxc_span::Span layout (free conversion)
pub enum Severity { Error, Warning, Info, Hint }       // +Hint (Main)
pub struct DiagCode(pub Cow<'static, str>);            // Cow (Main): borrowed for static ids, owned for tsc's "TS2345"
pub enum Tool { Lint, Fmt, Bundle, Check, CheckPreview }   // +CheckPreview (Main)
pub struct Fix { pub edits: Vec<Edit> }  pub struct Edit { pub span: Span, pub replacement: String }
```
CHK-002 uses only `Severity::{Error, Warning}` and `'static` codes (`Cow::Borrowed`) — so it sits comfortably inside the canonical shape. The "fast preview, never authoritative" label (I-4) is **first-class and structural**, set centrally in `report` (A3) so a rule cannot omit it:
- **The label = `tool: Tool::CheckPreview`.** This is the discriminator the editor/CLI/`check-parity` gate read: CHK-001's authoritative daemon emits `Tool::Check`; CHK-002 emits `Tool::CheckPreview`. Same `code` (e.g. `"check/cannot-find-name"`) under different `tool` means "same diagnostic class, preview vs. authoritative" — exactly the editor's preview→daemon supersede story (CANON §20 "routing to the right LSP source"). Per Main's direction, CHK-002 does **not** carry an interim `"preview/…"` code prefix — the `tool` field carries the label and the codes stay in the shared `"check/…"` namespace.
- **The code = `DiagCode("check/<id>")`**, `Cow::Borrowed` (zero-alloc; CHK-002's ids are all `'static`). It is a stable, greppable id sharing the check domain with CHK-001 (so a preview finding and its eventual authoritative counterpart carry the same code).
```rust
// crates/check-preview/src/lib.rs
use meow_diag::Tool;
/// The `tool` stamp for every preview diagnostic — the first-class I-4 label (Main-ruled canonical).
const PREVIEW_TOOL: Tool = Tool::CheckPreview;
```

```rust
// === CHK-002 ===  (crates/cli/src/cli.rs)
/// `meow check --preview` — load each target into ONE GraphDb (parse-once), run the preview
/// rule set, render, and exit non-zero iff a preview-detectable ERROR was found. The output
/// ALWAYS carries the "fast preview / not authoritative" banner (I-4/I-11): exit 0 means
/// "no preview-detectable errors", NOT "type-checks cleanly".
fn cmd_check_preview(paths: &[PathBuf]) -> ExitCode {
    let mut db = meow_graph::GraphDb::new();
    // Expand paths → first-party .ts/.tsx/.mts/.js/.mjs files; set_file each ONCE (host edge).
    let files: Vec<meow_graph::FileId> = /* read + db.set_file(path, text) per target */;
    let registry = meow_check_preview::PreviewRegistry::standard(known_globals());
    let diags = meow_check_preview::preview_check(&db, &files, &registry);
    // Shared meow-diag renderer (TOOL-002), then the mandatory preview banner to stderr.
    print!("{}", meow_diag::render_pretty(&diags, &|p| source_of(&db, p)));
    eprintln!("note: fast preview — not authoritative; run `meow check` for full type correctness");
    if diags.iter().any(|d| d.severity == meow_diag::Severity::Error) {
        ExitCode::FAILURE
    } else {
        ExitCode::SUCCESS
    }
}
// === /CHK-002 ===
```

`Command::Check`'s landing already reads `("check", "P3")` (DIST-001); no `landing()` edit is needed — `--preview` is a flag, not a verb.

### A7 — Consumed contract (NOT redefined here)

- **`meow_diag` (TOOL-002, OWNER per Main):** `Diagnostic`, `Span`, `Severity`, `DiagCode`, `Tool`, `Fix`/`Edit`, `render_pretty`, `render_json` — cited from the **Main-ruled canonical** `crates/diag` surface (A4: `DiagCode(Cow<'static, str>)`, `Severity{…,Hint}`, `Tool{…,CheckPreview}`). CHK-002 **emits** these; it defines none.
- **`meow_graph` (GRAPH-001):** `GraphDb::{semantic, path, recomputes}`, `SemanticGraph::{scoping, nodes, source}`, `FileId`. CHK-002 reads stage 2 only; it never calls `set_file` (the driver/CLI owns the mutation cadence) and never touches stage 5 (strip is RT-003's, irrelevant to linting). - **`oxc_ast`/`oxc_span`/`oxc_semantic` (the same workspace pins GRAPH-001 uses, 0.134):** `AstKind`, `Span`, `Scoping` — for matching node kinds and querying scopes/references in rule bodies. **Read-only**: CHK-002 constructs no `Parser`/`SemanticBuilder` (P15) — it only reads the `SemanticGraph` GRAPH-001 already built.
- **CHK-001:** `Command::Check` + `CheckArgs` + `cmd_check` — CHK-002 extends them under `// === CHK-002 ===` fences (A5); CHK-001 reserves the dispatch slot and keeps the daemon path as the default.

## Non-goals

- **Authoritative type checking** — **CHK-001**. CHK-002 never spawns/embeds/proxies `tsc`/`tsgo`, builds no type graph, performs no inference/assignability/narrowing. It is a strict subset of `meow check`; a clean preview is explicitly **not** a clean check (I-4 — the whole point).
- **General lint rules** (`no-first-party-cjs`, erasable-only, style/convention) — **TOOL-002** (`meow lint`, `tool: Tool::Lint`, `"lint/…"` codes). CHK-002 owns only the **type-aware preview** rules (`tool: Tool::CheckPreview`, `"check/…"` codes) under `meow check --preview`.
- **The shared `Diagnostic` model + renderer** — **TOOL-002** (`meow-diag`, Main ruling). CHK-002 consumes/emits it; it defines none of those types.
- **The parse-once driver/session** (`ToolSession`/`meow-driver`) — **TOOL-001**. CHK-002 conforms to the locked `(&GraphDb, &[FileId]) -> Vec<Diagnostic>` tool seam and is *driven* by it; it does not own or build it, and does not `set_file`.
- **Editor/LSP wiring** — a later LSP spec. CHK-002 ships the in-process *callable* (`preview_check`) + `PreviewRegistry`/`KnownGlobals`; the JSON-RPC server, the keystroke-debounced preview-then-daemon supersede flow, and squiggle rendering are not in this spec (precedent: LSP-001's `EditorResolver` is the in-process shared-graph consumer; CHK-002 is the diagnostics analogue).
- **Autofix beyond the safe minimum.** Only `check/no-unused` (unused import specifier) may emit a `Fix`; the type-class rules point at the fix in `help` and emit no edit (an autofix for a type mismatch would need type info CHK-002 lacks).
- **Cross-file analysis.** Every rule is single-file (one `SemanticGraph`). Reachability/dead-export across the module graph is type/graph-driven → CHK-001 / later passes (CANON's "deeper type-aware lint on the semantic graph" is a post-1.0 stretch).
- **Watch mode** — `meow check --watch` is CHK-001's (the daemon). `--preview` is a one-shot batch; an editor obtains incrementality by re-calling `preview_check` over the warm `GraphDb` the driver keeps.

## Interface

- **New crate** `crates/check-preview` (`meow-check-preview`), **library only**. Picked up by the `members = ["crates/*"]` glob — no root `Cargo.toml` membership edit. Public surface: `preview_check`, `PreviewRegistry`, `PreviewRule`, `KnownGlobals`. Deps: `meow-diag` (`Diagnostic`, the emitted model), `meow-graph` (`GraphDb`/`SemanticGraph`/`FileId`), `oxc_ast`/`oxc_span`/`oxc_semantic` (AST kinds + spans for rule bodies — same workspace pins GRAPH-001 uses, **read-only**; CHK-002 constructs no parser), `rustc-hash` (the globals set), `thiserror`. **No new external pin** → no `[workspace.dependencies]` fence.
- **CLI:** `meow check --preview [PATHS]` — a flag on the existing `Command::Check`. No new verb, no `landing()` change. Exit `0` = no preview-detectable **errors** (warnings do not fail); `1` = a `Severity::Error` preview diagnostic; the daemon path (no flag) is unchanged.

## Implementation sketch

New crate `crates/check-preview`: `src/lib.rs` (`preview_check`, `PREVIEW_TOOL`, `report` seam, `check_code`), `src/registry.rs` (`PreviewRule`, `PreviewRegistry`, `KnownGlobals`), `src/rules/{cannot_find_name,unused,floating_promise,type_mismatch}.rs` (one `PreviewRule` impl each), `tests/preview.rs`. Mechanism mirrors the **existing** `ErasablePolicy::check` in `crates/graph/src/strip.rs` (walk the stage-2 graph, match `AstKind`, push diagnostics) — the codebase's established way to consume stage 2, reused, not reinvented.

1. **`preview_check`** → for each `&file`: `let Some(sem) = db.semantic(file) else { continue }`; `let path = Arc::from(db.path(file).unwrap_or(Path::new("<unknown>")))`; for each `rule` in `registry.rules()`: `rule.run(sem, &path, &mut out)`. No parser, no `set_file`.
2. **`cannot_find_name`** → iterate `sem.scoping().root_unresolved_references()`; skip `globals.contains(name)`; `report` each reference span (`Severity::Error`).
3. **`unused`** → iterate `sem.scoping()` symbol ids; `report` those with empty `get_resolved_references`, after the exclusion filter (exported / `_`-prefixed / ambient / trailing-param). Unused *import specifier* attaches a `Fix` deleting the specifier span.
4. **`floating_promise`** → match `AstKind::ExpressionStatement` in `sem.nodes()`; if the expr is a non-awaited/non-voided `CallExpression` whose callee resolves (via `scoping`) to a same-file `async` function/method, `report` (`Severity::Warning`).
5. **`type_mismatch`** → match `AstKind::VariableDeclarator` (+ defaulted `FormalParameter`); if an explicit primitive `TSTypeAnnotation` contradicts a primitive-literal initializer, `report` (`Severity::Error`).
6. **`known_globals()` (CLI helper)** → build `KnownGlobals` from the runtime's exported global registry (RT-004 strict-web names + `meow:*`); the crate only `contains`-queries the supplied data (P16).

CRAFT discipline: no `unwrap`/`panic!` on any file-reachable path (a retired `FileId` → skip; a broken parse → Oxc-recovered `SemanticGraph`, partial analysis); rule bodies borrow (`&AstNode`, `&str`, `&Scoping`) and allocate only the `String` message + the `clone` of the `Arc<Path>`; the rule set is **data** (`Vec<Box<dyn PreviewRule>>`), never a hand-rolled `if`-ladder; the `report` seam is the single stamping point so `tool: Tool::CheckPreview` + the `"check/<id>"` code (the I-4 label) cannot be forgotten; rules are conservative (false-negative-biased) so the preview never cries wolf (the meow cardinal honesty rule).

## Tests required

`crates/check-preview/tests/preview.rs` (fixtures: small TS strings → `GraphDb::set_file` → `preview_check`) + unit tests per rule. Proves **I-1** [`graph-integrity`] (primary), with **I-4** [`check-parity`] (the labelling) and **I-11** [`honesty`] (the boundary). Floor: `cargo test/clippy/fmt`, `harness/principles-check.sh`.

- **Parse-once / single-graph (I-1, `graph-integrity` — primary):** build one `GraphDb`; `set_file` a TS fixture once; read `db.semantic(file)` directly (simulating another tool), THEN run `preview_check` over the same db; assert `db.recomputes().semantic == 1` for that file (the SemanticGraph was computed once and **reused**, not re-derived). Structural: the crate references **no** `oxc_parser`/`SemanticBuilder` (mirrors LOAD-003's parser-absence assertion; backed by `principles-check.sh` P15) — CHK-002 only reads `GraphDb::semantic`/`SemanticGraph`.
- **Each rule fires on a true positive AND stays quiet on the valid lookalike (the false-positive guard — the honesty bar):**
  - `cannot-find-name`: `fetcch()` → one `check/cannot-find-name` (`Error`); `fetch()` with `fetch` in `KnownGlobals` → **none**; an imported-then-used name → **none**; a name bound in a nested scope → **none**.
  - `no-unused`: `const x = 1;` unreferenced → one `check/no-unused` (`Warning`); `const _x = 1;` → **none**; an exported `const` → **none**; an unused `import { a }` → one diagnostic carrying a `Fix` that deletes `a`.
  - `floating-promise`: a discarded call to a same-file `async function f(){}` → one `Warning`; the same call `await`ed or `void`ed → **none**; a discarded call to an *imported* function (promise-ness only in its type) → **none** (proves the honest boundary: the preview deliberately does **not** flag it).
  - `type-mismatch`: `const n: number = "x"` → one `Error`; `const n: number = 1` → **none**; `const o: {a:number} = {a:"x"}` → **none** (needs inference → CHK-001).
- **Labelling (I-4, `check-parity` clause "confirm the in-process linter is labelled fast preview"):** every `Diagnostic` from `preview_check` has `tool == Tool::CheckPreview` and `code.0` starting `"check/"`. No path emits `Tool::Check` (CHK-001's authoritative tag), `Tool::Lint`, or any other tool — so the editor/CLI can always tell preview from authoritative off the `tool` field alone.
- **Honesty boundary, asserted not just claimed (I-11):** a fixture `meow check` would reject but the preview provably cannot (e.g. an assignability error through an imported generic) yields **zero** preview diagnostics — encoding "preview ⊊ check" as a test, so a future contributor who "improves" a rule into a false-positive breaks it.
- **Robustness (no panic):** a syntactically broken file (Oxc-recovered), an empty file, a retired `FileId`, and a `.d.ts` ambient file each return cleanly (skipped or partial), never panic.
- **CLI exit semantics:** `meow check --preview` over a fixture with a `check/cannot-find-name` exits `1`; over a warning-only fixture exits `0`; the "fast preview — run `meow check`" banner is always on stderr (assert via a CLI integration test, mirroring the existing `cli.rs` stub tests).

GATES: **`graph-integrity`** (I-1 — primary; one parse pipeline, CHK-002 builds no parser and reuses the shared `SemanticGraph`, parse-once proven by `recomputes`), `check-parity` (I-4 — the gate verifies the in-process linter is **labelled** "fast preview"; CHK-002's `tool: Tool::CheckPreview` is exactly that mechanism, and the gate's tsc-diff corpus is CHK-001's, not CHK-002's — the preview is never diffed *for parity*, only confirmed *labelled*), `honesty` (I-11 — preview↔truth boundary stated in code/output/help). Floor as above.
