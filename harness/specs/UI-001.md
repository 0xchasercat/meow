## Motivation

Meow's systems engineering is now drop-in and serious; the user-facing shell must feel delightful without becoming vague. UI-001 creates the "structural cuteness" layer: a cute envelope around technically precise output.

The rule is **Envelope + Letter**:

- Envelope: icons, labels, and palette create the vibe.
- Letter: body text, diagnostics, paths, versions, and source snippets stay exact.

The UI layer is an adoption feature (Amendment 002), but it must never become a footprint or CI tax. It is zero external dependencies, disables styling/animation for non-terminals, and leaves user program stdout/stderr untouched.

## Acceptance criteria

- `crates/ui` exists as `meow-ui` and has no external dependencies.
- Palette:
  - Success/Purr: `😸 [Purrfect!]`, Catnip Green `#98FF98`.
  - Error/Hiss: `🙀 [Bad Kitty!]`, Mochi Pink `#FFB7C5`.
  - Action/Pounce: `🐾 [Pouncing...]`, Sky Blue `#89CFF0`.
- `Ui::auto()` disables color and animation when output is not a terminal or `NO_COLOR` is set.
- Walking paw spinner frames are exactly:
  - `🐾    `
  - ` 🐾   `
  - `  🐾  `
  - `   🐾 `
  - `    🐾`
- Bento boxes render structured output in thin Unicode frames.
- Source diagnostics render a miette-style snippet with Mochi Pink caret highlighting.
- Waterfall renderer renders 500+ module spans without quadratic behavior or terminal animation.
- CLI integration routes meow's own success/error/action lines through `meow-ui`; user program stdout remains raw.
- Runtime bridge exposes `import { ui } from "meow:ui"` with `ui.purr()`, `ui.hiss()`, `ui.pounce()`.

## Interface

```rust
pub struct Ui { /* stream style + animation mode */ }

impl Ui {
    pub fn auto() -> Ui;
    pub const fn plain() -> Ui;
    pub fn purr_line(self, body: &str) -> String;
    pub fn hiss_line(self, body: &str) -> String;
    pub fn pounce_line(self, body: &str) -> String;
    pub fn purr(self, body: &str);
    pub fn hiss(self, body: &str);
    pub fn pounce(self, body: &str);
    pub fn spinner(self, label: impl Into<String>) -> Spinner;
}

pub mod bento {
    pub fn render(style: Style, title: &str, lines: &[String]) -> String;
}

pub mod diagnostic {
    pub struct SourceDiagnostic<'a> { pub path: &'a str, pub source: &'a str, pub span: (usize, usize), pub message: &'a str, pub label: Option<&'a str> }
    pub fn render(style: Style, diag: &SourceDiagnostic<'_>) -> String;
}

pub mod waterfall {
    pub struct Span { pub module: String, pub start_us: u64, pub dur_us: u64 }
    pub fn render(style: Style, spans: &[Span], track: usize) -> String;
}
```

Runtime bridge:

```ts
import { ui } from "meow:ui";
ui.pounce("installing");
ui.purr("done");
ui.hiss("bad input");
```

## Implementation plan

1. Build `crates/ui` pure renderers and IO facade.
2. Add `meow-ui` as a path dependency of `meow-cli`; route CLI diagnostics through the facade while preserving program output.
3. Add a runtime UI extension with typed ops for purr/hiss/pounce and an embedded ASCII-only `meow:ui` module.
4. Add CLI/runtime tests for plain non-TTY output and bridge behavior.
5. Run full floor and footprint check.

## Tests required

- Envelope renderer keeps body verbatim and colors only the header.
- Bento box rows align even with ANSI-colored content.
- Diagnostic snippets clamp bad spans and render caret under the correct column.
- Waterfall renders 500 entries and offsets later modules rightward.
- Spinner disables in non-animated mode and exposes exact paw frames.
- CLI output assertions still pass in non-TTY mode (plain output, no ANSI/animation).
- `meow:ui` module can be imported and emits purr/hiss/pounce lines.

## Operator notes

FORK[UI-001:dependencies] zero external deps by default because cuteness must not threaten the <60 MB budget; miette/ratatui/etc. can be considered only if a later audit proves the hand-rolled renderer is insufficient.

FORK[UI-001:program-output] meow's own diagnostics are wrapped, user program output is never wrapped because drop-in compatibility beats brand consistency.
