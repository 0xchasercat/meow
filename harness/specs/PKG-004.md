## Motivation

ADR-4 makes PnP-style in-memory resolution the **default** — no `node_modules`, the loader points imports at the global content-addressed cache (CANON §12.2, I-5). The named, accepted cost (CANON §24.4): **tools that `stat()` the real filesystem for packages break under PnP** — certain bundlers, native-addon toolchains, IDE plugins. ADR-4's consequence is explicit: *"`--materialize` is a required escape hatch, not optional polish — it ships in the same phase as PnP"* (§24.4: "`--materialize` ships **with** PnP (Phase 2), not after; provide `vendor` too"). PLAN §P2 lists "PnP in-memory loader **and `--materialize` together**" as one deliverable, and the P2 dependency note repeats it.

This spec is the **disk-projection half** of that pair (PKG-003 is the in-memory PnP half). It writes a **real `node_modules/` tree** (`--materialize`) — the compatibility escape hatch for foreign tools — and a **self-contained `vendor/` copy** (`--vendor`) for air-gapped deploys (CANON §12.2 install-modes table: *Materialized → "Real files written to disk → CI, Docker, legacy tools"*; *Vendor → "Full local dependency copy → Air-gapped deployments"*).

The constitutional spine this rides on:

- **I-5 [`resolver-parity`]** — the load-bearing invariant. Materialize is a *projection of the same resolved graph*, **not a second resolver**. `meow run`/`check`/`bundle` continue to resolve through the single `meow_loader::Resolver` (LOAD-003) reading the cache + lockfile; meow itself **never** reads the materialized `node_modules` to run. The tree exists so *external* tools see the graph meow already computed. Parity is therefore checkable two ways: meow's resolution is unchanged (still PnP, one resolver), and a faithful Node `node_modules` walker over the materialized tree resolves every specifier to the *same* `(name, version)` meow's `Resolver` does.
- **I-7 [`lockfile-integrity`]** — every byte written to disk comes from `Cache::read(&integrity)`, which recomputes + verifies the hash before returning (PKG-001). A tampered cache blob **aborts** materialize; the escape hatch never launders unverified bytes onto disk.
- **I-6 [`determinism`]** — same `meow.lock.jsonl` (→ same `ResolutionGraph`) + same projection ⇒ a **byte/structure-stable tree** (same paths, bytes, symlink targets, mode bits). Reproducible across machines (the core bet, CANON §1).
- **I-11 [`honesty`]** — materialize is a **compatibility escape hatch, not the default** and is documented as such; it widens the trust surface (plain real files any process can read/execute), so the capability story (I-8) governs only meow's own execution, not foreign tools — stated plainly, never overclaimed.

Tracing: `plan_ref` → PLAN §P2 (the ADR-4 coupling) + backlog `PKG-004`. `constitution_ref` → I-5, I-6, I-7, I-11 (CANON §12.2, §24.4, ADR-4).

## Acceptance criteria

Concrete, checkable Rust in `crates/pkg` (install modes are a PKG concern — PLAN subsystem map, CANON §12.2). All identifiers are the PKG-001 newtypes; every reachable failure is a typed `thiserror` enum — no path panics on a malformed archive, a missing edge, or a hostile member name (CRAFT Part B). Errors are causal and point at the fix (I-11).

### A1 — `meow_pkg::ResolutionGraph` is the single input (consumed, not redefined — PKG-003)

Materialize takes an already-built, already-validated `ResolutionGraph` (PKG-003's `.pnp`-equivalent: the reachable closure of `meow.lock.jsonl` rooted at the project's direct deps). It does **not** re-resolve, re-validate the closure, or touch the registry. Contract consumed (PKG-003, confirmed over `irc` — see Operator notes):

```rust
// Defined by PKG-003 in meow_pkg — referenced here, NOT redefined.
impl ResolutionGraph {
    pub fn assemble(lockfile: Arc<Lockfile>, root_deps: BTreeMap<PackageName, Version>) -> Result<Self, PnpError>;
    pub fn root_deps(&self) -> &BTreeMap<PackageName, Version>;
    pub fn lockfile(&self) -> &Arc<Lockfile>;
    pub fn packages(&self) -> impl Iterator<Item = ResolvedPackage<'_>>; // reachable closure ONLY
}
pub struct ResolvedPackage<'a> { pub name: &'a PackageName, pub version: &'a Version, pub integrity: &'a ContentHash, pub dependencies: &'a BTreeMap<PackageName, Version> }
```

`ResolvedPackage::integrity` (→ cache path) and `ResolvedPackage::dependencies` (→ the edge set). The same manifest is fed to `Resolver::new` (LOAD-003) and to the `Materializer` — one graph, two projections (I-5).

### A2 — Projection + options (`crates/pkg/src/materialize.rs`, new)

```rust
use std::path::{Path, PathBuf};
use crate::{Cache, ContentHash, PackageName, Version};
use crate::ResolutionGraph; // PKG-003

/// Which on-disk projection of the resolved graph to write. Both are projections of the SAME
/// `ResolutionGraph`; they differ only in (a) location and (b) default link strategy. PnP (no
/// projection at all) stays the default — these are the §24.4 escape hatch, never the norm.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Projection {
    /// `<root>/node_modules/` — compatibility escape hatch for tools that `stat()` packages
    /// (bundlers, native-addon toolchains, IDE plugins). Default link = symlink-into-store.
    NodeModules,
    /// `<root>/<vendor_dir>/` (default `vendor/`) — a self-contained full-COPY tree with no
    /// symlinks and no dependency on the global cache; git-committable for air-gapped deploys.
    Vendor,
}

/// How a dependency edge / package payload lands on disk.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LinkStrategy {
    /// Relative symlinks for edges; each package payload is written ONCE per (name,version)
    /// into the virtual store. Cheapest + smallest. Default for `NodeModules`.
    Symlink,
    /// Full file copies for every edge — no symlinks anywhere. Portable + git-committable,
    /// larger on disk, no global-cache dependency. Default for `Vendor`.
    Copy,
    /// Symlink where the filesystem supports it, else fall back to `Copy`. (Windows junctions
    /// are P5 hardening.) Deterministic GIVEN the resolved capability of the target FS.
    Auto,
}

#[derive(Debug, Clone)]
pub struct MaterializeOptions {
    pub projection: Projection,
    pub link: LinkStrategy,
    /// Remove a pre-existing tree before writing (default false → reconcile in place, A6).
    pub clean: bool,
    /// Vendor directory name relative to the project root (`Projection::Vendor` only).
    pub vendor_dir: PathBuf, // default "vendor"
}

impl MaterializeOptions {
    /// `node_modules/`, symlink edges. The default escape-hatch shape.
    pub fn node_modules() -> Self;
    /// `vendor/`, full-copy, self-contained.
    pub fn vendor() -> Self;
}
```

### A3 — The isolated (no-hoist) on-disk layout

Both projections produce a **pnpm-style isolated store** — each `(name, version)` materialized once under a virtual store dir, dependency edges projected per-package. **No hoisting / no flattening**: hoisting collapses versions and would make a foreign Node walker resolve a *different* version than meow's PnP graph, breaking `resolver-parity` (I-5). A flat/hoisted `node_modules` is therefore an explicit **non-goal** (confirmed with Main).

```text
node_modules/                                   # (or <vendor_dir>/ for Projection::Vendor)
  .meow/                                         # the virtual store (deterministic; pnpm's .pnpm analogue)
    is-odd@3.0.1/
      node_modules/
        is-odd/                                  # REAL package files, unpacked from the cached archive
          package.json
          index.js
        is-number -> ../../is-number@6.0.0/node_modules/is-number   # edge: relative symlink (or copy)
    is-number@6.0.0/
      node_modules/
        is-number/
          package.json
          index.js
    @scope+pkg@1.2.0/                            # scoped names: `/` escaped to `+` in the store key
      node_modules/
        @scope/pkg/                              # real package keeps its scoped path
          package.json
  is-odd -> .meow/is-odd@3.0.1/node_modules/is-odd        # top-level edge per ROOT dep
  @scope/pkg -> .meow/@scope+pkg@1.2.0/node_modules/@scope/pkg
```

Layout rules (all deterministic):
- **Store key** = `<escaped-name>@<version>` where `escaped-name` replaces `/` with `+` (`@scope/pkg` → `@scope+pkg@1.2.0`), keeping `.meow/` a single flat directory; the real package dir under it keeps the unescaped scoped path (`node_modules/@scope/pkg/`).
- **Package payload**: for every `ResolvedPackage`, the cached archive (gzip-tar, members under a `package/` prefix) is unpacked to `.meow/<key>/node_modules/<name>/`, stripping the `package/` prefix (A5).
- **Per-package edges**: for each `(dep, depVer)` in `dependencies`, create `.meow/<key>/node_modules/<dep>` pointing at `../../<dep-key>/node_modules/<dep>` (relative — portable, machine-independent). Scoped deps create the intermediate `@scope/` dir.
- **Top-level edges**: for each `(name, ver)` in `manifest.root_deps()`, create `<root-projection>/<name>` pointing at `.meow/<key>/node_modules/<name>`.
- A Node `node_modules` walker starting inside any package finds its sibling `node_modules/<dep>` (the per-package edge) at the exact version from that package's `LockEntry.dependencies` — so nested resolution and multi-version coexistence (A→B@1, C→B@2) match the PnP graph exactly.

### A4 — `Materializer` + deterministic `plan`/`materialize` (`materialize.rs`)

```rust
pub struct Materializer<'a> {
    cache: &'a Cache,
    manifest: &'a ResolutionGraph,
    project_root: &'a Path,
}

/// A fully-computed, disk-free description of the tree. PURE function of (manifest, options):
/// no I/O, no clock, no env. Serializing it deterministically yields `tree_hash`.
pub struct MaterializePlan {
    root: PathBuf,        // node_modules or <vendor_dir>, absolute
    nodes: Vec<PlanNode>, // sorted by `path` (byte order) → canonical, HashMap-iteration-order-free
}

pub struct PlanNode {
    pub path: PathBuf, // project-root-relative
    pub entry: PlanEntry,
    pub mode: u32,     // normalized: dir 0o755, file 0o644, exec 0o755
}

pub enum PlanEntry {
    /// Unpack the cached archive `integrity` to `path` (strip `package/`).
    Package { integrity: ContentHash, name: PackageName, version: Version },
    /// A dependency edge: `path` resolves to `target` (relative). Symlink, or a copy of `target`'s subtree.
    Edge { target: PathBuf },
}

impl MaterializePlan {
    /// Deterministic digest over the sorted (path, kind, integrity|target, mode) tuples. Same
    /// manifest + options ⇒ identical hash regardless of map iteration order. The determinism +
    /// idempotence oracle (reuses `ContentHash::of`).
    pub fn tree_hash(&self) -> ContentHash;
    pub fn root(&self) -> &Path;
    pub fn packages(&self) -> usize; // distinct (name,version)
    pub fn edges(&self) -> usize;
}

#[derive(Debug, Clone)]
pub struct MaterializeReport {
    pub root: PathBuf,
    pub tree_hash: ContentHash,
    pub packages: usize,
    pub edges: usize,
    pub bytes_written: u64,
    /// true iff an up-to-date tree already matched `tree_hash` and nothing was written (A6 idempotence).
    pub skipped: bool,
}

impl<'a> Materializer<'a> {
    pub fn new(cache: &'a Cache, manifest: &'a ResolutionGraph, project_root: &'a Path) -> Self;

    /// Compute the deterministic plan WITHOUT touching disk. The parity/determinism test oracle.
    /// Total: a manifest with a dangling edge (should be impossible post-PKG-003) is a typed
    /// `MaterializeError::DanglingEdge`, never a panic.
    pub fn plan(&self, opts: &MaterializeOptions) -> Result<MaterializePlan, MaterializeError>;

    /// Execute the plan. For each `Package`: `cache.read(&integrity)` (recompute+verify hash, I-7)
    /// → decode gzip-tar → write members under the store. For each `Edge`: symlink or copy per
    /// `opts.link`. Built into a temp sibling dir then `rename`d into place (PKG-001 `tmp_path`
    /// pattern) so a crashed run never leaves a half-tree a later tool would trust. Idempotent (A6):
    /// a tree already matching `plan.tree_hash()` is left untouched (`skipped: true`).
    pub fn materialize(&self, opts: &MaterializeOptions) -> Result<MaterializeReport, MaterializeError>;
}
```

### A5 — Streaming archive unpack (`crates/pkg/src/archive.rs`, new)

```rust
/// Decode a cached npm package archive (gzip-tar, members under a `package/` prefix) and write
/// each member under `dest`, stripping the prefix. The on-disk counterpart to LOAD-003's in-memory
/// `PackageFs::from_archive` (SAME archive grammar; this streams to disk, that buffers in memory —
/// overlap flagged for Main, Operator notes).
///
/// HARDENING (the P5-hardenable seam lives here):
/// - Rejects path-traversal / unsafe members: any normalized member path that escapes `dest`
///   (`..` segments, absolute paths) or is a tar symlink/hardlink/device entry → `UnsafeMember`.
/// - Normalizes mode bits (file 0o644, executable [tar mode & 0o111] → 0o755, dir 0o755) and mtime
///   to a fixed constant, so the tree is reproducible across machines + umasks (I-6).
/// - Does NOT execute any lifecycle script (no `postinstall`) — materialize writes files, runs nothing.
pub fn unpack_to(bytes: &[u8], dest: &Path) -> Result<UnpackStats, MaterializeError>;

pub struct UnpackStats { pub files: usize, pub bytes: u64 }
```

### A6 — Determinism, idempotence, atomicity (the behavior bar)

- **Determinism (I-6):** `Materializer::plan(opts)` is a pure function of `(ResolutionGraph, opts)` — `plan().tree_hash()` is identical across runs and machines; `nodes` are sorted by `path`, so neither `HashMap`/`BTreeMap` iteration nor filesystem order leaks in. Two `materialize` runs from the same lockfile produce trees with identical (path, bytes, symlink target, mode).
- **Idempotence (A6):** `materialize` first computes `plan().tree_hash()`; if the on-disk tree already matches (a sidecar `node_modules/.meow/.materialized` records the last `tree_hash` + projection), it writes nothing and returns `skipped: true`. Otherwise it reconciles: when `opts.clean`, the whole projection dir is removed first; when not, paths absent from the plan are removed and differing paths rewritten — converging on the planned tree either way. Running `materialize` twice ⇒ the second run is a no-op.
- **Atomicity:** the tree is assembled under a temp sibling (`<root>.meow-tmp-<pid>`) and `rename`d onto `<root>`; a crash mid-write never leaves a partially-populated `node_modules` that a foreign tool (or a stale-tree check) would treat as complete.
- **Integrity (I-7):** every package payload originates from `Cache::read(&integrity)`; a mismatch surfaces as `MaterializeError::Cache(CacheError::IntegrityMismatch{..})` and the run aborts with nothing committed (temp dir discarded) — the escape hatch refuses to write unverified bytes.
- **Parity (I-5):** the materialized tree is a faithful projection: a Node `node_modules` walk for any `(importer, specifier)` lands on the exact `(name, version)` meow's `Resolver::locate` returns (A3 guarantees it via no-hoist isolated edges). meow's own resolution is unchanged — still PnP, one resolver.

## Non-goals

- **Resolution / registry fetch / lockfile generation / cache population** — **PKG-002**. Materialize only *reads* an already-populated cache + an already-written lockfile.
- **The PnP in-memory loader + `ResolutionGraph` construction/validation** — **PKG-003**. Materialize *consumes* a built `ResolutionGraph`; it does not build, validate, or own the closure.
- **A second resolver / reading `node_modules` to run meow** — forbidden by I-5. The materialized tree is an *export for foreign tools*; meow's own `run`/`check`/`bundle` resolve via the one `meow_loader::Resolver` (LOAD-003). Materialize adds **zero** new resolution paths for meow.
- **Flat / hoisted `node_modules`** — explicit non-goal (breaks `resolver-parity`; confirmed with Main). The layout is strictly isolated/no-hoist.
- **VFS / FUSE mode (`--vfs`)** — separate install mode (CANON §12.2), not in this spec.
- **Root `package.json` / `tsconfig.json` projection** — **CFG-002** already owns the generated root manifests; materialize writes only the dependency tree, not the config shadows.
- **Running npm lifecycle scripts (`postinstall`, …) or building native addons (`node-gyp`)** — materialize writes files, runs nothing. The **hardened** materialized install (script policy, native-addon handling, Windows junction strategy, executable `.bin` shims) is **P5** ("hardened materialized install", PLAN §P5 / CANON §24.4).
- **Capability enforcement over the materialized files** — real files are plainly readable/executable by any process; capability scoping (I-8) governs meow's own execution, not foreign tools. Stated as an honest boundary, not silently implied.
- **Async I/O** — sync `std::fs` is sufficient for a CLI install step (matches PKG-001).

## Interface

- **Crate:** `crates/pkg` (extends PKG-001/PKG-003). New public surface: `Materializer`, `MaterializePlan`, `MaterializeReport`, `Projection`, `LinkStrategy`, `MaterializeOptions`, `MaterializeError`, and `archive::{unpack_to, UnpackStats}`.
- **Consumes (does NOT redefine):** `meow_pkg::{Cache, ContentHash, PackageName, Version, CacheError, tmp_path}` (PKG-001), `meow_pkg::{ResolutionGraph, ResolvedPackage, PnpError}` (PKG-003), `LockEntry.{integrity, dependencies}` (PKG-001).
- **Relationship to PKG-003's data (the ADR-4 coupling):** identical `ResolutionGraph` instance feeds both `Resolver::new(cache, m.lockfile().clone(), m.root_deps().clone(), root)` (LOAD-003 / PKG-003 runtime path) **and** `Materializer::new(cache, &m, root).materialize(..)` (this spec). One resolved graph; PnP is the in-memory projection, materialize/vendor are the on-disk projections (I-5).
- **CLI:** `meow install --materialize | --vendor [--vendor-dir DIR] [--copy] [--clean]` (A8), in `crates/cli`.
- **On-disk output:** `<root>/node_modules/` (isolated store + edges, A3) or `<root>/<vendor_dir>/` (same shape, full-copy). A `node_modules/.meow/.materialized` sidecar records the last `tree_hash` + projection for idempotence.
- **New crate deps:** a gzip decoder + tar reader for `archive::unpack_to` — **reuse whatever LOAD-003 already pulled in** (e.g. `flate2` + `tar`); add nothing new if the loader's choice is workspace-shareable (I-10 footprint). No other new deps.

## Implementation sketch

Extends `crates/pkg` (no new workspace member). New files: `src/materialize.rs`, `src/archive.rs`. Shared-file edits use the `// === PKG-004 ===` fence (P5 concurrency):

1. **`crates/pkg/src/lib.rs`** — fence: `mod materialize; mod archive;` + `pub use materialize::{Materializer, MaterializePlan, MaterializeReport, Projection, LinkStrategy, MaterializeOptions, MaterializeError};` and `pub use archive::{unpack_to, UnpackStats};`.
2. **`crates/pkg/src/materialize.rs`** (new) —
   - `plan`: walk `manifest.packages()` → for each, a `PlanEntry::Package` at `.meow/<key>/node_modules/<name>` and, for each `dependencies` edge, a `PlanEntry::Edge` with the relative target; append `manifest.root_deps()` top-level edges. Push all into `nodes`, **sort by `path`**, build `MaterializePlan`. `tree_hash` = `ContentHash::of` over the canonical serialization of the sorted nodes.
   - `materialize`: compute `plan`; short-circuit on the sidecar `tree_hash` match (`skipped`); else assemble under a `tmp_path`-style temp sibling — `Package` nodes via `cache.read` (I-7) → `archive::unpack_to`; `Edge` nodes via symlink (`std::os::unix::fs::symlink` / `std::os::windows::fs::symlink_dir`, `SymlinkUnsupported` on failure) or recursive copy per `opts.link` — then `rename` onto `<root>` and write the sidecar.
3. **`crates/pkg/src/archive.rs`** (new) — gzip+tar stream; per member: normalize path (reject escapes → `UnsafeMember`), strip `package/`, normalize mode + mtime, write. Returns `UnpackStats`.
4. **`crates/cli/src/cli.rs`** — fence `// === PKG-004 ===`: the new `InstallArgs` flags (A8) + the projection dispatch inside `cmd_install` (owned by PKG-002/003): after the manifest is built, if `--materialize`/`--vendor`, call `Materializer::materialize` and print the `MaterializeReport` (count, bytes, `skipped`). **Coordinate the `cmd_install` body with PKG-002/003 over `irc`** — PKG-004 only adds the post-resolve projection arm, not the resolve/lockfile-write itself.

CRAFT discipline: no `unwrap`/`panic!` on any archive/edge/FS path; borrow `&[u8]`/`&Path`; package payload written once per `(name,version)` (no redundant unpack); reuse PKG-001's atomic `tmp_path` + `ContentHash::of` rather than reinventing.

## Tests required

`crates/pkg/tests/materialize.rs` (integration) + unit tests in `materialize.rs`/`archive.rs`. Build a `Lockfile` + `ResolutionGraph` over synthetic gzip-tar archives `Cache::store`d into a temp `Cache::with_root`, materialize into a temp project root, and assert on the tree. Proves **I-5** [`resolver-parity`], **I-6** [`determinism`], **I-7** [`lockfile-integrity`]; honesty boundary documented (I-11). Floor: `cargo test/clippy/fmt`, `principles-check.sh`.

- **Determinism / byte-structure-stable tree (`determinism`, I-6):** `plan(opts).tree_hash()` is identical across repeated calls and independent of manifest insertion order; two full `materialize` runs (fresh dirs) produce trees with identical (path set, file bytes, symlink targets, mode bits). Property test over shuffled `(name, version)` dependency sets ⇒ stable `tree_hash`.
- **Idempotence (A6):** `materialize` twice into the same root ⇒ second run `skipped: true`, tree unchanged; after deleting one edge, a third run reconciles back to the planned tree.
- **Parity: materialized tree resolves the same packages as PnP (`resolver-parity`, I-5):** for a specifier corpus (the LOAD-003 corpus reused), assert a faithful Node `node_modules` walk over the materialized tree resolves each `(importer, specifier)` to the same `(name, version)` that `meow_loader::Resolver::locate` (constructed from the *same* `ResolutionGraph`) returns. Multi-version case (A→B@1, C→B@2): each importer's `node_modules/b` symlink targets its own version's store entry. Assert **no hoisting** (no top-level `node_modules/b` unless `b` is a root dep).
- **Integrity refusal (`lockfile-integrity`, I-7):** tamper a cached package blob after `store`; `materialize` ⇒ `MaterializeError::Cache(IntegrityMismatch)` and the destination root is **not** created/populated (temp discarded). Truncated archive ⇒ `InvalidArchive`, never a panic.
- **Hostile archive (red-team, archive.rs):** a tar member with `../escape`, an absolute path, or a symlink/device entry ⇒ `UnsafeMember`; nothing written outside `dest`. Garbage (non-gzip) bytes ⇒ `InvalidArchive`, no panic.
- **Vendor projection:** `Projection::Vendor` writes `<root>/vendor/` with `LinkStrategy::Copy` (no symlinks present in the tree) and is self-contained — resolving the corpus against the vendored tree succeeds with the global `Cache` root removed/unreadable (air-gap proof).
- **Scoped names:** `@scope/pkg` produces store key `@scope+pkg@<v>`, real dir `node_modules/@scope/pkg/`, and correct relative edges through the intermediate `@scope/` dir.
- **One-resolver invariant (I-5):** structural/assertion check that the materialize path imports `Cache`/`ResolutionGraph` only and constructs **no** `Resolver`; meow's resolution remains the single `meow_loader::Resolver`. The materialized `node_modules` is never read by any meow command in the test run.

GATES: `resolver-parity` (I-5 — parity test extends the LOAD-003 corpus fixture), `determinism` (I-6 — `tree_hash` stability), `lockfile-integrity` (I-7 — tamper refusal). Continuous touch: `footprint` (I-10 — no new heavy deps beyond LOAD-003's archive reader), `honesty` (I-11 — escape-hatch wording).

## Rollout

- **Additive.** Extends `crates/pkg`; no existing behavior changes. `meow install` without `--materialize`/`--vendor` stays pure PnP (PKG-003). No persisted production state.
- **Sequencing:** ships in P2 **with** PnP (ADR-4/§24.4), gated behind PKG-002 (cache populated) + PKG-003 (`ResolutionGraph`). The CLI dispatch arm is coordinated with PKG-002/003's `cmd_install` over `irc`.
- **Reversibility:** revert the `crates/pkg` `lib.rs` + `materialize.rs`/`archive.rs` and the `crates/cli` `// === PKG-004 ===` fence; PnP is unaffected. A materialized tree is a rebuildable artifact — `rm -rf node_modules vendor` (and re-run `meow install --materialize` to recreate). `node_modules`/`vendor` SHOULD be gitignored for `--materialize` (rebuildable, escape hatch); `vendor/` MAY be committed for air-gap (the project's choice) — documented, not forced.
- **Format evolution:** the `.materialized` sidecar carries `tree_hash` + projection + a small version int so a layout change invalidates stale trees cleanly.

- `FORK[PKG-004:layout]` isolated/pnpm-style **no-hoist** store (`.meow/<name>@<ver>/node_modules/<name>` + per-package symlink edges). - `FORK[PKG-004:link]` symlink-vs-copy default — chosen: `--materialize` defaults to **symlink** edges (cheapest, smallest, matches the shared-store intent); `--vendor` defaults to **copy** (portable, git-committable, no global-cache dependency). `--copy` forces copies for symlink-hostile filesystems; `SymlinkUnsupported` is a typed error pointing at `--copy`, never a silent copy. Confidence: medium.
- `FORK[PKG-004:vendor-self-contained]` vendor = **full self-contained copy** resolvable with the global `~/.meow/cache` absent (air-gap proof is a required test), at the cost of disk size + duplication. Confidence: medium.

Honest boundaries (I-11): materialize is a **compatibility escape hatch, not the default** — never marketed as the recommended mode. It widens the trust surface (plain real files any process reads/executes); capability scoping (I-8) governs only meow's own execution, not foreign tools — **stated, not implied**. The tree is a faithful projection of meow's graph, but a foreign tool implementing a *different* resolution (e.g. hoisting-dependent heuristics) may still diverge from meow — that is the tool's behavior, not a meow guarantee. No lifecycle scripts run and native addons are not built (P5: hardened materialized install). meow itself never reads the materialized tree (I-5: one resolver, PnP).
