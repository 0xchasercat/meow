## Motivation

P0's foundational exit is *"a trivial ESM file runs through V8"* (PLAN.md → Build sequence · P0 Foundations; Initial spec backlog · Wave 1 · RT-001; CANON §21 Phase 0). Everything downstream — type stripping (RT-003), the module loader (LOAD-001), Web globals (RT-004), the test runner's isolate-per-file model (CANON §16) — depends on a runtime crate that owns a V8 isolate, drives the event loop to completion (resolving top-level await), and exposes a registration seam so other subsystems contribute ops/extensions without re-embedding V8.

This is the single embedding chokepoint (CANON ADR-1, §6.2 Runtime). It traces to two invariants:

- **I-10 (small footprint; upstream V8).** V8 is consumed via *unmodified upstream* `deno_core`/`rusty_v8`, never forked, and the exact version is pinned (CANON §26.2, §24.8). `crates/runtime` is the only crate that touches `deno_core`; reaching for a different V8 binding or patching the upstream one is the violation this gate (`footprint`) exists to catch.
- **I-6 (determinism & hermeticity).** The embedding introduces *no ambient host reads* (CANON §1, CRAFT "Determinism & hermeticity are structural"). The only host boundary is the op seam, and at P0 the only op is `op_print` (stdout) plus reading the explicit entry file the user named. Env/clock/randomness gating is RT-006's job; here the posture is simply: this crate adds zero stray `std::env`/`SystemTime`/`Instant`/`rand` calls.

ADR-1 is *the* founding decision (V8 only, no engine abstraction); this spec is its first concrete realization.

## Acceptance criteria

Concrete and checkable. New crate `crates/runtime` (added to the existing Cargo workspace from DIST-001), consuming `deno_core.workspace = true` (the exact pin is owned by DIST-001's `[workspace.dependencies]`; I-10 — see Operator notes).

### A1 · Public surface (`crates/runtime/src/lib.rs`)

```rust
use std::rc::Rc;
use deno_core::{Extension, JsRuntime, ModuleId, PollEventLoopOptions, RuntimeOptions as DenoRuntimeOptions};
pub use deno_core::ModuleSpecifier;            // re-export (url::Url); callers do not depend on deno_core directly
pub use deno_core::v8;                          // re-export so v8::Global<v8::Value> is nameable without a direct dep

/// One V8 isolate + its event loop. Owns the embedding so no other crate touches `deno_core`.
/// NOT `Send`/`Sync`: `JsRuntime` is single-threaded — construct and drive on one thread with a
/// current-thread tokio runtime (see A5).
pub struct Runtime {
    js_runtime: JsRuntime,
}

/// Construction inputs. Deliberately minimal at P0 — the extension list is the registration seam (A4).
pub struct RuntimeOptions {
    /// Resolves + fetches modules. At P0 this is `TrivialModuleLoader` (A3); LOAD-001 replaces it
    /// with the real shared resolver. Required (no implicit default → no ambient fs authority).
    pub module_loader: Rc<dyn deno_core::ModuleLoader>,
    /// Subsystem-contributed ops/extensions (RT-002 async I/O, RT-004 globals, …). The crate's own
    /// `meow_runtime` extension (A4) is always prepended internally; callers never pass it.
    pub extensions: Vec<Extension>,
}

/// Typed, causal error surface. The runtime NEVER panics on user JS — every failure is one of these
/// and `Display`s as a diagnostic that names the cause (CRAFT "Diagnostics are a product surface").
#[derive(Debug, thiserror::Error)]
pub enum RuntimeError {
    #[error("failed to initialize the V8 runtime: {0}")]
    Init(String),
    #[error("module error for {specifier}: {source}")]
    Module { specifier: String, #[source] source: deno_core::error::CoreError },
    /// An uncaught JS exception — surfaced, never a Rust panic. `report` carries message + stack +
    /// source position and renders as a diagnostic.
    #[error("uncaught exception in {specifier}:\n{report}")]
    Uncaught { specifier: String, report: JsExceptionReport },
    #[error("event loop error: {0}")]
    EventLoop(#[source] deno_core::error::CoreError),
}

/// Structured form of a thrown JS value (not a stringly error). Built from `JsError`.
#[derive(Debug)]
pub struct JsExceptionReport {
    pub message: String,
    pub stack: Option<String>,
    pub file_name: Option<String>,
    pub line_number: Option<i64>,
    pub column_number: Option<i64>,
}
// impl std::fmt::Display for JsExceptionReport -> renders "<msg>\n  at <file>:<line>:<col>\n<stack>"
```

### A2 · Lifecycle methods

```rust
impl Runtime {
    /// Creates the isolate. Prepends the crate's `meow_runtime` extension to `options.extensions`.
    /// Initializes the V8 platform exactly once per process (A5). No host reads.
    pub fn new(options: RuntimeOptions) -> Result<Runtime, RuntimeError>;

    /// Non-module script eval; returns the completion value. Used for bootstrap snippets and tests.
    /// `name` is the synthetic source name shown in stack traces.
    pub fn execute_script(
        &mut self,
        name: &'static str,
        src: impl Into<deno_core::ModuleCodeString>,
    ) -> Result<v8::Global<v8::Value>, RuntimeError>;

    /// Loads `spec` as the main ESM module via the configured loader, evaluates it, and drives the
    /// event loop to completion — resolving top-level await and draining the microtask + macrotask
    /// queues. Returns `Ok(())` only after the loop is fully quiesced. Uncaught exceptions become
    /// `RuntimeError::Uncaught` (no panic).
    pub async fn run_main_module(&mut self, spec: &ModuleSpecifier) -> Result<(), RuntimeError>;

    /// Same as `run_main_module` but the source is supplied directly (no loader fetch). Satisfies the
    /// "evaluate an ESM module from a string" criterion; backs `execute_script`-style ESM tests.
    pub async fn run_main_module_from_source(
        &mut self,
        spec: &ModuleSpecifier,
        src: impl Into<deno_core::ModuleCodeString>,
    ) -> Result<(), RuntimeError>;

    /// Pumps the event loop until there is no more pending work. Public so RT-002 can interleave I/O.
    pub async fn run_event_loop(&mut self) -> Result<(), RuntimeError>;
}
```

Internally `run_main_module` does the canonical `deno_core` dance and MUST resolve the evaluation future *and* the loop, surfacing whichever fails first:

```rust
let id: ModuleId = self.js_runtime.load_main_es_module(spec).await /* -> Module{..} on err */;
let eval = self.js_runtime.mod_evaluate(id);
self.js_runtime.run_event_loop(PollEventLoopOptions::default()).await /* -> EventLoop / Uncaught */;
eval.await /* -> Uncaught on a thrown top-level value */;
```

### A4 · Op / extension registration seam (`crates/runtime/src/ext.rs` + `src/js/bootstrap.js`)

The registration pattern is idiomatic `deno_core`: a `Vec<Extension>` on `RuntimeOptions` plus the crate's own extension built with the `extension!`/`#[op2]` macros. (No bespoke `OpProvider` trait is introduced — that would be speculative generality over what `Extension` already is; CRAFT.)

```rust
deno_core::extension!(
    meow_runtime,
    ops = [op_print],
    esm_entry_point = "ext:meow_runtime/bootstrap.js",
    esm = [dir "src/js", "bootstrap.js"],
);

/// The ONLY host I/O op at P0 (the "hello op"): backs `console.log`/`console.error` so a trivial
/// program is observable. Synchronous, infallible write; the async I/O layer is RT-002.
#[op2(fast)]
fn op_print(#[string] msg: &str, is_err: bool);
```

`bootstrap.js` installs a minimal `globalThis.console` (`log`/`error` → `op_print`) and nothing else (no Web globals — RT-004). `Runtime::new` always prepends `meow_runtime::init_ops_and_esm()`; subsystem extensions append after it. A second test-only extension (an echo op, A-test) proves the seam round-trips JS↔Rust without shipping any capability.

### A5 · Process/threading correctness

- The V8 platform is initialized exactly once per process (guarded `std::sync::Once` around `JsRuntime::init_platform`, or rely on `deno_core`'s internal one — pick whichever the pinned version exposes and document it). Repeated `Runtime::new` on one thread must not double-init.
- `Runtime` is single-threaded by construction; `run_main_module` is driven on a current-thread tokio runtime. Document this on the type (it is not `Send`).

### A6 · CLI wiring — `meow run <file.mjs>` (fenced edit in `crates/cli`)

`meow run <path>` executes the file end-to-end (the P0 exit). Edit lands inside a balanced comment-marker fence in the existing CLI dispatch (DIST-001 created the skeleton):

```rust
// === RT-001 ===
// `meow run <file>`: canonicalize → file: URL → drive one ESM to completion through V8.
fn cmd_run(path: &std::path::Path) -> std::process::ExitCode {
    let rt = tokio::runtime::Builder::new_current_thread().enable_all().build()?;
    rt.block_on(async {
        let abs = std::fs::canonicalize(path)?;                 // explicit: the program the user named
        let spec = deno_core::resolve_path(&abs.to_string_lossy(), &std::env::current_dir()?)?;
        let mut runtime = meow_runtime::Runtime::new(meow_runtime::RuntimeOptions {
            module_loader: std::rc::Rc::new(meow_runtime::TrivialModuleLoader::new()),
            extensions: vec![],
        })?;
        match runtime.run_main_module(&spec).await {
            Ok(()) => std::process::ExitCode::SUCCESS,
            Err(e) => { eprintln!("{e}"); std::process::ExitCode::FAILURE }   // diagnostic, never a panic
        }
    })
}
// === /RT-001 ===
```

`meow run hello.mjs` where `hello.mjs` is `console.log("hello from meow")` MUST print `hello from meow` and exit `0`. An uncaught error in the file MUST print the diagnostic and exit non-zero — not panic / backtrace.

## Non-goals

- **No async / file / network I/O ops.** The only host I/O is the single synchronous `op_print` backing `console.log`. The async I/O layer (`tokio`, `io_uring`/`kqueue`/IOCP) is **RT-002**.
- **No real module loader or cache integration.** `TrivialModuleLoader` is a throwaway; the shared ESM resolver + content-addressed cache read is **LOAD-001** (I-1/I-5). No `node_modules`, no lockfile, no resolution algorithm here.
- **No TypeScript / type stripping.** ESM/JS only; `.ts` execution is **RT-003**.
- **No Web/WinterTC globals and no `meow:*` surface.** `fetch`/streams/`crypto` are **RT-004**; `meow:*` modules + generated types are **RT-005/I-9**. Only `console` exists.
- **No determinism harness.** Gating env/clock/randomness behind capabilities is **RT-006**; this spec only avoids *introducing* ambient reads.
- **No startup snapshot.** A V8 startup snapshot is a later cold-start optimization (no perf claim made now; I-11).
- **No `Send`/multi-isolate pooling, no isolate-per-test.** Test isolation is **TEST-001** (CANON §16).

## Interface

- **Crate:** `crates/runtime` (lib `meow_runtime`), `deno_core.workspace = true`, `thiserror.workspace = true`, `tokio.workspace = true` (current-thread, for tests). Added to the workspace `members` (DIST-001 owns the root manifest).
- **Rust API:** `Runtime`, `RuntimeOptions`, `RuntimeError`, `JsExceptionReport`, `TrivialModuleLoader`, re-exports `ModuleSpecifier`, `v8` — exactly as A1–A4.
- **CLI surface:** `meow run <file>` (A6). Output contract: program stdout on success + exit 0; rendered diagnostic on stderr + non-zero exit on any `RuntimeError`. No other CLI flags added.
- **Embedding invariant:** `crates/runtime` is the sole dependency edge to `deno_core`/`rusty_v8` in the workspace (asserted by the `footprint` gate / a workspace-dependency check).

## Implementation sketch

1. **Crate skeleton** — `crates/runtime/{Cargo.toml, src/lib.rs, src/loader.rs, src/ext.rs, src/error.rs, src/js/bootstrap.js}`. `Cargo.toml` uses workspace dep pins only (no version literals → single source, I-10).
2. **`Runtime::new`** — platform-init guard (A5); build `DenoRuntimeOptions { module_loader: Some(options.module_loader), extensions: [meow_runtime::init_ops_and_esm()].into_iter().chain(options.extensions).collect(), ..Default::default() }`; map any setup failure → `RuntimeError::Init`.
3. **Module run path** — `run_main_module` / `run_main_module_from_source` per A2. `from_source` uses `load_main_es_module_from_code(spec, code)`; the file path uses the loader. Convert `deno_core::error::JsError` → `JsExceptionReport` (message/stack/frame) → `RuntimeError::Uncaught` in `src/error.rs`. **No `unwrap`/`expect` on any path reachable from user JS** (CRAFT) — only on genuine internal invariants.
4. **Loader** (`src/loader.rs`) — `HashMap` of preloaded sources + a `file:` arm reading bytes once; unresolved → typed `ModuleLoaderError` with the specifier in the message.
5. **Extension + bootstrap** (`src/ext.rs`, `src/js/bootstrap.js`) — `extension!` macro, `#[op2(fast)] op_print`, minimal `console`.
6. **CLI wiring** — fenced `// === RT-001 ===` … `// === /RT-001 ===` block in `crates/cli` (A6). Fence MUST be balanced (`principles-check.sh`).

Comment-marker fences for shared-file edits: **`// === RT-001 ===`** (CLI dispatch in `crates/cli`).

## Tests required

In-crate integration/unit tests (`crates/runtime/tests/`), run via `cargo test --workspace`. They prove the invariants, not the plumbing (CRAFT "tests assert behavior").

- **T1 · trivial ESM runs end-to-end** (proves the P0 exit / I-6 happy path). Run `console.log("hello from meow")` as a main module; capture `op_print` output via a test print sink (inject a stdout buffer through the extension); assert the captured bytes == `"hello from meow\n"` and the run returns `Ok(())`. A second case drives `meow run` over a temp `.mjs` file (A6) and asserts exit code 0 + stdout. **Gate:** feeds `determinism` (happy path) and is the P0 `footprint`/foundations checkpoint.
- **T2 · op round-trip JS↔Rust** (proves the registration seam, A4). Register a test-only echo op via `RuntimeOptions.extensions`; an ESM module calls it with a value and `console.log`s the result; assert the value returned from Rust reaches JS unchanged. Proves a subsystem can add ops without re-embedding V8.
- **T3 · uncaught JS error → typed Rust error, no panic** (proves CRAFT "runtime never panics on user input" + diagnostics). Run a module that `throw new Error("boom")` and one with a top-level-await rejection; assert each returns `Err(RuntimeError::Uncaught { report, .. })` with `report.message` containing `"boom"` and a populated source position; assert the test process does not abort/panic (no `#[should_panic]`; the call returns `Err`). A syntax-error module asserts `RuntimeError::Module`.
- **T4 · top-level await resolves** (proves the loop is driven to completion). A module doing `await Promise.resolve()` then printing asserts the print happened before `run_main_module` returned `Ok(())`.
- **T5 · determinism posture — no ambient reads** (proves I-6 structurally). A test (or the `principles-check.sh` grep, referenced here) asserts `crates/runtime/src` contains no `std::env::var`, `SystemTime::now`, `Instant::now`, or `rand` call outside the V8/FFI seam. The full adversarial `determinism` gate is RT-006; this is the floor tripwire.

**Applicable gates:** `footprint` (I-10 — `crates/runtime` is the sole `deno_core`/`rusty_v8` edge, version pinned, unmodified upstream); `determinism` (I-6 — no ambient reads; RT-006 runs the adversarial form); `honesty` (I-11 — no perf/snapshot claims in code or strings).

## Rollout

- **Sequencing:** depends on DIST-001 (workspace + pinned `[workspace.dependencies]` for `deno_core`/`rusty_v8` + release build). Unblocks RT-002/RT-003/RT-004 and LOAD-001 (which replaces `TrivialModuleLoader`).
- **Flag:** none — `meow run` is new surface, not a behavior change to anything existing.
- **Reversibility:** fully reversible within scope. The CLI change is a single balanced `// === RT-001 ===` fence (revert = delete the fence and drop `meow run`); the crate is additive (revert = remove `crates/runtime` from workspace `members`). No persisted state, no migration, no external service.

## Operator notes

- **V8 binding pin (I-10).** The exact `deno_core` (and transitive `rusty_v8`) version is owned by **DIST-001** in the root `[workspace.dependencies]`; `crates/runtime` consumes it as `deno_core.workspace = true` so there is one source of truth and no drift. The pin MUST be an exact `=x.y.z` from crates.io (unmodified upstream — **never** a git/fork source; CANON §26.2). **[ASSUMPTION]** at drafting time the intended pin is the latest stable `deno_core` line (≈ `deno_core 0.3xx` / `rusty_v8 1xx`); confirm and copy DIST-001's actual chosen value before implementing — do not invent a number that diverges from DIST-001.
- **Honest boundary — building V8 needs the network (flag to Main).** Compiling this crate pulls `rusty_v8`'s **prebuilt static V8 library over the network** (Deno publishes the multi-platform binaries; that is exactly why we consume upstream — no V8-from-source in CI, `cargo build` under a minute, CANON §24.8). If that artifact is **unavailable in the build/CI environment** (offline, blocked egress, or a platform Deno does not publish), the build cannot complete. That is a **`needs-input` (provision V8 / allow the `rusty_v8` download or set `RUSTY_V8_MIRROR`)**, **NOT** a stub, a fake, or a fork. Per the completeness contract this is the legitimate "missing prerequisite" case: state it plainly, implement everything else, and do not paper over it with a mock V8.
- **Minor fork resolved (logged here, not in decisions.json — Main consolidates):** the op-registration seam is the plain `Vec<Extension>` + `extension!`/`#[op2]` idiom rather than a bespoke `OpProvider` trait. Rationale: `Extension` already *is* the registration unit; a wrapper trait would be speculative generality (CRAFT). If a later subsystem needs richer per-extension metadata, introduce the trait then.
- **No snapshot / no perf claim (I-11).** A V8 startup snapshot is intentionally deferred; no doc, string, or comment in this change may claim a cold-start number — there is no benchmark behind one yet.
