## Motivation

P1's exit is *"a small TS web server runs with no emitted JS; behavior is identical across two machines on the same version+lockfile"* (PLAN.md → *Build sequence · P1 Minimal Runtime*; backlog *Wave 2 · RT-004*). A web server needs the Web-standard globals it is written against. CANON §8.1 fixes exactly which ones for P1 — the **"Stateless Edge" subset (Q7, resolved → CANON §8.1, §27 Q7)**: `fetch`, `Request`/`Response`, `Headers`, `URL`/`URLPattern`, `console`, `crypto.subtle`, `TextEncoder`/`TextDecoder`, `AbortController`, `Blob`, `FormData`, `setTimeout` (streaming body types arrive alongside `fetch`). Explicitly **no** DOM, `window`, or `localStorage`.

This is the `strict-web` default surface (PRODUCT.md lexicon — `strict-web` is the default *mode*; these are its ambient globals). It traces to two invariants:

- **I-6 (determinism & hermeticity).** The only global here that touches the host is `fetch` (network). It MUST flow through the single capability seam RT-002 established (`CapabilityCheck` in `OpState`) — there is no second, ungoverned path from JS to the network (CANON §1, CRAFT *"Determinism & hermeticity are structural"*). Clock (`setTimeout` timing, `performance.now`) and randomness (`crypto.getRandomValues`) gating is **RT-006's** job; RT-004's posture is: introduce no *ungoverned* host authority and wire `fetch`'s gate onto the existing seam.
- **I-9 (runtime types are generated / no hand-maintained drift).** Every meow-visible TS surface ships types. These globals are **Web-standard, not a `meow:*` module**, so their `.d.ts` is *curated from the upstream WHATWG/WinterTC declarations and conformance-checked*, not generated from Rust — the *generate-from-impl* mechanism (`meow types` + `types-fresh`) is reserved for `meow:*` surfaces and is **RT-005's** scope. RT-004 honors I-9 by shipping types at all and naming this boundary honestly (confirmed with peer `RT005` over IRC: RT-004 = ambient Web-global types, curated; RT-005 = generated `meow:*` module types; no overlap).

**Strategy decision (CRAFT *"reuse the ecosystem we bet on"*, I-10 *upstream, unmodified*).** Do **not** hand-roll WHATWG. `deno_core` already exposes these as the unmodified upstream extension crates — `deno_webidl`, `deno_console`, `deno_url`, `deno_web`, `deno_crypto`, `deno_fetch` — co-versioned with the `deno_core` pin RT-001 consumes. Wiring those is both the ecosystem-reuse choice *and* the I-10 *unmodified-upstream* choice. Hand-rolling `URL`/`Headers`/`SubtleCrypto` would be the "hand-roll of a solved problem" craft symptom. The cost (footprint — `deno_fetch` pulls a hyper/rustls HTTP client) is the one honest tension; it is handled as a flagged boundary + a contingency, not hidden (see Operator notes).

## Acceptance criteria

Concrete and checkable. RT-004 adds a `web` module to the RT-001-owned `crates/runtime`, assembles the ordered upstream extensions, adapts `fetch`'s permission hook onto the RT-002 seam, ships the ambient `.d.ts`, and wires the extensions into `meow run`. All upstream extension/option/trait spellings track the pinned `deno_core 0.403` co-versioned extension set; exact attribute/field names are `[INFERENCE]` confirmed against that pin at implementation time.

### A1 · Web-extension assembly (`crates/runtime/src/web/mod.rs`)

The single entry the CLI (and later the test runner) calls to obtain the Stateless-Edge globals as a `Vec<Extension>` to append to RT-001's `RuntimeOptions.extensions` (the registration seam from RT-001 A4):

```rust
use std::rc::Rc;
use std::sync::Arc;
use deno_core::Extension;

/// Inputs needed to stand up the Web globals.
pub struct WebOptions {
    /// The RT-002 network/host gate. `fetch`'s permission hook (A3) delegates here —
    /// the SAME `Rc<dyn CapabilityCheck>` RT-002 stores in `OpState`, so network has
    /// one governed entry (I-6/I-8). At P1 the default is RT-002's `AllowAll`
    /// (enforcement is P6 SEC-001); the seam is wired now.
    pub caps: Rc<dyn crate::io::CapabilityCheck>,
    /// `User-Agent` the fetch client sends. Fixed string (no host read) — e.g. "meow/<version>".
    pub user_agent: String,
}

/// Build the ordered Stateless-Edge extension list (CANON §8.1). Order is load-bearing:
/// deno_webidl → deno_console → deno_url → deno_web → deno_crypto → deno_fetch
/// (each depends on the ones before it). Caller appends RT-002's `meow_io` and RT-001's
/// `meow_runtime` is already prepended by `Runtime::new`.
pub fn extensions(opts: WebOptions) -> Vec<Extension>;
```

`extensions()` MUST construct each upstream extension with `init_ops_and_esm()` (NOT `init_ops()` — RT-001 ships no V8 startup snapshot, so the extensions' JS must be evaluated at runtime init; the cold-start cost of no-snapshot is an honest boundary, not a perf claim — Non-goals/Operator notes). Concretely (illustrative; spelling tracks the pin `[INFERENCE]`):

```rust
vec![
    deno_webidl::deno_webidl::init_ops_and_esm(),
    deno_console::deno_console::init_ops_and_esm(),
    deno_url::deno_url::init_ops_and_esm(),
    deno_web::deno_web::init_ops_and_esm::<WebTimers>(
        Arc::new(deno_web::BlobStore::default()),
        None, // maybe_location: no document base URL (no window) — I-6, no ambient origin
    ),
    deno_crypto::deno_crypto::init_ops_and_esm(None), // seed=None at P1; RT-006 wires the hermetic seed
    deno_fetch::deno_fetch::init_ops_and_esm::<WebFetchPermissions>(deno_fetch::Options {
        user_agent: opts.user_agent,
        ..Default::default()       // default hyper/rustls client; no proxy, no cert overrides
    }),
]
```

The `caps` handle is threaded into `OpState` so A3's permission adapter can read it (it is the same value RT-002's `install_io` stores; RT-004 reuses it rather than introducing a second copy). `WebTimers`/`WebFetchPermissions` are zero/Rc-sized state types placed in `OpState` via the extension's `state`/`op_state_fn` closure.

### A3 · Fetch permission adapter onto the RT-002 seam (`crates/runtime/src/web/perms.rs`)

`fetch`'s network gate is the *single* governed seam — RT-002's `CapabilityCheck`, reusing its existing `CapRequest::NetConnect(&str)` (no new capability variant; the URL host\[:port] is the connect target):

```rust
/// Adapts deno_fetch's permission trait onto RT-002's capability seam. Network is a capability
/// (I-8); the check happens BEFORE any socket is opened. At P1 `caps` is `AllowAll` (seam, not
/// enforcement — SEC-001/P6); the wiring is what matters for I-6 (one governed network entry).
pub struct WebFetchPermissions {
    pub caps: Rc<dyn crate::io::CapabilityCheck>,
}

impl deno_fetch::FetchPermissions for WebFetchPermissions {
    fn check_net_url(&mut self, url: &deno_core::url::Url, _api: &str)
        -> Result<(), /* deno_permissions::PermissionCheckError [INFERENCE] */ FetchPermError>
    {
        let host = url.host_str().unwrap_or_default();
        let target = match url.port_or_known_default() {
            Some(p) => format!("{host}:{p}"),
            None => host.to_string(),
        };
        self.caps
            .check(&crate::io::CapRequest::NetConnect(&target))
            .map_err(FetchPermError::from) // CapDenied → a permission error → JS rejection, never a panic
    }

    /// `file:` fetch is OUT of scope at P1 (filesystem read via fetch). Deny with a diagnostic
    /// that names the boundary, rather than silently reading the disk (I-6, CRAFT diagnostics).
    fn check_read(&mut self, _path: &std::path::Path, _api: &str)
        -> Result<std::path::PathBuf, FetchPermError>
    { Err(FetchPermError::FileFetchUnsupported) }
}
```

Behavior contract: a `fetch(url)` whose host the seam **denies** rejects the JS promise with a `TypeError`/permission error (no Rust panic — CRAFT *"runtime does not panic on user input"*). With the P1 default (`AllowAll`) the request proceeds. The bytes themselves flow through `deno_fetch`'s own hyper/rustls client — **not** RT-002's `op_tcp_connect`/`io_uring` path; the seam is the *authorization* gate, not the transport (honest boundary — Operator notes). No `unwrap`/`expect` on any path reachable from user JS.

### A4 · `console` — keep RT-001's, do not double-install

`console` already exists (RT-001 A4 installs `globalThis.console` → `op_print`). `deno_console` is pulled here only because `deno_web`/`deno_fetch` depend on its *inspect/formatting* infrastructure — RT-004 MUST NOT let it install a second, competing `console` global over RT-001's. The assembly either (a) omits `deno_console`'s console-installing ESM if the pin allows ops-only init, or (b) lets `deno_console` provide the richer WHATWG `console` and RT-001's minimal one is superseded — **decision: keep RT-001's `console` as the installed global** (its single-stdout-op shape is the determinism-friendly one; RT-002/RT-001 own that op). This is a coordination point with peer `RT001` (fenced edit, A6) — confirm the no-collision shape before wiring.

### A5 · Ambient global type declarations (`crates/runtime/src/web/lib/strict-web.d.ts`)

The Stateless-Edge globals ship native TS types as a **lib-style ambient declaration file** — `declare`d `globalThis` members, *no import* (peer `RT005` confirmed: RT-004 = ambient globals, RT-005 = `meow:*` modules):

```ts
// strict-web ambient globals (CANON §8.1). Curated from the upstream WHATWG/WinterTC
// declarations + Deno's own .d.ts for the wired extensions; conformance-checked, NOT
// generated from Rust (I-9 generate-from-impl applies to meow:* — RT-005). Marks the
// committed P1 subset; types are scoped to exactly the Stateless-Edge set, even where the
// runtime exposes more transitively (see Non-goals / honest boundary).
declare var fetch: typeof globalThis.fetch;
declare var Request: typeof globalThis.Request;
declare var Response: typeof globalThis.Response;
declare var Headers: typeof globalThis.Headers;
declare var URL: typeof globalThis.URL;
declare var URLPattern: typeof globalThis.URLPattern;
declare var TextEncoder: typeof globalThis.TextEncoder;
declare var TextDecoder: typeof globalThis.TextDecoder;
declare var AbortController: typeof globalThis.AbortController;
declare var AbortSignal: typeof globalThis.AbortSignal;
declare var Blob: typeof globalThis.Blob;
declare var FormData: typeof globalThis.FormData;
declare var crypto: Crypto;            // SubtleCrypto via crypto.subtle (digest/sign/verify/…)
declare function setTimeout(handler: (...a: any[]) => void, timeout?: number, ...args: any[]): number;
declare function clearTimeout(id?: number): void;
// + the minimal interface bodies these reference (Request/Response/Headers/URLPattern/Crypto/SubtleCrypto)
```

The decl file is shipped inside the `meow` binary's resource set and resolved to a stable on-disk path the typecheck program can reference.

(Decision: `compilerOptions.types` pointing at the shipped decl, over a `typeRoots` scan — `types` is the precise, single-file inclusion; `typeRoots` would invite ambient scanning. ### A7 · CLI wiring — `meow run` gets the globals (`// === RT-004 ===` in `crates/cli`)

Inside the existing `meow run` dispatch (RT-001 A6 fence; RT-002 also fences here), append the Web extensions to `RuntimeOptions.extensions`:

```rust
// === RT-004 ===
let mut exts = meow_runtime::web::extensions(meow_runtime::web::WebOptions {
    caps: caps.clone(),                       // the same Rc<dyn CapabilityCheck> RT-002 installs
    user_agent: format!("meow/{}", env!("CARGO_PKG_VERSION")),
});
extensions.append(&mut exts);
// === /RT-004 ===
```

`meow run server.ts` where `server.ts` constructs `new URL(...)`, `new Response(...)`, calls `crypto.subtle.digest`, and (capability-gated) `fetch`, MUST execute end-to-end through V8 and exit 0; an uncaught error renders the RT-001 diagnostic and exits non-zero — never a panic.

## Non-goals

- **No DOM, `window`, `localStorage`, `document`, `navigator`, history/storage.** These were never in `deno_web`/`deno_fetch`/`deno_url`/`deno_crypto` (deno adds them in its *runtime bootstrap*, which RT-004 does **not** pull) — so the wired surface excludes them by construction (CANON §8.1). RT-004 must not add them.
- **No committed full WHATWG streams beyond fetch bodies.** `ReadableStream`/`WritableStream`/`TransformStream` arrive *transitively* with `deno_web` and back `fetch`/`Response` bodies (that is the in-scope use). They are **not** part of the P1 *committed, typed, conformance-tested* subset — `strict-web.d.ts` does not export them as a promise, and no test asserts the full stream surface. Honest boundary (Operator notes): runtime presence ⊇ committed subset.
- **No `WebSocket`.** Later (CANON §8.1 full target lists it; not Phase-1).
- **No `EventTarget`/`structuredClone`/`queueMicrotask`/`atob`/`btoa`/`performance` as committed surface.** Some ship transitively with `deno_web`; like streams they are present-but-uncommitted and untyped here.
- **No randomness or clock gating.** `crypto.getRandomValues`/`randomUUID` (randomness) and `setTimeout` timing / `performance` (clock) are determinism levers; gating them behind capabilities is **RT-006** (`determinism` adversarial gate). RT-004 wires the globals and the `fetch` gate only; it must claim no determinism property over clock/randomness.
- **No capability *enforcement*.** The `fetch` seam defaults to allow (RT-002 `AllowAll`); real tiered enforcement is **SEC-001/P6** (I-8). RT-004 must not describe `fetch` as "sandboxed"/"blocked" (I-11, CRAFT cardinal sin).
- **No `meow:*` surface and no type *generation*.** `meow:http`/`meow:fs` and the generate-from-impl `meow types` step + `types-fresh` gate are **RT-005** (I-9). RT-004 ships *curated* ambient Web-global types only.
- **No hand-rolled WHATWG.** Reuse the upstream extensions; reimplementing `URL`/`Headers`/`SubtleCrypto` is a craft block (CRAFT, I-10).
- **No V8 startup snapshot.** Snapshotting the extension ESM for faster cold start is a later optimization (no perf claim now — I-11).

## Implementation sketch

1. **`Cargo.toml`** — add the six `deno_*` extension crates as `*.workspace = true` (DIST-001 owns the pins; they MUST be the version set matching `deno_core 0.403`). No version literals.
2. **`src/web/perms.rs`** — `WebTimers` (`allow_hrtime → false`), `WebFetchPermissions` (delegates `check_net_url` → `CapRequest::NetConnect`; `check_read` → `FileFetchUnsupported`), and `FetchPermError` (`thiserror`, `From<CapDenied>`, conforming to deno's error-class trait so it surfaces as a JS exception — `[INFERENCE]` exact trait tracks the pin).
3. **`src/web/mod.rs`** — `WebOptions`; `extensions()` builds the ordered vec with `init_ops_and_esm()` and threads `caps` into `OpState` (reusing the value RT-002 installs — do not store a second copy). Build the default `deno_fetch` client (hyper/rustls) via `deno_fetch::Options { user_agent, ..Default::default() }`.
4. **`src/web/lib/strict-web.d.ts`** — curate the ambient decls for exactly the §8.1 set from the upstream WHATWG/Deno `.d.ts`; conformance is the type-level test (T-types). Shipped as a binary resource at a stable path.
5. **`src/lib.rs`** — `// === RT-004 ===` fence adding `pub mod web;`.
6. **`crates/cli`** — `// === RT-004 ===` fence appending `web::extensions(...)` to `RuntimeOptions.extensions` (A7); coordinate with RT-001/RT-002 fences in the same dispatch.
7. **`crates/config/src/shadow.rs`** — `// === RT-004 ===` fence adding `compilerOptions.types: [<strict-web.d.ts path>]` to the generated shadow tsconfig (A6); keep it inside CFG-001's deterministic serialization so the file stays byte-stable.

`unsafe`: none introduced (the V8/FFI `unsafe` lives in `deno_core`/`rusty_v8`; this layer is safe glue — CRAFT). No ambient host reads added in Rust (`user_agent` is a build-time constant, not an env read — I-6).

## Tests required

Behavior, not plumbing (CRAFT). Integration tests run from JS via `meow run` over temp files (`crates/runtime/tests/web_*.rs`), proving each shipped global is spec-conformant and that the host-touching one is seam-gated.

- **`web_url`** — `new URL("https://h.example/p?a=1&a=2#x").searchParams.getAll("a")` ⇒ `["1","2"]`; `new URLPattern({pathname:"/u/:id"}).exec("https://h/u/42").pathname.groups.id` ⇒ `"42"`. *Proves: `URL`/`URLPattern` conform.*
- **`web_text_codec`** — `new TextDecoder().decode(new TextEncoder().encode("héllo"))` ⇒ `"héllo"` (UTF-8 round-trip, multibyte). *Proves: `TextEncoder`/`TextDecoder`.*
- **`web_crypto_subtle`** — `crypto.subtle.digest("SHA-256", new TextEncoder().encode("abc"))` ⇒ the known digest `ba7816bf…f20015ad` (assert hex). *Proves: `crypto.subtle` (deterministic; no randomness involved).*
- **`web_response_body`** — `await new Response("hi").text()` ⇒ `"hi"`; `new Headers({a:"b"}).get("a")` ⇒ `"b"`; `new Request("https://h/").method` ⇒ `"GET"`. *Proves: `Request`/`Response`/`Headers` + a fetch body type.*
- **`web_blob_formdata`** — `await new Blob(["xy"]).text()` ⇒ `"xy"`; a `FormData` with one field round-trips via `Request` body / `.get`. *Proves: `Blob`/`FormData`.*
- **`web_set_timeout`** — `await new Promise(r => setTimeout(r, 1))` resolves under `run_main_module` (the macrotask drains before the loop quiesces). *Proves: `setTimeout` integrates with the event loop.*
- **`web_fetch_allowed`** — bind a `tokio::net::TcpListener` on `127.0.0.1:0` serving `200 "pong"`; with the default `AllowAll` cap, `await (await fetch("http://127.0.0.1:<port>/")).text()` ⇒ `"pong"`. *Proves: `fetch` works end-to-end against a real server.*
- **`web_fetch_denied`** (the I-6/seam invariant) — install a recording `CapabilityCheck` that denies `NetConnect`; assert `fetch(...)` rejects with a permission/`TypeError` (not a Rust panic/abort) **and** the recorder saw exactly one `CapRequest::NetConnect` with the right host:port — i.e. the gate is *on the path before any socket*. *Proves: network has one governed entry (I-6 posture; pre-stages the P6 `capability` gate).*
- **`web_fetch_abort`** — `AbortController` whose `signal` aborts an in-flight `fetch` rejects with an `AbortError` (no panic). *Proves: `AbortController` + fetch integration.*
- **`web_no_dom`** — assert `typeof window === "undefined"` and `typeof document === "undefined"` and `typeof localStorage === "undefined"`. *Proves: the §8.1 "no DOM/window" boundary holds — guards against a later dependency dragging them in.*
- **`T-types` (type-level)** — a `.ts` fixture using every committed global typechecks under the generated shadow tsconfig (run `meow check`/`tsgo` over it); a use of a *non*-committed/removed symbol fails. *Proves: the ambient `.d.ts` is wired into the program and scoped to the committed subset (I-9 honest typing).*

**Applicable gates:** `determinism` (I-6 — `fetch` traverses the single seam; no ungoverned network path; clock/randomness explicitly deferred to RT-006, so the surface claims none); `types-fresh` (I-9 — types exist and are scoped; the *generation* mechanism is RT-005, so RT-004's audit point is that the curated decls match the wired runtime surface and claim no generation); `honesty` (I-11 — no string/comment/doc claims `fetch` is sandboxed/blocked at P1, no perf/cold-start claim, no "full streams" claim); `footprint` (I-10 — the added crates are unmodified upstream, pinned via DIST-001; re-measure the binary-size probe, see Operator notes).

## Rollout

- **Sequencing:** depends on RT-001 (the `RuntimeOptions.extensions` seam + `Runtime`). Consumes RT-002's `CapabilityCheck`/`CapRequest::NetConnect` (merged) for the `fetch` gate, and extends CFG-001's shadow tsconfig (merged) for types. Unblocks RT-005 (`meow:http serve` reuses these `Request`/`Response`/`Headers` as ambient globals) and is on the P1 web-server exit path.
- **Flag:** none — new ambient surface, not a behavior change to existing globals (`console` unchanged). If footprint forces the contingency (below), `fetch` lands behind a default-on `web-fetch` cargo feature so the lighter globals can ship without the HTTP client.
- **Reversibility:** fully reversible within scope. Revert = delete `crates/runtime/src/web/`, the three `// === RT-004 ===` fences (`lib.rs`, `crates/cli`, `crates/config/src/shadow.rs`), and the six `deno_*` `Cargo.toml` deps. The shadow tsconfig regenerates without the `types` entry. No persisted state, no migration, no external service.

## Operator notes

- **Honest boundary — runtime surface ⊇ committed subset.** Wiring `deno_web` brings `ReadableStream`/`WritableStream`/`TransformStream`, `EventTarget`, `structuredClone`, `queueMicrotask`, `atob`/`btoa`, `performance`; `deno_crypto` brings `crypto.getRandomValues`/`randomUUID`. These are *present at runtime* but **not** part of the P1 committed/typed/tested subset — `strict-web.d.ts` covers only CANON §8.1, and no test or doc promises the extras. We do not strip them out (that would mean patching upstream — an I-10 violation); we scope the *promise* to the committed set and say so. Streams beyond fetch bodies, EventTarget, structuredClone → later specs.
- **Honest boundary — the `fetch` seam gates authorization, not transport.** `deno_fetch` uses its own hyper/rustls client; bytes do **not** flow through RT-002's `op_tcp_connect`/`io_uring` path. The single governed gate is the `check_net_url` permission hook (one network entry — satisfies I-6's *governed-entry* posture). No code/comment may imply RT-002's I/O accelerant backs `fetch`.
- **Honest boundary — capability is a seam, not enforcement.** At P1 the default cap is RT-002's `AllowAll`; `fetch` is *not* sandboxed. Enforcement is SEC-001/P6 (I-8). Forbidden to describe `fetch` as "blocked"/"sandboxed" (I-11, CRAFT cardinal sin).
- **Honest boundary — no snapshot ⇒ extension ESM evaluates at startup.** Cold start carries the cost of loading the extensions' JS each run. This is a known later optimization (snapshot); **no** doc/string/comment may state a startup number (I-11).
