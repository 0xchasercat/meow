## Motivation

CANON Amendment 001 is explicit: `package.json` is the authority for dependencies, scripts, workspaces, and project metadata; `meow` reads it and never owns/generates/clobbers it. CFG-002 inverted that rule by making `meow.config` the dependency + metadata source and projecting an owned root `package.json`. That is now constitutionally wrong and blocks the 5-minute test (`cd existing-project && meow install && meow run dev` with zero file edits).

CFG-003 is the clean cutover for the first drop-in domino. It removes the `meow.config` dependency surface entirely, retires the CFG-002 package.json projection/doctor ownership path, and rewires the runtime/install/why-dep roots to the user-owned root `package.json`. This traces directly to PLAN `P2.5 · Drop-In Core` and its exit gates: `drop-in` (stock project install+run) and `resolver-parity` (same roots feed the one resolver, no `node_modules`).

## Acceptance criteria

Every reachable failure stays typed (`ConfigError` or existing typed downstream errors); no `unwrap`/`expect`/`panic!` on user `package.json` bytes. No new crate dependency.

### A1 — `MeowConfig` becomes runtime-only (`crates/config/src/schema.rs`, `crates/config/src/lib.rs`)

`MeowConfig` no longer carries any package authority:

- delete `dependencies: BTreeMap<PackageName, VersionReq>`.
- delete CFG-002's `Publish` struct and `publish: Publish` field.
- `meow-config` no longer exports `Publish`, `generate_root_package_json`, `render_root_package_json`, `classify_root_package_json`, `PackageJsonStatus`, or `PACKAGE_JSON_MARKER`.
- shared-file edits are fenced `// === CFG-003 ===`.

Consequence: a legacy `meow.config.json` containing `dependencies` or `publish` now fails `deny_unknown_fields` parsing honestly instead of being silently ignored. That is the intended clean cutover: no dual authority.

### A2 — New `package.json` reader (`crates/config/src/package_json.rs`)

Add a new module:

```rust
use meow_pkg::{PackageName, VersionReq};
use std::collections::BTreeMap;
use std::path::Path;

#[derive(Debug, Clone, PartialEq, Eq, Default, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct PackageJson {
    #[serde(default)] pub name: Option<String>,
    #[serde(default)] pub version: Option<String>,
    #[serde(default)] pub dependencies: BTreeMap<PackageName, String>,
    #[serde(default)] pub dev_dependencies: BTreeMap<PackageName, String>,
    #[serde(default)] pub peer_dependencies: BTreeMap<PackageName, String>,
    #[serde(default)] pub scripts: BTreeMap<String, String>,
    #[serde(default)] pub workspaces: Option<PackageJsonWorkspaces>,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(untagged)]
pub enum PackageJsonWorkspaces {
    Patterns(Vec<String>),
    Config(PackageJsonWorkspaceConfig),
}

#[derive(Debug, Clone, PartialEq, Eq, Default, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct PackageJsonWorkspaceConfig {
    #[serde(default)] pub packages: Vec<String>,
    #[serde(default)] pub nohoist: Vec<String>,
}

impl PackageJson {
    pub fn read(root: &Path) -> Result<PackageJson, ConfigError>;
    pub fn direct_dependencies(&self) -> Result<BTreeMap<PackageName, VersionReq>, ConfigError>;
}
```

Rules:

- every field above is `#[serde(default)]`.
- **no** `deny_unknown_fields`; stock `package.json` files routinely carry extra keys.
- `read(root)` reads `root/package.json`.
  - missing file => `ConfigError::PackageJsonNotFound(path)`.
  - malformed JSON / wrong typed field (`dependencies: []`, `scripts: 3`, etc.) => `ConfigError::PackageJsonParse { path, source }`.
- `direct_dependencies()` merges `dependencies` then `devDependencies` into the `resolve_roots` input shape (`&BTreeMap<PackageName, VersionReq>`).
  - parse each string through `VersionReq::parse`.
  - unsupported specifier => `ConfigError::UnsupportedDependencySpecifier { name, spec, source }` with a message shaped like `unsupported dependency specifier <name>: <spec> — lands in a later slice`.
  - same package declared in both `dependencies` and `devDependencies` with different specifiers => `ConfigError::ConflictingDependencySpecifier { ... }` (single root map would otherwise be ambiguous).
  - `peerDependencies` are read/stored but are **not** roots in CFG-003.

### A3 — `package.json` mutation helpers (`crates/config/src/deps.rs`)

Rewrite the persistence helpers to mutate the user-owned root `package.json`:

```rust
pub fn add_dependency(root: &Path, name: PackageName, req: VersionReq) -> Result<PackageJson, ConfigError>;
pub fn remove_dependency(root: &Path, name: &PackageName) -> Result<PackageJson, ConfigError>;
```

Behavior:

- mutate only the top-level `dependencies` object.
- preserve every other top-level field/value.
- write 2-space pretty JSON with a trailing newline.
- sort dependency keys alphabetically.
- `add_dependency` creates a minimal root object when `package.json` is missing.
- `remove_dependency` on missing `package.json` is a typed `PackageJsonNotFound` error.
- if the root is not a JSON object or `dependencies` exists but is not an object, fail with a typed `ConfigError` (`PackageJsonRootMustBeObject` / `PackageJsonFieldMustBeObject`).

`write_json_config` is retired.

### A4 — CLI cutover (`crates/cli/src/cli.rs`)

Fence the shared-file edits with `// === CFG-003 ===`.

`meow sync`
- keep `.meow/tsconfig.json`, `.meow/types/*`, and the root `tsconfig.json` shim generation.
- remove the root `package.json` generation call.
- success output no longer claims `package.json` was regenerated.

`meow doctor`
- remove CFG-002's package.json staleness/hand-edit implementation.
- command reverts to the existing honest stub path (`PLAN P6`).

`meow why-dep`
- read `PackageJson::read(root)`.
- build `direct = package_json.direct_dependencies()?`.
- call `meow_pkg::resolve_roots(&direct, &lockfile)`.
- not-found prose now names `package.json` as the direct-dependency root source.

`meow install`
- `meow install <pkg>` resolves the request exactly as today, then mutates `package.json` through `meow_config::add_dependency` before resolution.
- plain `meow install` with no `package.json` treats direct dependencies as empty (`PackageJson::default()` at the CLI edge).
- build the install input from `package_json.direct_dependencies()`.
- write `meow.lock.jsonl` exactly as before.
- remove the package.json generation call.
- materialize/vendor projection roots come from `resolve_roots(&direct_deps, &lockfile)`.

`meow run`
- `load_declared_root_deps(project_root, lockfile)` reads `package.json` instead of `meow.config`.
- if `package.json` is absent, keep `fallback_root_deps_from_lockfile(lockfile)` for the local-only fallback.
- remove the `ConfigError::TsNotSupported` branch from root-dep derivation; TS config evaluation is no longer on the dependency path.

### A5 — Retire CFG-002 package ownership surface

Delete the old module (`crates/config/src/package.rs`) and its exports. After CFG-003 there is no provenance marker, no classification surface, and no meow-owned root package.json. Any remaining code/comments that imply otherwise are bugs.

### A6 — User-visible contract after cutover

Concrete, observable CLI behavior:

- Stock project, already has `package.json`:
  - `meow install` reads `dependencies` + `devDependencies`, resolves them, and writes `meow.lock.jsonl`.
  - `meow run <file>` derives runtime root pins from `package.json` + `meow.lock.jsonl`.
  - `meow why-dep <name>` traces from `package.json` direct deps.
- Explicit add path:
  - `meow install lodash@^4` writes `package.json.dependencies.lodash = "^4"`, then resolves and writes the lockfile.
- No `package.json`:
  - `meow install` with no package args resolves an empty direct set and writes an empty lockfile.
  - `meow run` keeps the lockfile-only fallback.
  - `meow why-dep` errors honestly because roots are missing.

## Non-goals

- `package.json` script execution (`meow run <script>` / `meow <script>`) — RUN-001.
- workspace linking / discovery semantics beyond storing the `workspaces` field — WS-001.
- support for npm aliases, `workspace:*`, `file:`, `git:`, dist-tags in existing `package.json`, or other non-semver dependency specifiers. CFG-003 names them honestly and errors; a later slice widens support.
- reformatting policy parity with npm/Bun beyond 2-space pretty JSON and dependency-key sorting.
- reintroducing any compatibility shim that reads both `meow.config` deps and `package.json` deps.

## Rollout

- Flag-free, clean cutover.
- Existing projects must move declared deps/metadata into `package.json`; lingering `meow.config.dependencies` / `publish` are parse errors by design.
- Reversibility: restore the deleted `package.rs` ownership path, re-add the schema fields and exports, and revert the CLI wiring. Nothing in the data model is one-way; the change is policy + callsite selection.

## Operator notes

- **FORK[CFG-003:pkgjson-format]** — mutation uses a `serde_json::Value` round-trip. This preserves every top-level field/value but, because the workspace `serde_json` build does **not** enable `preserve_order`, top-level object keys are rewritten in lexicographic order on write. Dependency keys are also lexicographically sorted. This is the simplest correct cutover; the read path (the 5-minute-test critical path) is unaffected.
- **Verified parser behavior:** `VersionReq::parse` is a thin wrapper over `semver::VersionReq::parse`. It accepts normal semver ranges **and `"*"`**; it rejects dist-tags/protocols/aliases like `"latest"`, `"workspace:*"`, `"file:../x"`, and `"npm:foo@^1"`. Therefore `PackageJson::direct_dependencies()` accepts `"*"` and errors on the rest.
- **Hard cutover:** CFG-003 deliberately rejects legacy `meow.config` dependency/metadata fields instead of shadow-reading both sources. Parallel authority would violate Amendment 001 and make resolver bugs impossible to reason about.
- **Behavior choice:** explicit add (`meow install <pkg>`) creates a minimal `package.json` when absent so the authority can be established in-band; plain `meow install` without package args still treats a missing `package.json` as an empty direct-dependency set at the CLI edge.
