## Motivation

LOAD-003 landed THE single resolver (`meow_loader::Resolver`, I-1/I-5) and made it lockfile-driven: it resolves any specifier against the **content-addressed cache + `meow.lock.jsonl` only — never `node_modules`** by keying first-party bare specifiers off `root_deps` and cached-referrer deps off `LockEntry.dependencies` (`resolver.rs::dependency_version`). But the resolver only *consumes* `(Arc<Lockfile>, root_deps)`; nothing yet **produces** them faithfully. The P1 run-path uses an explicit stand-in (`crates/cli/src/cli.rs::root_deps_from_lockfile`) that treats *every* lockfile line as a direct dependency and errors on any multi-version package — a placeholder its own doc comment retires to "PKG-002/P2": it cannot tell a root direct dep from a transitive one, and it forbids the very multi-version trees LOAD-003 resolves correctly.

PKG-003 is the **PnP in-memory loader** (CANON ADR-4, §12.2 "PnP (in-memory) — *default*", §24.4): the node_modules-free resolution data structure — the `.pnp` manifest equivalent — that maps the **whole resolved dependency tree** (the root's direct deps pinned to exact versions + every package's own dependency map + its location in the content-addressed cache) so the one `Resolver` resolves any specifier with **no `node_modules` on disk**. Concretely it lands `meow_pkg::ResolutionGraph`: a validated, install-mode-independent projection of `meow.lock.jsonl` rooted at the project's direct deps, built from the lockfile (PKG-001) + the cache (PKG-001), and fed unchanged into LOAD-003's `Resolver`. The runtime and the LSP construct their resolver from the **same** `ResolutionGraph` through **one** seam, so the editor and the runtime cannot disagree (ADR-4 consequence; I-5).

This is the default-mode half of P2's exit condition: *a project installs and runs pure-ESM dependencies with no `node_modules`; the same lockfile reproduces the same graph; runtime and LSP resolve identically.* Per **ADR-4 it ships in the same phase as `--materialize` (PKG-004)** — PnP is the default, materialize/vendor the escape hatch — and both are two projections of this one resolved graph (in-memory vs. on-disk), over one resolver.

Traceability: `plan_ref` → PLAN.md *Build sequence · P2 Packages & Resolution* + *backlog later-phases* (`PKG-003 PnP in-memory loader`). `constitution_ref` → **I-5** [`resolver-parity`] (no `node_modules`; runtime ≡ LSP resolution, ADR-4/CANON §12.2), **I-7** [`lockfile-integrity`] (the graph is a projection of the integrity-pinned lockfile; cache reads verify the hash, CANON §12.1/§12.3), **I-1** [`graph-integrity`] (one resolver; PnP builds inputs, never a second resolver), **I-11** [`honesty`] (PnP is the only resolution path — `node_modules` is an export, never consulted; capability/provenance metadata rides along but stays advisory until P6/P7).

## Acceptance criteria

A new `crates/pkg/src/pnp.rs` module plus a thin construction seam in `crates/loader` and the run-path wiring in `crates/cli`. Every reachable failure is a typed, causal `thiserror` enum pointing at the fix (`meow install`); nothing on the build/validate path `unwrap`/`panic!`s on a malformed lockfile or a stale cache (CRAFT Part B). All identifiers are PKG-001 newtypes (`PackageName`, `Version`, `ContentHash`), never raw `String`.

### A1 — `ResolutionGraph` + `ResolvedPackage` (`crates/pkg/src/pnp.rs`, new)

```rust
use std::collections::{BTreeMap, BTreeSet};
use std::path::Path;
use std::sync::Arc;

use crate::{Cache, ContentHash, DepSpec, Lockfile, LockEntry, PackageName, RootResolveError, Version};
// `DepSpec`, `RootResolveError`, and the `resolve_roots` fn are PKG-002's (same crate); consumed, not redefined.

/// The install-mode-independent, fully-pinned resolved dependency tree — meow's
/// `.pnp` manifest equivalent (CANON ADR-4, §12.2). A *validated closed projection*
/// of `meow.lock.jsonl` (PKG-001) rooted at the project's direct dependencies:
///
/// - the root's direct deps, pinned to EXACT versions (the root has no `LockEntry`);
/// - every reachable package's own dependency map + its content-addressed cache
///   location — both read straight from `LockEntry.{dependencies, integrity}`.
///
/// It holds NO `Cache` and writes nothing to disk: it is the data the ONE
/// `meow_loader::Resolver` (LOAD-003) is constructed from, and the data
/// `--materialize`/`--vendor` (PKG-004) projects to disk — two projections, one
/// graph, one resolver (I-5). Cheap to clone (`Arc<Lockfile>` + two small maps).
#[derive(Clone)]
pub struct ResolutionGraph {
    /// The project's DIRECT dependencies, pinned to exact versions. The project
    /// root is not itself a `LockEntry`, so first-party bare specifiers resolve
    /// through this map (it is exactly LOAD-003's `Resolver::root_deps` input).
    root_deps: BTreeMap<PackageName, Version>,
    /// The closed transitive graph: `(name, version) → LockEntry` (integrity =
    /// cache locator; dependencies = that package's own exact-version edges).
    /// Read-only here — PKG-002 owns every write.
    lockfile: Arc<Lockfile>,
    /// The ROOT-REACHABLE closure (keys into `lockfile`), validated dangling-free
    /// at `assemble`. Sorted set ⇒ `packages()` is deterministic. Unreachable
    /// lockfile entries (e.g. orphans from a since-shrunk graph) are excluded.
    reachable: BTreeSet<(PackageName, Version)>,
}

/// A borrowed view of one node in the reachable closure. The exact per-package
/// data a projection consumer (PKG-004 disk layout, LSP-001 `.meow/deps` symlinks,
/// OBS-001 `why-dep`) walks. Minimal by design: `integrity` is the cache locator,
/// `dependencies` are the package's own edges; provenance/capabilities stay in the
/// `LockEntry` and are NOT surfaced for layout (they are advisory, I-8/I-11).
#[derive(Clone, Copy)]
pub struct ResolvedPackage<'a> {
    pub name: &'a PackageName,
    pub version: &'a Version,
    pub integrity: &'a ContentHash,
    pub dependencies: &'a BTreeMap<PackageName, Version>,
}

impl ResolutionGraph {
    /// Pure, disk-free constructor (the fixture/test seam). Validates the reachable
    /// closure and stores `{root_deps, lockfile, reachable}`. No I/O, no `Cache`.
    ///
    /// Validation (BFS from `root_deps` over `LockEntry.dependencies`):
    /// - every `(name, version)` in `root_deps` has a matching `LockEntry`
    ///   (else `PnpError::RootNotLocked`);
    /// - every transitive edge resolves to a present `LockEntry`
    ///   (else `PnpError::DanglingEdge`) — the closure is proven closed once, here,
    ///   so downstream consumers (PKG-004) may trust it.
    pub fn assemble(
        lockfile: Arc<Lockfile>,
        root_deps: BTreeMap<PackageName, Version>,
    ) -> Result<ResolutionGraph, PnpError>;

    /// Load from a project: read `<project_root>/meow.lock.jsonl` (`Lockfile::read`,
    /// I-7-strict), pin the root via the SHARED `meow_pkg::resolve_roots` (owned by
    /// PKG-002 — the single root derivation install, runtime, and the LSP all use,
    /// so they cannot diverge), then `assemble`. `direct` is the project's declared
    /// direct deps (built from `MeowConfig.dependencies` by the caller — keeps
    /// `meow_pkg` free of a `meow_config` dependency). Convenience for the LSP /
    /// any caller wanting the whole read path in one call; the run-path uses the
    /// two-step form (PKG-002 derives `root_deps`, PKG-003 `assemble`s — see A4).
    pub fn from_project(
        project_root: &Path,
        direct: &BTreeMap<PackageName, DepSpec>,
    ) -> Result<ResolutionGraph, PnpError>;

    pub fn root_deps(&self) -> &BTreeMap<PackageName, Version>;
    pub fn lockfile(&self) -> &Arc<Lockfile>;

    /// The root-reachable closure, deterministic `(name, version)` order. The
    /// per-node walk PKG-004 lays out to disk and LSP-001 enumerates for symlinks.
    /// Excludes unreachable lockfile entries; never yields a dangling edge.
    pub fn packages(&self) -> impl Iterator<Item = ResolvedPackage<'_>> + '_;

    /// PnP precondition check: assert every reachable package's blob is PRESENT in
    /// `cache` (so resolution can proceed with no `node_modules`). Presence only
    /// (`Cache::contains`) — fast, no rehash; the hash recompute (I-7) fires lazily
    /// at resolution time on the actual `Cache::read` (matching LOAD-003's
    /// `package_fs`). A missing blob ⇒ `PnpError::NotCached { name, version }`
    /// (fix: `meow install`).
    pub fn verify_cached(&self, cache: &Cache) -> Result<(), PnpError>;
}
```

Behaviors:
- `assemble` is a **pure function of `(lockfile, root_deps)`**: same inputs ⇒ same graph ⇒ `packages()` yields the same sequence, regardless of `BTreeMap` insertion order (I-6 substrate).
- `packages()` yields **only** the root-reachable set, ascending by `(name, version)`. A package present in the lockfile but unreachable from `root_deps` is silently excluded (it is dead weight, not an error — the lockfile may legitimately carry more than one project's closure is moot here since one project = one lockfile, but shrinking the root set must not require rewriting the lock).
- Multi-version is inherent: `lodash@4.17.20` and `lodash@4.17.21` both reachable ⇒ both yielded; each referrer points at its own version via its `dependencies` map (no hoisting, no flattening).
- `assemble` never reads the cache; `from_project` reads only `meow.lock.jsonl`; `verify_cached` reads only `Cache::contains`. The hot path's integrity enforcement stays where I-7 already lives — `Cache::read` at resolve time.

### A2 — `PnpError` (`crates/pkg/src/error.rs`, fenced `// === PKG-003 ===`)

```rust
#[derive(thiserror::Error, Debug)]
pub enum PnpError {
    #[error("reading lockfile while building the resolution graph")]
    Lock(#[from] LockError),
    #[error("direct dependency {name} pinned to {version}, but no such entry is in \
             meow.lock.jsonl — run `meow install`")]
    RootNotLocked { name: PackageName, version: Version },
    #[error("dependency {name}@{version} requires {dep}@{dep_version}, which is not in \
             meow.lock.jsonl (dangling edge) — run `meow install`")]
    DanglingEdge { name: PackageName, version: Version, dep: PackageName, dep_version: Version },
    #[error("package {name}@{version} is not in the cache — run `meow install`")]
    NotCached { name: PackageName, version: Version },
    #[error(transparent)]
    Roots(#[from] RootResolveError), // from `meow_pkg::resolve_roots` (PKG-002): a declared dep missing/unsatisfiable in the lock
}
```

(`RootResolveError` is owned by PKG-002 alongside `resolve_roots`; PKG-003 re-wraps it via `#[from]` so a single `PnpError` covers the whole build path — see Operator notes / `depends_on`.)

### A3 — The Resolver seam (`crates/loader/src/resolver.rs`, fenced `// === PKG-003 ===`)

The resolver is **not changed** — its fields keep their meaning; PnP becomes their single producer. One sugar constructor is added so the runtime and the LSP build the resolver through the **identical** call:

```rust
impl Resolver {
    /// THE construction seam (I-5). Build the one shared resolver from a resolved
    /// graph. The runtime run-path and the LSP both call THIS with the same
    /// `Arc<ResolutionGraph>` ⇒ identical `(lockfile, root_deps)` inputs ⇒
    /// identical resolution (resolver-parity). `Resolver::new` stays the low-level
    /// constructor but is no longer called outside this crate.
    pub fn from_resolution(
        graph: &meow_pkg::ResolutionGraph,
        cache: Arc<Cache>,
        project_root: Url,
        native: Arc<dyn meow_runtime::native::NativeModuleSource>,
    ) -> Resolver {
        Resolver::new(
            cache,
            graph.lockfile().clone(),
            graph.root_deps().clone(),
            project_root,
            native,
        )
    }
}
```

- `from_resolution` does exactly what the run-path does inline today — `Resolver::new(cache, lockfile, root_deps, project_root, native)` — but reads `lockfile`/`root_deps` from one validated `ResolutionGraph`, so the two consumers cannot pass divergent inputs.
- The resolution algorithm (LOAD-003: `locate`/`resolve`, `dependency_version`, exports/imports/conditions) is **untouched**. `dependency_version` already reads first-party deps from `root_deps` and cached-referrer deps from `lockfile.get(name, version).dependencies` — PnP only supplies and *validates* those two inputs.

### A4 — Run-path wiring: route the resolver through `ResolutionGraph` (`crates/cli/src/cli.rs`, fenced `// === PKG-003 ===`)

This is a **shared `cmd_run` edit handed off from PKG-002** (coordinate fence boundaries — PKG-004 also fences `cmd_install` here). PKG-002 already removes the P1 `root_deps_from_lockfile` stand-in and derives the real `root_deps` in `cmd_run` via `MeowConfig::load` → build `direct: BTreeMap<PackageName, DepSpec>` from `cfg.dependencies` → `root_deps = meow_pkg::resolve_roots(&direct, &lockfile)?` (PKG-002 A6). PKG-003 picks up from there: it **replaces the resolver-construction lines** (the inline `Resolver::new(...)` PKG-002 leaves so `cmd_run` compiles) with the validated-graph + seam path:

```rust
// === PKG-002 === (already landed: lockfile loaded; root_deps derived via resolve_roots)
//   let lockfile = load_lockfile(&project_dir)?;
//   let direct   = direct_deps(&cfg);                      // MeowConfig.dependencies -> BTreeMap<_, DepSpec>
//   let root_deps = meow_pkg::resolve_roots(&direct, &lockfile)?;
// === /PKG-002 ===

// === PKG-003 ===
// Validate the closure once, then build THE resolver from it. No node_modules is read
// or written (I-5); the LSP builds from the same graph + same seam (resolver-parity).
let cache = std::sync::Arc::new(meow_pkg::Cache::in_home(crate::host::host_home()));
let graph = std::sync::Arc::new(
    meow_pkg::ResolutionGraph::assemble(std::sync::Arc::new(lockfile), root_deps)?,
);
graph.verify_cached(&cache)?;                              // honest precondition: every blob present
let resolver = meow_loader::Resolver::from_resolution(
    &graph,
    cache,
    project_root,
    meow_runtime::native::native_module_registry(),
);
let loader = std::rc::Rc::new(meow_loader::MeowModuleLoader::new(
    resolver,
    std::rc::Rc::new(std::cell::RefCell::new(meow_graph::GraphDb::new())),
));
// === /PKG-003 ===
```

- PKG-003 consumes the `root_deps` PKG-002 produced (it does not re-derive it); `assemble` re-validates the closure (defensive — `assemble` is pure and does not trust its caller) and `verify_cached` asserts every reachable blob is present before the isolate starts.
- A missing `meow.lock.jsonl` / empty `cfg.dependencies` ⇒ empty `root_deps` ⇒ empty `ResolutionGraph` (a local-only run with no deps still resolves first-party `./` imports; not an error).
- The diagnostic for a typed `PnpError` renders as `meow run: <error>` (never a backtrace), exactly as the existing run-path renders `LockError`.
- **Fence handoff (P5):** if PKG-002 chooses to own the whole resolver-construction block (not leave an inline `Resolver::new`), PKG-003's fence simply contains the `assemble`/`verify_cached`/`from_resolution` lines after PKG-002's `root_deps` line — same result; coordinate the exact boundary at merge.

## Non-goals

- **Install / registry fetch / lockfile generation / cache population** — **PKG-002**. PKG-003 only *reads* an already-populated cache + lockfile and projects them into a graph; it never downloads, resolves ranges into the lockfile, or writes the cache. (`resolve_roots`, the declared-dep → exact-root-pin derivation, is PKG-002's; PKG-003 consumes it.)
- **The on-disk materialized / vendor form** — **PKG-004**. `node_modules`/`.meow/<name>@<ver>/…` layout, symlink edges, `--materialize`/`--vendor` are PKG-004, which consumes this exact `ResolutionGraph` via `packages()`. PKG-003 is in-memory only; nothing here writes a package tree to disk.
- **VFS / FUSE** — CANON §12.2 lists a VFS mode; not P2, not this spec.
- **The LSP itself** — **LSP-001**. PKG-003 guarantees the LSP *can* obtain the identical resolver (same `ResolutionGraph` + `Resolver::from_resolution`); the editor wiring and the `.meow/deps/` shadow symlink map (§20.1) are LSP-001.
- **Capability / provenance enforcement** — `LockEntry.{capabilities, registry}` ride along in the graph but PnP **does not enforce or verify** them. They are advisory until the capability tiers (P6/P7, I-8) and Sigstore/OSV provenance (§15.4) land — stated honestly (I-11), never surfaced by `ResolvedPackage` as if they gated resolution.
- **The hash-algorithm model (npm sha512 vs. meow sha256)** — **PKG-002**. PKG-003 consumes `LockEntry.integrity` as the meow cache key (sha256, PKG-001) and relies on `Cache::read`'s recompute (I-7); the download-time sha512 provenance check is install's.
- **CJS dependency execution** — LOAD-004 (P5). PnP resolves CJS *locations* via LOAD-003's existing classification; it adds no CJS behavior.
- **Async I/O** — `from_project`/`verify_cached` use sync `std::fs`/`Cache` (build-time, off the hot path), as PKG-001 does.

## Interface

- **Crate `meow_pkg`** gains: `ResolutionGraph` (`assemble`, `from_project`, `root_deps`, `lockfile`, `packages`, `verify_cached`), `ResolvedPackage<'a>`, `PnpError`. Consumes (does not redefine): `Cache`, `Lockfile`, `LockEntry`, `ContentHash`, `PackageName`, `Version`, `LockError` (PKG-001), and `resolve_roots`/`DepSpec`/`RootResolveError` (PKG-002).
- **Crate `meow_loader`** gains: `Resolver::from_resolution(&ResolutionGraph, Arc<Cache>, Url, Arc<dyn NativeModuleSource>) -> Resolver`. `Resolver::new` becomes crate-internal in practice (only `from_resolution` and tests call it).
- **CLI:** `meow run` builds the resolver from a `ResolutionGraph` (root deps from `MeowConfig.dependencies` + `meow.lock.jsonl`); the P1 `root_deps_from_lockfile` stand-in is gone. No new CLI command or flag (install modes are PKG-002/PKG-004; PnP is the default, ADR-4).
- **On-disk inputs consumed** (none written by this spec):
  - `<project_root>/meow.lock.jsonl` — the closed graph (PKG-001 format).
  - `MeowConfig.dependencies` — declared direct dep ranges (PKG-002's config field).
  - `~/.meow/cache/<algo>/<hash>` — package blobs (PKG-001 cache; gzip-tar, `package/` prefix; verified on read, I-7).
- **The ADR-4 shared model:** `meow_pkg::ResolutionGraph` is the single resolved-tree type consumed by **PKG-003** (in-memory → `Resolver`) and **PKG-004** (on-disk → `node_modules`/vendor via `packages()`), and by **LSP-001** (`from_resolution` + `packages()` for the symlink map). One graph, two projections, one resolver.

## Implementation sketch

New module `crates/pkg/src/pnp.rs`; shared-file edits carry `// === PKG-003 ===` fences.

1. **`assemble`** — BFS the reachable closure: seed a work-queue + `BTreeSet<(PackageName, Version)>` `reachable` from `root_deps`; for each `(name, version)`, `lockfile.get(name, version)` → on `None`, `RootNotLocked` (if it was a root pin) or `DanglingEdge` (if reached via an edge — track the referrer to name it); insert into `reachable`; enqueue each `entry.dependencies` edge not yet visited. Closure is finite (bounded by lockfile size) and order-independent (set + sorted iteration). Store `{ root_deps, lockfile, reachable }`.
2. **`packages`** — iterate `reachable` (ascending) and map each key through `lockfile.get` → `ResolvedPackage { name, version, integrity, dependencies }` borrowed from the `LockEntry`. (`get` is infallible here — membership was proven at `assemble`.)
3. **`from_project`** — `Lockfile::read(project_root.join("meow.lock.jsonl"))` (or empty when absent) → `root_deps = resolve_roots(direct, &lockfile)?` (PKG-002) → `assemble(Arc::new(lockfile), root_deps)`.
4. **`verify_cached`** — `for p in self.packages() { if !cache.contains(p.integrity) { return Err(NotCached { name, version }) } }`. Presence only; integrity stays lazy (I-7 at `Cache::read`).
5. **Seam** (`crates/loader/src/resolver.rs`) — the `from_resolution` sugar (A3); no algorithm change. **Run-path** (`crates/cli/src/cli.rs`) — PKG-002 has already removed the `// === LOAD-001 ===` stand-in (`root_deps_from_lockfile`) and derives `root_deps` via `resolve_roots`; PKG-003's `// === PKG-003 ===` fence replaces the resolver-construction lines with `assemble` + `verify_cached` + `Resolver::from_resolution` (A4). Coordinate the fence boundary with PKG-002.
6. **`resolve_roots` consumption** — owned by PKG-002 (its written spec A6: `pub fn meow_pkg::resolve_roots(direct: &BTreeMap<PackageName, DepSpec>, lockfile: &Lockfile) -> Result<BTreeMap<PackageName, Version>, RootResolveError>` = max-satisfying locked version per declared direct dep; `RootResolveError::NotInLockfile` when a declared dep is absent). It is the single root-derivation shared by install / runtime / LSP / PnP — parity by construction. PKG-003 calls it from `from_project` and re-wraps `RootResolveError` into `PnpError`; the run-path uses the `root_deps` PKG-002 already derived (A4).

CRAFT discipline: no `unwrap`/`panic!` on the build/validate path; borrow (`&Lockfile`, `&ContentHash`) on `packages()`/`verify_cached` (no per-node clones); `ResolutionGraph` clone is `Arc` + two small maps (cheap, so both the run-path and a future watch/daemon can hold copies).

## Tests required

`crates/pkg/tests/pnp.rs` (graph build/validate, in-memory fixtures) + a resolver-parity integration test reusing LOAD-003's corpus harness. Proves **I-5** [`resolver-parity`], **I-7** [`lockfile-integrity`], **I-1** [`graph-integrity`], with **I-6** [`determinism`] on the build and **I-11** [`honesty`] on the no-`node_modules` claim.

- **A real dep tree resolves with no `node_modules` (I-5, the P2 exit shape):** store synthetic gzip-tar archives (root → A, A → B@1, root → C, C → B@2) in a `Cache::with_root(tmp)`, write the matching `meow.lock.jsonl`, `assemble` with `root_deps = {A, C}`; build `Resolver::from_resolution(&graph, …)` + `MeowModuleLoader`; resolve+execute an entry importing A (which imports B@1) and C (which imports B@2) through `meow_runtime::Runtime` → both transitive Bs observed; assert **no path containing `node_modules` was opened and none exists**, and every resolved dep URL is `meow-cache://…`.
- **Resolver-parity: runtime path ≡ resolver-only/LSP path (I-5, the gate fixture):** over a specifier corpus (bare, subpath, self-ref, `#import`, nested multi-version), build ONE `Arc<ResolutionGraph>`; construct two resolvers via `Resolver::from_resolution` — one driven through `MeowModuleLoader::load` (runtime), one calling `Resolver::locate` directly (the LSP stand-in, resolve-without-execute) — and assert **identical `(url, ModuleLocator)`** for every specifier. This is the `resolver-parity` gate's fixture; LSP-001 resolves the same corpus through the same seam.
- **Closure validation (I-7/honesty):** a lockfile with a `LockEntry.dependencies` edge to a `(name, version)` that has no entry ⇒ `assemble` → `PnpError::DanglingEdge` naming referrer + missing dep; a `root_deps` pin with no matching entry ⇒ `RootNotLocked`. No panic on either.
- **`verify_cached` (I-7 precondition):** all blobs present ⇒ `Ok`; remove one reachable blob ⇒ `PnpError::NotCached { name, version }` (fix message). Integrity is still enforced lazily — a *tampered* (present-but-wrong-bytes) blob passes `verify_cached` but fails at `Cache::read` during resolution with `IntegrityMismatch` (assert this, proving I-7 lives at read, not at the presence check).
- **Reachable closure excludes orphans + multi-version (I-1):** a lockfile with an unreachable extra package ⇒ `packages()` does NOT yield it; `lodash@4.17.20` + `4.17.21` both reachable ⇒ `packages()` yields both, sorted; the resolver routes each referrer to its own version.
- **Determinism / order-independence (I-6):** `assemble` from the same `(lockfile, root_deps)` with shuffled `BTreeMap` build order ⇒ `packages()` yields a byte-identical `(name, version, integrity)` sequence; two `assemble`s are equal.
- **`from_project` end-to-end:** a tmp project with `meow.lock.jsonl` + a `direct` deps map ⇒ `from_project` pins roots via `resolve_roots`, builds the graph, and resolves the entry; an empty/missing lockfile + empty `direct` ⇒ empty graph, local-only run still resolves first-party `./` imports.

GATES: `resolver-parity` (I-5 — the corpus is shared with LOAD-003/LSP-001 as the gate fixture; runtime ≡ resolver-only ≡ LSP), `lockfile-integrity` (I-7 — graph is a projection of the integrity-pinned lock; tamper still refused at read), `graph-integrity` (I-1 — one resolver; PnP builds inputs, no second resolver), `determinism` (I-6 — assemble is a pure function of the lock), `honesty` (I-11 — `node_modules` never read/written; capabilities advisory). Floor: `cargo test/clippy/fmt`, `principles-check.sh`.

## Rollout

- **Additive + one internal breaking change.** New `pnp` module + `ResolvedPackage`/`PnpError`; additive `Resolver::from_resolution`. The breaking part is internal-only: the `meow run` path stops calling `Resolver::new` inline and the P1 `root_deps_from_lockfile` stand-in is **deleted**. One call site; no user-visible behavior changes except that `meow run` now resolves *real* direct-vs-transitive trees (and multi-version transitives) instead of the single-version stand-in.
- **No data migration / no flag.** `meow.lock.jsonl` and the cache are PKG-001 formats already on disk; PnP is the default install mode (ADR-4, `InstallMode::Pnp`), so nothing new is gated behind a flag. `--materialize`/`--vendor` arrive with PKG-004 over the same graph.
- **Reversibility:** revert the `// === PKG-003 ===` fences in `crates/cli/src/cli.rs`, `crates/loader/src/resolver.rs`, `crates/pkg/src/lib.rs`, and `crates/pkg/src/error.rs`, and delete `crates/pkg/src/pnp.rs`; the LOAD-001/P1 stand-in run-path returns. Nothing is written to disk, so there is no persisted state to roll back.
