## Motivation

`meow` executes TypeScript by **erasing annotations to whitespace** — producing valid JS with byte-for-byte identical source positions, no transpiler output, and no sourcemap layer for normal TS (CANON §9, §7.1 stage 5). This is the runtime's hot path: stripping runs on every TS module before V8 sees it, and checking is explicitly *not* in line (CANON §9.1, "runtime execution must not wait on full typechecking").

The policy is **strict TC39 Erasable Syntax (CANON §27 Q6, resolved)**: only constructs that *are* pure type annotations may be stripped. Constructs that emit runtime JS — `enum`, non-ambient `namespace`, parameter properties, `import =` / `export =` — are **banned** and must produce a fix-pointing diagnostic rather than being silently transpiled. There is no downlevel-emit crutch.

This is invariant **I-3** verbatim ("Type-strip is meaning-preserving and erasable-only … `enum`, runtime `namespace`, parameter properties, and `import =` error with a fix-pointing message; stripping never emits downlevel JS"), gated by `strip-fidelity`. RT-003 is the implementation of that policy; GRAPH-001 owns the pipeline it plugs into (stage 1 CST → stage 5 Runtime IR).

## Acceptance criteria

All new code lives in `crates/graph` (the one parse/lowering chokepoint, I-1) behind `// === RT-003 ===` comment-marker fences, coordinated with GRAPH-001. RT-003 owns the **erasable-only policy** (the strip algorithm + the non-erasable catalog + the fix-pointing strings); GRAPH-001 owns the surrounding types (`Cst`, `SemanticGraph`, `RuntimeIr`, `Diagnostic`, `Severity`, `GraphError`) and the `lower_to_ir` seam.

### 1. The core entrypoint — `strip`

New module `crates/graph/src/strip.rs`:

```rust
// === RT-003 ===
//! Erasable-only TC39 type stripping (CANON §9, I-3). Whitespace-preserving
//! annotation erasure on the hot path. Never transpiles; never emits downlevel JS.

use crate::cst::Cst;                 // stage-1 lossless tree (GRAPH-001)
use crate::diagnostic::Diagnostic;   // shared diagnostic (GRAPH-001)

/// Type-erased program text. Same byte length and same line/column geometry
/// as the input `source`: every retained byte keeps its original byte offset,
/// so positions are stable WITHOUT a source map (CANON §9).
pub struct Stripped {
    /// `text.len() == source.len()`. Each erased byte is replaced by an ASCII
    /// space, except `\n` / `\r`, which are preserved so line numbers are exact.
    text: Box<str>,
}

impl Stripped {
    /// The erased program, ready to hand to V8 as JS.
    pub fn as_str(&self) -> &str { &self.text }
}

/// Erase erasable TS syntax to whitespace, or reject the module with the full
/// set of non-erasable diagnostics. Pure and syntactic: it reads only the
/// stage-1 `Cst` (no `SemanticGraph`, no resolver, no host) — that is what keeps
/// it on the hot path. Returns ALL diagnostics found, not just the first.
pub fn strip(source: &str, cst: &Cst) -> Result<Stripped, Vec<Diagnostic>>;
```

Behavioral contract for `strip`:

- **Whitespace fidelity.** `strip(source, cst)?.as_str().len() == source.len()`. Every byte that is *not* part of an erased span is byte-identical and at its original offset. Erased bytes become `0x20` (space), with `\n` (`0x0A`) and `\r` (`0x0D`) preserved in place. ⇒ both line and column of every retained token are unchanged; no sourcemap is produced or needed.
- **Reparse equivalence.** `strip(source, cst).as_str()` reparses as valid JS (no TS syntax remains) whose AST equals the input AST with all type-only nodes removed (the `strip-fidelity` property, below).
- **Erase-only-on-success.** When any non-erasable construct is present, `strip` returns `Err(diags)` and produces **no** `Stripped` — the runtime never runs partially-erased code.
- **No allocation of a second copy when clean of types is impossible** (every TS file has at least annotations), but the algorithm performs a single pass and writes into one `String` of `source.len()` capacity (CRAFT: no gratuitous clones on the parse hot path).

### 2. What gets erased (the erasable set)

`strip` collects the spans of, and blanks, exactly these stage-1 nodes (Oxc TS AST kinds), keeping everything else verbatim:

- Type annotations: `: T` on parameters, variables, class fields, function return types.
- `type` alias declarations and `interface` declarations (whole statement).
- Type parameter lists `<T, U extends V>` and type argument lists `f<T>()`, `new C<T>()`.
- `as T` and `satisfies T` expression suffixes (keep the operand, blank the operator + type).
- Non-null `!` postfix and definite-assignment `!` on fields.
- Optional `?` markers on parameters and members.
- `implements` clauses on classes.
- `declare` statements and ambient declarations, including `declare namespace` / `declare enum` (ambient ⇒ erasable; only the *non-ambient* forms are banned — see §3).
- `import type …`, `export type …`, and inline `import { type X }` / `export { type X }` specifiers (type-only imports removed before execution, CANON §9). Pure value imports are **kept** (verbatim-module-syntax semantics: erasure is syntactic, never elides a value import based on usage).
- Member accessibility/`readonly`/`override`/`abstract` modifiers on ordinary members (these are erasable; the parameter-property case is the exception, §3).

### 3. What is banned (the non-erasable catalog)

`strip` detects these constructs and emits one `Diagnostic` each (collecting all in the module). Codes are namespaced `strip::*` (RT-003 owns this namespace per GRAPH-001). Each carries `message` = cause and `fix` = remedy, matching the product diagnostic bar (CANON §9 exemplar voice):

```rust
// === RT-003 ===
/// One catalog entry per non-erasable construct. `span` points at the offending
/// syntax so the editor underlines the exact token.
fn diag_enum(span: Span) -> Diagnostic;             // strip::enum
fn diag_namespace(span: Span) -> Diagnostic;        // strip::namespace
fn diag_param_property(span: Span) -> Diagnostic;   // strip::param_property
fn diag_import_equals(span: Span) -> Diagnostic;    // strip::import_equals
fn diag_export_equals(span: Span) -> Diagnostic;    // strip::export_equals
```

| Code | Construct (detected node) | `message` (cause) | `fix` (remedy) |
|------|---------------------------|-------------------|----------------|
| `strip::enum` | `enum` and `const enum`, non-ambient | "Enums emit runtime code and cannot be type-stripped." | "Use a `const` object instead." |
| `strip::namespace` | `namespace`/`module Foo { … }` with a runtime body, non-ambient | "Namespaces with a runtime body emit code and cannot be type-stripped." | "Use ES modules (separate files and named exports) instead." |
| `strip::param_property` | `constructor(public/private/protected/readonly x: T)` | "Parameter properties emit an assignment and cannot be type-stripped." | "Declare the field on the class and assign it in the constructor body instead." |
| `strip::import_equals` | `import x = require(…)` and `import x = Foo.Bar` | "`import =` emits runtime code and cannot be type-stripped." | "Use a standard ESM `import` instead." |
| `strip::export_equals` | `export = …` | "`export =` emits CommonJS and cannot be type-stripped." | "Use `export default` or named exports instead." |

`severity` is `Error` for every entry. `const enum` is banned alongside `enum` (it still participates in emit and is not erasable syntax). Ambient forms (`declare enum`, `declare namespace`) are **not** banned — they erase like any other declaration.

### 4. Pipeline integration — the `StripPolicy` seam

GRAPH-001 exposes `fn lower_to_ir(cst: &Cst, semantic: &SemanticGraph, policy: &dyn StripPolicy) -> Result<RuntimeIr, GraphError>` and `GraphDb::runtime_ir(path) -> Result<RuntimeIr, GraphError>` (stage 5). RT-003 supplies the policy:

```rust
// === RT-003 ===
/// The erasable-only policy. Stateless; syntactic. `lower_to_ir` calls this to
/// obtain the erased text (or the diagnostics) before building Runtime IR.
pub trait StripPolicy {
    fn strip(&self, source: &str, cst: &Cst) -> Result<Stripped, Vec<Diagnostic>>;
}

pub struct ErasablePolicy;

impl StripPolicy for ErasablePolicy {
    fn strip(&self, source: &str, cst: &Cst) -> Result<Stripped, Vec<Diagnostic>> {
        crate::strip::strip(source, cst) // the §1 entrypoint
    }
}
```

`runtime_ir`/`lower_to_ir` convert a non-empty `Vec<Diagnostic>` into the appropriate `GraphError` variant (GRAPH-001 owns the mapping; RT-003 only returns the diagnostics). `ErasablePolicy` is the only policy `meow` ships — there is no "transpile" policy (no downlevel emit, I-3).

## Non-goals

- **No typechecking.** RT-003 does not resolve types, infer, or check assignability. Diagnostics from typing are the delegated `tsc`/`tsgo` daemon's job (ADR-5, I-4). `strip` is purely syntactic.
- **No transpilation / no JS emit.** No lowering of TS features to runtime JS, no class-field downleveling, no decorator emit, no `enum`→object rewrite. The only output transformation is annotation→whitespace.
- **No source maps.** Position fidelity is achieved by whitespace preservation, so no map is generated for normal TS.
- **No decorator semantics.** Decorators are out of scope for this spec (separate decision); RT-003 neither emits nor strips decorator runtime behavior.
- **No second parser.** RT-003 consumes GRAPH-001's stage-1 `Cst`; it never constructs an Oxc parser of its own (I-1).
- **No host access.** No env, clock, filesystem, or randomness reads (I-6) — the function takes `&str` + `&Cst` and nothing else.

## Interface

Public surface added to `crates/graph` (all behind `// === RT-003 ===`):

- `strip::strip(source: &str, cst: &Cst) -> Result<Stripped, Vec<Diagnostic>>` — the core (§1).
- `strip::Stripped` with `fn as_str(&self) -> &str` (§1).
- `strip::StripPolicy` trait + `strip::ErasablePolicy` (§4), consumed by GRAPH-001's `lower_to_ir`.
- The five catalog constructors (§3), `pub(crate)` — invoked inside `strip`, not part of the external API; the stable contract is the `code` strings (`strip::*`) and the message/fix text.

Consumed from GRAPH-001 (do not redefine): `cst::Cst`, `SemanticGraph`, `RuntimeIr`, `GraphError`, and from `crates/graph/src/diagnostic.rs`:

```rust
pub struct Diagnostic {
    pub code: &'static str,       // "strip::enum", …
    pub message: Box<str>,        // cause
    pub fix: Option<Box<str>>,    // remedy (always Some for RT-003 entries)
    pub span: oxc_span::Span,     // stable byte offsets
    pub severity: Severity,       // Error
}
```

## Implementation sketch

1. **Single-pass span collector.** Walk the stage-1 Oxc TS AST (via GRAPH-001's `Cst`). One visitor with two outputs: (a) a `Vec<Span>` of erasable spans to blank (§2); (b) a `Vec<Diagnostic>` of non-erasable hits (§3). Detection is by node kind — `enum`/`const enum` declarations, `TSModuleDeclaration` with a body and without the `declare` modifier, constructor params bearing an accessibility/`readonly` modifier, `TSImportEquals`, `TSExportAssignment`. Continue traversing after a hit so all diagnostics in the file are reported at once.
2. **Reject-or-blank.** If the diagnostic vec is non-empty, return `Err(diags)` immediately — no text is produced. Otherwise build the output: allocate `String::with_capacity(source.len())`, copy `source`, and for each erase-span overwrite bytes with `b' '` while leaving `\n`/`\r` in place (iterate the span's byte range; cheap, in-place). Wrap as `Stripped`.
3. **Why blank-not-delete.** Deleting bytes would shift every downstream column and force a source map (CANON §9 explicitly avoids this). Blanking to spaces + preserving newlines keeps `start`/`end` of every surviving token exactly as the delegated checker and the runtime stack traces expect.
4. **Fences.** All edits land inside `// === RT-003 ===` fences in `crates/graph/src/strip.rs` (new file, RT-003-owned) and at the policy call-site inside `runtime_ir`/`lower_to_ir` in `crates/graph/src/ir.rs` (shared with GRAPH-001 — fence the call). Catalog strings live in `strip.rs`.
5. **Idioms (CRAFT Part B).** No `unwrap`/`panic!` on the user-input path — a malformed module surfaces as diagnostics, never a panic. `code` is `&'static str`; messages are owned `Box<str>` built once. Reuse the single output buffer; no per-node string allocation.

## Tests required

Proves invariant **I-3**; satisfies the **`strip-fidelity`** gate (GATES.md: "Property test: `strip → reparse` equals source AST minus types, source positions stable; `enum`/namespace/param-props/`import =` fixtures error with a fix message; no downlevel JS emitted"). Tests live in `crates/graph` (`#[cfg(test)]` + a `tests/strip_fidelity.rs` integration file).

- **PROPERTY — meaning preservation (`strip-fidelity`).** Over a corpus of valid erasable-TS modules (hand-written fixtures + a generator of annotated programs): parse `source`, run `strip`, reparse the output as JS, and assert the reparsed AST equals the original AST with all type-only nodes pruned. Property holds for every input. (This is the gate's defining test.)
- **PROPERTY — position stability.** For each fixture, `stripped.len() == source.len()`, and for every surviving identifier/literal token its `(line, column)` in the stripped text equals its position in the source. Newline count is identical (no line drift).
- **PROPERTY — output is valid JS.** The stripped text contains no TS-only syntax and parses cleanly with the parser in JS mode (no TS grammar enabled).
- **UNIT — non-erasable catalog (one per construct).** Five fixtures (`enum`, `const enum`, non-ambient `namespace` with a body, `constructor(public x: number)`, `import x = require("y")`, `export = x`) each return `Err` with exactly the expected `code`, the exact `message` + `fix` text from §3, `severity == Error`, and a `span` covering the offending token. Assert on the **logical** code/fix presence, not incidental wording of unrelated fields.
- **UNIT — ambient is allowed.** `declare enum E {}` and `declare namespace N {}` strip successfully (erased, no diagnostic) — guards the ambient/non-ambient boundary.
- **UNIT — value imports retained.** `import { foo } from "x"; import type { T } from "y";` strips to keep the `foo` import and blank the `import type` line — verifies type-only removal is syntactic and never elides value imports.
- **UNIT — multi-error collection.** A module with two `enum`s and one parameter property returns three diagnostics in one call (no early return).

No `strip-fidelity` claim is made beyond the corpus actually run; the gate's reality-check (`reality-checks/strip-fidelity-<N>.md`) records the corpus (I-11, honest claims).

## Rollout

- **Sequencing.** Lands in **P0 Foundations** after GRAPH-001 provides stage-1 `Cst`, the shared `Diagnostic`, and the `lower_to_ir` seam (`depends_on: [GRAPH-001]`). It is the "a trivial TS file strips-and-runs" half of the P0 exit and the P1 MVP "type stripping (no emitted JS)" deliverable.
- **Flags.** None. Erasable-only is the only policy; there is no opt-in transpile mode to gate.
- **Reversibility.** Self-contained behind `// === RT-003 ===` fences plus the one new file `crates/graph/src/strip.rs`. Reverting = removing the fenced blocks and the file, and pointing `lower_to_ir` at a no-op/`unimplemented` policy; nothing else in the graph depends on the strip internals (only on the `StripPolicy` trait + `Stripped`). The shared `Diagnostic`/`Cst` types are GRAPH-001's and stay.
- **Forward compat.** Adding a future erasable construct = extend §2's collector; tightening a ban = add a catalog entry. Both are additive and covered by the property corpus.

## Operator notes

- **Decision on `const enum`:** banned alongside `enum` (it is not erasable — it still participates in emit/inlining). CANON §9 lists `enum` generically; this spec resolves the sub-case explicitly. Reasonable default, flagged here for Main to consolidate into `decisions.json` if a record is wanted (not baked silently).
- **Decision on `export =`:** CANON §9 / I-3 name `import =`; `export =` is its emit-bearing twin and is included in the ban for symmetry (same fix-pointing treatment). Flagged for the same reason.
- **Diagnostic ownership:** the `Diagnostic`/`Span`/`Severity` types are GRAPH-001's (confirmed live: `crates/graph/src/diagnostic.rs`, struct has `code/message/fix/span/severity`). RT-003 owns the `strip::*` code namespace and the message/fix strings only. If GRAPH-001's struct shifts before merge, RT-003 tracks it — coordinate at the fence, do not fork a parallel type (I-1, CRAFT "one graph").
- **Position fidelity is by blanking, not mapping:** stack traces and the delegated `tsc`/`tsgo` checker (which sees the *un*-stripped source) both rely on offsets being identical. Any future change that deletes rather than blanks bytes breaks this and the `strip-fidelity` gate — it is load-bearing, not cosmetic.
