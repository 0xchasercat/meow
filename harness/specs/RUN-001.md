## Motivation

Amendment 001 makes the five-minute test non-negotiable: `cd existing-project && meow install && meow run dev` must work on a stock `package.json` app with zero edits. CFG-003 already makes `package.json` the authority for scripts; RUN-001 is the execution half of that contract.

The runtime architecture stays opinionated: one resolver, one shared loader/runtime, no `node_modules`, no synthetic project-local `.bin` tree. The adoption path is not opinionated: when a user types `meow run dev`, meow must prefer the package script exactly the way npm users expect, preserve current direct-file behavior when no script exists, and fall back honestly when the authored script requires a real shell.

## Acceptance criteria

- `meow run <name-or-file> [-- args...]` resolves in this order:
  1. find the nearest ancestor `package.json` from the invocation cwd,
  2. if `scripts[<name-or-file>]` exists, execute that script,
  3. otherwise treat `<name-or-file>` as a file path exactly like the pre-RUN-001 `meow run` path.
- When a string is both a script key and a real file path, the script wins.
- `meow dev [-- args...]` is a first-class shorthand for `meow run dev [-- args...]`.
- Direct file execution keeps the existing guarantees:
  - same argv forwarding behavior,
  - same shared loader/runtime path,
  - same package.json dependency roots / lockfile cache resolution,
  - same Node built-ins default surface (RT-007),
  - same first-party + dependency CJS behavior (LOAD-004).
- Named script execution uses npm-style lifecycle ordering when hooks exist:
  - `pre<name>` → `<name>` → `post<name>`.
  - if `pre<name>` fails, stop immediately and return that exit code.
  - if `<name>` fails, stop and return that exit code.
  - if `post<name>` fails, return the post hook's exit code.
- Native execution path for a simple script (no shell operators/metacharacters requiring shell parsing):
  - local entry forms like `./scripts/dev.mjs` or `node ./scripts/dev.cjs` execute on meow itself,
  - a first token that names a package bin (for example `vite`) is resolved from the root direct-dependency set, then from the cached package manifest `bin` field,
  - cached bin execution feeds the resolved member URL/path into the shared `meow_loader::MeowModuleLoader` / `meow_runtime::Runtime`; it does not materialize `node_modules` and does not invent a project-local `.bin` shim.
- Package-bin resolution is by bin name, not only by package name. A package such as `typescript` exposing `tsc` is runnable from `scripts` without `node_modules`.
- If multiple direct dependencies expose the same bin name, RUN-001 fails honestly and names the conflicting packages instead of guessing.
- Shell fallback:
  - any script containing shell operators/metacharacters (`&&`, `||`, `|`, `>`, `<`, `;`, `$...`, backticks, parentheses, etc.),
  - or a simple bare command that is not a resolvable meow-native bin/local entry,
  - executes via the user's shell (`sh -c` on Unix; Windows shell edge compiled separately).
- Shell fallback preserves inherited stdio, exit status, cwd, and environment, plus the lifecycle env additions below.
- Script runs receive npm lifecycle basics without clobbering unrelated user env:
  - `npm_lifecycle_event`,
  - `npm_lifecycle_script`,
  - `npm_package_json`,
  - `INIT_CWD`.
- For named scripts, `process.cwd()` / shell cwd is the package root, while `INIT_CWD` remains the original invocation directory.

## Non-goals

- Arbitrary top-level `meow <script>` shorthand. `meow dev` lands now; broader external-subcommand parsing is a follow-up CLI slice if needed.
- Full npm shell emulation or every platform-specific quoting edge. RUN-001 only claims the documented shell fallback path and the tested operators.
- Reintroducing `node_modules` materialization, `.bin` shims, or a second JS runtime.
- npm's full lifecycle env surface beyond the four required variables above.

## Interface

CLI surface:

```text
meow run <name-or-file> [-- args...]
meow dev [-- args...]
```

Rust-side shape:

```rust
pub struct RunArgs {
    pub target: String,
    pub argv: Vec<String>,
    pub allow_clock: bool,
    pub allow_random: bool,
    pub allow_env: Option<String>,
}

pub struct RunScriptArgs {
    pub argv: Vec<String>,
    pub allow_clock: bool,
    pub allow_random: bool,
    pub allow_env: Option<String>,
}
```

Internal execution contract:

- a named script is planned into either:
  - a native local-file run,
  - a native cached-bin run,
  - or a shell fallback command.
- native cached-bin runs keep the module identity as a cached package URL so LOAD-004 resolves the package's own `require()` / bare deps correctly.
- `process.argv[1]`, `__filename`, and `__dirname` for cached bins point at the real unpacked-cache path, not a fabricated `node_modules/.bin/...` path.

## Implementation sketch

- `harness/specs/RUN-001.md` defines the cutover and the shell/native split.
- `crates/cli/src/cli.rs`
  - add `RunScriptArgs` plus the real `Command::Dev` dispatch,
  - factor the current runtime-building code out of `cmd_run` so direct-file entries and resolved package bins reuse one execution path,
  - add script planning helpers:
    - nearest-package-root discovery from cwd,
    - simple-script tokenizer / shell-detection,
    - package-bin scan over root direct dependencies,
    - lifecycle hook runner,
    - shell fallback launcher.
  - shared-file edits are fenced `// === RUN-001 ===` / `// === /RUN-001 ===`.
- `crates/loader/src/package.rs`
  - extend the cached package-manifest model with the `bin` field and helper accessors needed by RUN-001.
- `crates/runtime/src/node.rs` + `crates/runtime/src/js/node/{bootstrap.js,process.ts}`
  - allow the CLI edge to inject lifecycle env overrides into `process.env` for native runs without mutating the host process environment.
- Keep shell spawning at the CLI edge only (`std::process::Command`); libraries stay host-pure.
- Do not add `Resolver::resolve_bin` unless the manifest/bin scan proves impossible. Preferred path: CLI reads the manifest through existing package/cache surfaces, then hands the resolved entry URL/path to the shared loader/runtime.

## Tests required

- `crates/cli/tests/cli.rs`
  - `meow run dev` executes a stock `package.json` script.
  - `meow dev` executes the same script.
  - forwarded args after `--` reach the script process.
  - a script beats a same-named file.
  - `predev` / `dev` / `postdev` run in order with the documented failure behavior.
  - shell fallback executes a simple shell-authored script honestly.
  - missing script + missing file stays an honest non-zero diagnostic.
  - direct file run still works.
  - cached package-bin execution works without `node_modules`; at least one end-to-end case uses a CommonJS bin to exercise LOAD-004.
- Unit coverage for the script planner/bin resolver should prove:
  - shell metachar detection,
  - bin-name resolution across direct dependencies,
  - honest ambiguity on duplicate bin names.
- Full floor will be run separately; RUN-001 itself should at least pass targeted CLI tests locally.

Gates: `drop-in`, `resolver-parity`, `compat`, and `determinism` (direct file path stays deterministic under the existing RT-006 rules; named scripts deliberately inherit env in drop-in mode per RT-007).

## Rollout

No user migration. Once RUN-001 lands, existing stock projects can keep their `package.json` scripts unchanged and switch from `node`/`bun` invocation to `meow run` / `meow dev`.

Rollback is local to the CLI surface: remove the script planner and fall back to direct-file-only `cmd_run`; no persistent files or caches need migration.

## Operator notes

- Bin-name collisions across direct dependencies are surfaced as honest ambiguity instead of PATH-order guesswork.
- Windows shell fallback should compile behind an explicit branch even if the tested floor is Unix-first.
